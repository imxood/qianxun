## 0. 为什么用模拟器代替真机

真机 PKB110 是**指纹锁屏且未 root**，无法远程解锁：

```
locksettings set-disabled true  →  打印成功，但 get-disabled 仍返回 false
locksettings clear             →  User has a lock credential, but old credential was not provided
dumpsys window                  →  mDreamingLockscreen=true
```

更关键的是**锁屏时 Android 不给 WebView 布局**，实测：

```json
{"url":"http://192.168.20.2:23090/","vw":0,"vh":0,"qxMobile":false}
```

viewport 是 0×0，CSS 一条都算不出来 —— 也就是说真机上的**视觉验证在锁屏期间
根本不可能进行**，不是「不方便」，是做不到。

所以把模拟器调成与真机逐像素一致，作为等价替身：

| | 真机 PKB110 | 模拟器（已调） |
|---|---|---|
| 物理分辨率 | 1256×2760 | 1256×2760 |
| 密度 | 560 dpi | 560 dpi |
| **逻辑 dp** | **359×789** | **359×691**（扣系统栏） |
| dpr | 3.5 | 3.5 |

宽屏 359dp 是关键 —— 比原先模拟器的 412dp 更窄，布局结论差别很大。

⚠️ 这不等于「真机验证通过」。没验证的部分见 §5。

## 1. 白屏的真正原因（这一轮的起点）

你报的「页面已加载，但 custom.js 未生效」+ 整屏白，实测链条：

1. 主文档**能加载**（`readyState: complete`、`htmlLen: 37688`、`cookie` 在）
2. 但后续子资源**全部挂死** —— `/qx-mobile/version`、`/qx-mobile/bootstrap.js`、
   `/api/session/list` 三个 fetch 各自 6–8 秒无一返回
3. 排除网关：桌面侧复用同一条连接连发 6 次，**全部 0.00s**（网关健康）
4. 排除隧道：手机 shell 经 `nc` 直连，每请求 700–780ms 且正确回 `401`（路径通）
5. 排除定制层：CDP 强制重载后控制台打出
   `[qx-mobile] L3 第4版：395 条会话，待答 0 · 无法确认 102` —— **定制层是好的**

结论：**白屏是「首请求成功、后续请求挂死」**的连接复用型故障，
而它出现在锁屏期间（WebView 0×0）。锁定发生在冷启动首屏加载那一刻。

### 1.1 真机 release 的最终确认（CDP 抓到的控制台）

装上 release（versionCode 2005）后经 deep link 直达 DSH 页，CDP 抓到：

```
[qx-mobile] L3 第4版：395 条会话，待答 0 · 无法确认 102，错误=无
```

即 **定制层在真机上确实跑起来了**，395 条会话已拉到。
所以你看到的白屏 + 「custom.js 未生效」，不是定制层坏了，
是锁屏期间 WebView 被挂起（0×0）导致探测与子资源请求双双失败。

⚠️ 手机再次熄屏后，WebView 的调试 socket 会随 Activity 暂停一起消失
（实测：锁屏 → `/proc/net/unix` 里只剩 VPN 应用那一条）。
这也说明**锁屏期间无法持续观察**，是真机自动化最根本的一条限制。

### 1.2 仍然存在的 404

控制台有一条 `Failed to load resource: 404`。桌面侧用同一 URL 复现过：
`GET /assets/client.js?rev=… → 404`，属 DSH 自己的静态资源引用问题，
**不是本项目引入的**，也未影响页面（页面已渲染、控制台已打出会话数）。


顺带修掉一个真实缺陷：冷启动走 deep link 时连接还没从磁盘读完，
`_findConnection` 用 `container.read` 立刻返回 null，页面显示
「找不到这台电脑」—— 用户明明配对过。已改成 `Consumer` + `watch`。

## 2. 迭代记录

审查器一次跑出 18 个问题，逐轮降到 10 个（high 始终为 0）。

| 轮次 | 发现 | 处理 |
|---|---|---|
| 1 | 表格 TD/TH 全部报「超出视口 53px」 | **审查器误报** —— 那张表 288px 放在 x=32（右边缘 320 < 359），且 `overflow-x:auto` 自己能滚。改成跳过横向可滚祖先里的元素 |
| 1 | 状态条「11 轮 446 步·103 t…」少 63px、「89.2M tok·缓存命中 98%」少 57px | JS 按**行为**（`scrollWidth > clientWidth`）标记被砍的行，CSS 改成换行。「缓存命中 98%」被砍成「98」是信息丢失 |
| 1 | 代码 11px / 10.5px（109 处） | 先写 CSS 规则，发现**没用**：DSH 的 `._markdown_ :not(pre) > code` 特异性 (0,3,0) 且带 `!important`，压过 (0,1,0)。改用内联样式才稳赢 |
| 2 | 顶栏图标按钮 17–28px 宽、Chat tab 27px | `min-width: 44px`（**不用** `::after` 扩热区：相邻按钮热区会重叠，等于把「点不准」换成「点错地方」） |
| 3 | 审批/提问选项只有 23px 高 | 三条件筛选（块级 + 宽 > 45vw + 高 < 44）后补到 44dp。上限写成 32 时出现过自锁：补到 40 后元素不再满足筛选条件，永远补不到 44 |
| 3 | 正文里 15px 的行内链接 | 与块级**分开处理**：行内元素加纵向 padding 不改变行盒高度 |
| 3 | 行内链接仍被报 15px | **审查器测量盲区** —— `getBoundingClientRect` 对行内元素返回内容盒，看不见 padding。改成量「rect + padding」的真实热区 |

## 5. 没做到 / 未验证（必须说清）

1. **真机上的视觉验证没做成** —— 锁屏且未 root，见 §0。这一轮的结论都来自
   「与真机逐像素一致」的模拟器。
2. **白屏未在真机复现验证**。锁屏期间 WebView 是 0×0，无法判断解锁后是否仍白。
   需要你明天解锁手机后看一眼 DSH 页。
3. **顶栏 164px（24% 屏高）未优化**。已知 A10 的 `flex:1 1 100%` 与 A15 的
   `min-width:44px` 会互相加高，但两者各解决一个真问题，贸然合并会两头落空。
4. **剩余 71 个过小触控目标**多在转录深处的行内链接上，热区已用 padding 补到
   33px，达不到 44dp。
5. **远程桌面 Surface、扫码配对**没动。

## 6. 这一轮最该记住的三件事

1. **审查器自己也会有误报**，而且误报长得和真问题一模一样
   （表格「溢出」其实在滚、15px 链接其实有 33px 热区）。
   两轮都是先修审查器，再谈页面。
2. **`!important` 拼的是特异性**，不是顺序。同为 `!important`，
   (0,3,0) 压 (0,1,0)。压不过就上内联样式。
3. **自锁**：修复手段本身会改变元素的度量，导致它不再满足筛选条件
   （32px 上限 → 补到 40px → 永远补不到 44）。阈值要留出收敛空间。
