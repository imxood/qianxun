# 15 · 移动端产品与实施规格

> **面向对象**：任何要在千寻（qianxun）上实现 / 接手这套移动端的人或 agent。
> 本文只写**已实测的事实**与**由此产生的规格**，不写设想。
> 数字全部可在真机上复现，复现方式见 §7。

---

## 0. 需求原文与不可违反的原则

### 0.1 需求原文

> DSH 的所有内容一般情况下都**不要修改**，只处理对于 mobile 不友好的**布局**。
> 如左侧菜单需要优化、对话的顶部显示不全。
> **功能要保留**，仅仅是改变 UI 布局，相当于在移动端的 UI 表现。
> 你需要自己考虑如何才能显示得让人很舒服。

### 0.2 三条原则（违反其一即为做错）

| # | 原则 | 判据 |
|---|------|------|
| P1 | **不改 DSH 的内容与功能** | 不新增字段、不删除入口、不改文案含义、不改数据流 |
| P2 | **只重排布局** | 允许：换行 / 换列 / 改尺寸 / 改间距。禁止：隐藏功能、合并入口 |
| P3 | **UI 要专业、美观、精致** | 不是「没坏掉」就算好；外来的元素必须与宿主视觉语言一致 |

### 0.3 范围

- **做**：移动端（窄屏）下 DSH 的导航形态、顶栏、会话列表、composer、状态条、长内容排版
- **不做**：移动端设置页（用户明确不要）、远程桌面 Surface（未实现，见 §8）
- **交付形态**：`<dsh_home>/mobile-access/custom.{js,css}` + Flutter WebView 壳

## 1. 架构与分工

```
Flutter 壳（mobile-flutter/lib/）
  └─ 只做四件事，不重画任何 DSH 界面
     1. 加载前注入 qx_token cookie
     2. 处理返回键
     3. 外部链接交系统浏览器
     4. 顶栏：返回 + 机器名

千寻网关注入（src-tauri/src/remote/mobile_ui.rs）
  └─ /qx-mobile/{info,version,bootstrap.js,custom.css,custom.js}
     bootstrap.js 定义 window.qxMobile.register，轮询 hash，5 秒热替换

定制层（mobile-flutter/qx-mobile/custom.{js,css}）  ← 界面改造都在这里
```

**为什么定制层在 WebView 内而不是 Flutter 侧**：
把 DSH 的会话列表在 Flutter 里重画一遍就成了**两套 UI**，且与桌面不同步。
方案 B 的核心是「壳只负责能不能打开，页面负责打开后长什么样」。

## 3. 三个「模拟器正常、真机坏掉」的坑（**最该记住的一节**）

这三个在模拟器上**界面完全正常**，只有真机能暴露。
它们不是玄学，各自有明确的成因。

### 3.1 DSH 界面语言不同 → 按钮 aria-label 不同

| | 模拟器 | 真机 |
|---|---|---|
| 展开侧栏 | `Open sidebar` | `打开侧边栏` |
| 收起侧栏 | `Collapse sidebar` | `收起侧边栏` |

按英文匹配的结果：在真机上点菜单按钮**完全没反应**，
而界面上看不出任何异常 —— 最容易误判成「按钮没插进去」。

**规格**：`findSidebarToggle()` 同时认中英两种，
且都找不到时退回「侧栏里的第一个按钮」（折叠态第一个按设计就是切换键）。
**行为闸必须有中文 label 的断言**，否则这个 bug 会从闸门底下溜过去。

### 3.2 侧栏展开后顶栏被换成 blank header，菜单按钮被顶出屏幕

实测 x=381 而视口 359，**整整 66px 在屏幕外**，一次审查报出 5 个 high 溢出。
根因：侧栏展开后 DSH 把对话顶栏换成 `headerBlank`，
而菜单按钮挂在 `[data-slot="conversation.header.leading"]` 空槽里。

**规格**：侧栏展开时菜单按钮 `display:none`。
它那时本来就没用 —— 工作区页自带收起键。

### 3.3 `custom.js` 的 5 秒热替换不可靠

实测：CSS 的 hash 变了会热替换，**custom.js 的不会**。
按钮里仍是旧的文本内容，DOM 里连新元素都没有；`location.reload()` 之后才换。

**规格**：手机上改 `custom.js` **必须整页刷新**才生效。
不要相信「5 秒自动生效」那句提示。

## 4. 选择器纪律（违反其一就会埋雷）

### 4.1 绝不写 class 名选择器改 DSH 的东西

DSH 的 class 是**构建期哈希**，每次构建都变：
`hHd-Xa_root` / `bhn1Oq_list` / `pI_x6G_frame` / `qianxun-wSkVaW_header` …

**只能用 `data-slot`**（Base UI 的部件标记，语义化、带版本）。实测 42 种：

```
root  sidebar  main  rightbar  shell.overlay
conversation.composer / .input.dock / .header / .session …
sidebar.workspaces / .panellist / .footer.action …
```

以及状态属性：`data-sidebar-collapsed`
（**展开时该属性是「不存在」而不是 `"false"`**，所以展开态 = `:not([data-sidebar-collapsed)`）、
`data-row-key`（`workspace:<uuid>` / `session:session-<uuid>`）、
`data-disclosure-row`、`data-composer-input`。

### 4.2 哈希类名读得出来，但写不进 CSS

排查时用哈希类名快速定位（比如 `qianxun-bhn1Oq_searchButton`），
但**最终产物里不能出现** —— 下次 DSH 构建就全失效。

### 4.3 需要「按行为找元素」时，用 JS 打标记 + CSS 改样式

class 不可用但结构又不稳时（例如「找出被省略号砍掉的行」），
由 `custom.js` 按**行为**（`scrollWidth > clientWidth`）找元素、打
`data-qx-*` 属性，再由 CSS 据此改样式。标记与样式分离，
class 怎么变都不影响。

## 5. 布局改造规格（现有规则的由来）

### 5.1 A1 侧栏展开 → 全屏浮层

```css
@media (max-width: 760px) {
  [data-slot='root'] > :not([data-sidebar-collapsed]) {
    grid-template-columns: minmax(0, 1fr) 0px 0px !important;
  }
  [data-slot='root'] > :not([data-sidebar-collapsed]) [data-slot='sidebar'] > * {
    position: fixed !important; inset: 0 !important; width: 100% !important;
    z-index: 60;                      /* 低于 DSH 自己的弹窗层 */
    display: flex !important; flex-direction: column;
    overflow-y: auto; overscroll-behavior: contain;
  }
}
```

`grid-template-columns` 是内联样式，必须 `!important` 才压得住。

### 5.2 A11 折叠态 rail **不能 display:none**

⚠️ **栅格是按顺序自动放置的。** 删掉第 1 项后 main 滑到第 2 列，
而第 2 列是 0px —— 实测整个主区被推出屏幕（main 在 x=412、w=0）。

正确做法是**保持它在流里，只把那一列压成 0**：

```css
[data-slot='root'] > [data-sidebar-collapsed] {
  grid-template-columns: 0px minmax(0, 1fr) 0px !important;
}
[data-slot='root'] > [data-sidebar-collapsed] [data-slot='sidebar'] > * {
  width: 0 !important; min-width: 0 !important;
  overflow: hidden !important; visibility: hidden !important;
}
```

用 `visibility` 而非 `display` —— 前者彻底断掉交互，
但 JS 的 `.click()` 仍然派发（菜单按钮要靠它打开工作区页）。

### 5.3 A10 顶栏换行：标题块独占一行

```css
[data-slot='conversation.session.header'] > div:has(nav) {
  flex-wrap: wrap !important; align-items: center; row-gap: 0;
}
[data-slot='conversation.session.header'] > div:has(nav) > *:has(nav) {
  flex: 1 1 auto !important; min-width: 0;
}
```

⚠️ **不能写 `flex: 1 1 100%`** —— 菜单按钮也在这个 flex 容器里，
100% 会把它挤到第二排去（实测它掉到了 📁 那一行左边）。

⚠️ 曾试过把中间层改 `display:contents` 让 tablist 与按钮并到一行（省 50px 高度），
**已放弃**：顶栏 chip 随会话变（普通会话 vs 开了团队多出「Agent Team」「Standard mode」），
`order` 方案要写死「第几个子级是什么」，换个会话就散架。
`flex-wrap` 不依赖元素个数。

### 5.4 触控目标的三种改法（**不能混用**）

| 元素类型 | 改法 | 理由 |
|---|---|---|
| composer / 工作区页按钮 | `min-height:44 / min-width:40` | 块级，直接补 |
| 转录里审批、工具行 | `min-height:44`（带宽度筛选） | 块级 |
| 正文里的行内链接 | **纵向 padding** | 行内元素的纵向 padding **不改变行盒高度**，加了不撑开段落 |
| 消息下方图标按钮（间距仅 40px） | 只补到 `32×40` | 补到 44 会互相重叠 —— 把「点不准」换成「点错地方」 |

**块级 vs 行内必须分开**。给正文里的行内链接加 `min-height:44`
会把整段文字撑成一片，比原来更糟。

块级元素的筛选条件（缺一不可）：
1. `display` 是 block/flex（排除行内）
2. 宽度 ≥ 45vw **或** 父容器高度 ≈ 自身高度（说明「整行都是它」）
3. 高度 < 44px

### 5.5 字号下限 12px

代码是要**照着抄**的内容，比正文更不该小。
但注意：`!important` 拼的是**特异性**不是顺序 —— 同为 `!important`，
DSH 的 `._markdown_ :not(pre) > code`（0,3,0）会压过我们的 `[data-qx-tiny]`（0,1,0）。
**压不过就上内联样式**（`el.style.setProperty(..., 'important')`）。

## 6. 待做项（按性价比排序）

### P0 · 顶栏 164px，占屏高 24%

**现状**：`headerH=164`，视口 691dp。三行（标题行 / 按钮行 / tabs）。

**为什么该改**：手机上 24% 的高度花在导航上，正文只剩一半。
多数聊天 App 的标题栏在 110–130px。

**方向**：把 tablist 与按钮行并到同一行（省 48px）。
障碍已在 §5.3 说明 —— 需要用 JS 按行为搬运，而不是靠 `order` 写死位置。

**验收**：`audit_page.py` 报 `headerPct ≤ 18%`，且 tabs 与按钮仍都可点。

### P0 · 底部状态条两行内容重叠

**现状**：换行后第二行的「89.2M tok · 缓存命中 98%」与第一行的图标叠在一起。
换行本身是对的（不砍信息），但需要**重排**：图标独占一行，文字另起一行，
或者整体改成一行可横向滚动。

**验收**：截图上无重叠；全部字段可见。

### P1 · 巡检器提速

**现状**：真机走 VPN，每步 CDP 调用 ~10 秒，一轮「点→截图→审查」~30 秒。
9 个状态跑一轮要几分钟，且有 5 个截图因超时丢失、各状态报告相同（状态没真正切换）。

**方向**：批量迭代在**与真机 dp 完全一致的模拟器**上做（已调好：
1256×2760 @ 560dpi），真机只做抽样验证与最终确认。

**验收**：一轮 9 个状态 ≤ 90 秒，无状态失败。

### P1 · 亮色 / 暗色主题对比度统一

**现状**：定制层用 `currentColor` 跟随主题，但：
`.qx-hint-ctx` 的琥珀色在亮色下对比度不足；
`[data-qx-clipped]` 的换行只影响布局，颜色仍取 DSH 变量。

**方向**：两套主题各定义一组自有令牌，用 `prefers-color-scheme` 切换；
改完跑 `scripts/check_contrast.py` 闸门。

**验收**：两套主题下自有元素对比度 ≥ 4.5:1（正文）/ 3:1（图标）。

### P2 · 工作区页的信息密度

工作区页行高偏松，6 个工作区 + 会话列表要滚动才看完。
可考虑：折叠状态下工作区行降到 48dp（当前约 56dp）。

### P2 · 「未分组」会话的可达性（**待产品决策**）

实测 `session/list` 394 条里 **143 条**被 DSH 注册表认领，
其余 251 条里 **249 条是子 agent 会话**（`origin=subagent`，
id 是裸 uuid，标题就是系统提示词原文），
**只有 2 条**是真正的用户会话。

- DSH 侧栏**本来就没有**「未分组」组（全页叶子节点扫描 = 0）
- 所以这 251 条在**桌面端也只能靠搜索**到达
- 补一个「未分组」区等于把 249 行系统提示词端到手机列表上 —— 是噪声不是功能

**结论**：按 P1「不改 DSH 的内容」原则，不补。若将来要补，
那是一次明确的产品决策，需单独裁决。

### 7.4 ⚠️ 审查器自己也误报过三轮

**每一轮的误报都长得跟真问题一模一样。** 全部跳过：

| 误报 | 真相 |
|---|---|
| 表格 TD/TH「超出视口 53px」 | 那张表 288px 放在 x=32（右边缘 320 < 359），且 `overflow-x:auto` 自己能滚 —— 是**正确**的横向滚动 |
| 15px 行内链接「热区不足」 | 已用 padding 撑到 33px，但 `getBoundingClientRect` 对行内元素返回**内容盒**，看不见 padding。改为量「rect + padding」 |
| `headerBlank` 落在 x=379 报 3 个 high | 被祖先 `overflow` 裁掉，用户**根本看不见**，页面宽仍是 359、无横向滚动。逐条对过画面，无任何破损 |

**判定规则**：跳过「横向可滚祖先」与「裁剪祖先」里的元素；
触控目标量**含 padding 的热区**而不是 rect；
截断只在 `scrollWidth > clientWidth` 时才算。

> **律**：CSS 规则不查命中数，等于没写。审查器和页面一样会骗人。

## 10. 一句话总结给接手的人

> 界面改造全部在 `mobile-flutter/qx-mobile/custom.{js,css}`，**不要在 Flutter 侧重画 DSH**。
> 改 DSH 的东西只能用 `data-slot`，**绝不能写 class**（构建期哈希）。
> 真机与模拟器的差异会咬人三次（界面语言 / 顶栏 blank / 热替换失效），
> 所以**每一轮都要在真机上验一次**，不能只跑模拟器。
> 审查器会误报，**先确认「是不是真问题」再动手改**。
