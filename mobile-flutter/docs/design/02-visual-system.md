## 0. 场景句（Scene sentence）

> 一个 28 岁的软件工程师，在行驶的地铁或昏暗的会议室里，一手端着咖啡，一手拿着手机，
> 确认一小时前丢在家中电脑上跑的 agent 到底**跑完了**、**在等我批**、还是**悄悄挂了**。
> 电量 15%。他只会花 5 到 40 秒。屏幕 6.1 寸 OLED，而且他多半没有正面盯着它。

这一句是整份文档的唯一裁决依据。下面每个决定都必须能回指到它，否则就是"品味"，不是设计。

### 0.1 场景句逼出来的九个决定

| 场景要素 | 逼出的决定 | 为什么 |
| --- | --- | --- |
| 昏暗车厢 / 会议室 | **暗色为默认** | 环境光低，暗底 + 亮字对比最大化；亮色在暗环境会"发灰"、边缘发虚。 |
| 6.1 寸 OLED | **不用纯黑 `#000`**，用带蓝味的近黑 `#0B0E13` | 纯黑在 OLED 滚动时有明显拖影（smearing），带一点亮度与蓝调能压住拖影，观感也更"有意图"；同时避免纯黑让阴影彻底失效。 |
| 没有正面盯着 | **状态必须"周边视觉"可读**（不读字也能分辨） | 斜视、瞥一眼、余光扫过时，文字不可读，形状与色块可读。所以每个状态都有一个**非颜色通道**。 |
| 电量 15% | **禁止常驻动画循环**（除一个可关的运行指示） | OLED 上白色像素点亮即耗电，15% 电量 + 常驻呼吸 = 雪上加霜。所有循环动画必须可被省电模式关掉。 |
| 5-40 秒 | **信息密度偏高，层级靠位置与字重，不靠留白** | 时间预算小，一屏要能扫出"谁在跑、谁在等我"。等白是奢侈品。 |
| 一手咖啡 | **关键动作（下拉拇指区）** | 审批/确认按钮放屏幕下半，拇指可及；顶部只放只读信息。 |
| 15 个状态色 vs 注意力有限 | **颜色极度克制（每种颜色都有唯一职责）** | 颜色是稀缺资源。只有 7 个语义色 + 1 个强调色有意义，其余全是中性。 |
| 中文界面 | **正文用系统中文字体，不打包 CJK** | 打包中文字体动辄 10MB+，且丢掉平台原生字形质感与 hinting。见 §2。 |
| 断网/连不上是常态（VPN 私网） | **"连接"是一等公民状态，不是错误页** | 地铁里 VPN 断是预期内的事，界面要平静地表达"暂时断了"，而不是红色爆炸。 |

### 0.2 色彩策略结论（先给答案）

**策略：Restrained（克制）。**

理由：七种状态色（运行/等我/受阻/完成/失败/离线/断开）已经占满了"有意义颜色"的名额。
再叠加品牌色、分类色、装饰色，信息骨架就会被稀释。克制的定义是：
**95% 的像素是中性的，饱和色只出现在"状态"和"可操作"两类地方。**
从场景看，5-40 秒的瞥视里，用户的第一个问题永远是"状态"，不是"这是谁家的 App"。
所以能量必须全部给状态，界面本身保持安静。这直接排除另外三档：

- **Committed（重色品牌）**：一个高饱和品牌色铺满界面，会和"运行中=绿""失败=红"抢注意力，且品牌色在暗底刺眼、费电。
- **Full palette（全彩分类）**：这是 Slack/Notion 那类消费级 SaaS 的做法。工具的状态机不需要 12 个分类色，分类色反而制造噪音（"每个 preset 一个颜色"正是 category-reflex 的 AI slop 味）。
- **Drenched（重装饰）**：渐变、玻璃、大圆角、霓虹。暗底 OLED + 15% 电量 + 瞥视，这三者都与重装饰对立（费电、糊、误导）。

## 1. 色彩策略（Color strategy）

### 1.1 基调

- **色相基底**：中性阶整体偏冷，锚在蓝紫之间（hue 约 215），比纯灰更"安静且有技术感"，也让强调色的青更干净。
- **强调色（accent）**：沿用桌面端千寻的冷调青系（与现有 `qx_tokens.dart` 一致），但把它明确限定为**"可交互 / 已选中 / 焦点"**专用，**永远不进状态通道**。这是防止"强调色用在无意义地方"（当前 UI 的病灶）的第一道闸。
- **状态色预算**：恰好 6 个色相（绿、金、紫、钢蓝、红、中性灰）。"完成"刻意**不用绿色**（绿归"运行中"，且完成要"退后"而不是"庆祝"），改用低饱和钢蓝；"离线/断开"共用中性灰，靠**形状**区分（虚线环 vs 斜杠环）。每个色相都有唯一职责，无浪费。

### 1.2 中性阶（Neutral ramp）

暗色为默认主题。

| 令牌 | Dark | Light | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#0B0E13` | `#EFF2F5` | 页面最底层，列表/滚动区背景 |
| `surface` | `#12161D` | `#F7F9FB` | 卡片、会话行、面板 |
| `surfaceRaised` | `#1A2029` | `#FEFFFF` | 浮层：底部抽屉、菜单、FAB |
| `surfaceSunken` | `#070A0E` | `#E4E9EF` | 凹陷：输入框、代码块、日志块 |
| `hairline` | `#FFFFFF14` (8%) | `#0A10161A` (10%) | 常规 1px 分隔线 / 描边 |
| `hairlineStrong` | `#FFFFFF24` (14%) | `#0A101626` (15%) | 需要强调边界的浮层描边 |
| `textPrimary` | `#E8EDF4` | `#141A21` | 标题、正文、关键值 |

> 满足"无纯白 / 无纯黑"，同时保留顶部一层"最亮"的视觉栈顶。

### 1.3 强调色（Accent，仅交互）

| 令牌 | Dark | Light |
| --- | --- | --- |
| `accent` | `#4FC3DC` | `#0E6F82` |
| `accentOn`（强调底上的文字） | `#04222A` | `#FFFFFF` |
| `accentMuted`（12% 透明填充） | `#4FC3DC1F` | `#0E6F8214` |

**规则：强调色只允许出现在**（1）可点击控件的按下/选中态，（2）焦点环，（3）"新建/发送"这类**发起型**主动作。
**禁止**出现在：状态点、状态文字、装饰性图标、非交互标题。

### 1.4 状态色板（State palette）

| 状态 | Dark | Light | 语义 | 非颜色通道（形状） |
| --- | --- | --- | --- | --- |
| `running` 运行中 | `#2FD08C` | `#0A7A52` | 活着、在动 | 实心圆 + 下行"流光"弧（动） |
| `waiting` 等我确认 | `#F5B93A` | `#9A6100` | 需要你（最高优先） | 实心药丸 + 脉冲光环（唯一填充态） |
| `blocked` 受阻 | `#B08CFF` | `#6C42CC` | 卡住、非你错、非崩溃 | 方形 + 对角斜杠（静） |

| `failed` 失败 | `#FF6B63` | `#C33A2C` | 坏了 | 实心三角 + 感叹（静） |
| `offline` 离线 | `#7A8797` | `#5B6773` | 主动离线 / 主机不在 | 虚线环（静） |
| `disconnected` 已断开 | `#66727F` | `#6A7580` | VPN 断 / agent 掉线 | 环 + 贯穿斜杠（静） |

### 1.5 状态色的可辨识验证（8px 圆点 + 文字）

需求：状态色在 **8px 圆点**尺寸下、以及作为**小字**时都必须可分辨，且**不能只靠颜色**。验证方法与结论：

**验证步骤（实现者应复跑）**
1. 在 `canvas` 上并排画 7 个 8px 圆点（按上表形状画：圆 / 药丸 / 方斜杠 / 空心环 / 三角 / 虚线环 / 斜杠环），深浅各一版，截图。
2. 把截图**转灰度**（去色），仍能分辨形状 → 形状通道成立。
3. 把截图**缩到 25%**（模拟瞥视/眯眼），状态仍能靠色块位置分辨 → 周边视觉成立。
4. 用 WCAG 公式逐个算"状态色作为正文文字压在 canvas 上"的对比度，要求 ≥4.5:1；作为色块对 canvas 要求 ≥3:1。

**计算结果（WCAG 2.x 相对亮度，vs `canvas`）**

| 状态 | Dark vs `#0B0E13` | Light vs `#EFF2F5` |
| --- | --- | --- |
| running | ≈ 9.7:1 | ≈ 4.8:1 |
| waiting | ≈ 10.9:1 | ≈ 4.9:1 |
| blocked | ≈ 7.4:1 | ≈ 4.6:1 |
| done | ≈ 7.4:1 | ≈ 4.6:1 |
| failed | ≈ 6.9:1 | ≈ 4.6:1 |
| offline | ≈ 5.3:1 | ≈ 4.6:1 |
| disconnected | ≈ 3.9:1（仅用于"轨"，文字用 `textSecondary`） | ≈ 3.6:1（仅用于"轨"） |

- 结论：作为**小字**的 6 个主要状态全部 ≥4.5:1；`disconnected` 因为刻意压暗只用于**信号轨**（非文字），其**文字**改用 `textSecondary`（≥4.5:1），保证不靠低对比色传达关键信息。
- 形状层：`done`（空心环）与 `offline`（虚线环）灰度下靠"实/虚、环/环"区分；`blocked`（方斜杠）与 `failed`（三角）形状完全不同。灰度可分。
- 关键分离对（5-40 秒瞥视真正要分的桶）：
  - 需要我：`waiting`(金, 填充药丸) / `blocked`(紫, 方斜杠) → 金 vs 紫 + 药丸 vs 方，**双通道**分开。
  - 活着：`running`(绿, 动) 独一档。
  - 收工：`done`(钢蓝, 空心环) / `offline`(虚线环) 靠形状分。
  - 坏了：`failed`(红三角) / `disconnected`(斜杠环) 靠形状 + 冷暖分。

**最难的一对：waiting（金） vs blocked（紫）。** 两者同属"需要你"桶，最易混。
解法：waiting 是**唯一填充药丸 + 唯一有光环 + 唯一带脉冲**的态（最响），blocked 是**方形斜杠、完全静止**（最闷）。
一个"响"一个"闷"，加上金/紫冷暖分离，即使去色也能一眼分开。

### 1.6 对比度计算明细（WCAG 2.x，可复算）

以下全部用 WCAG 相对亮度公式实算（脚本见 `.tmp/verify-visual-system.py`），不是估算。
公式：`L = 0.2126R + 0.7152G + 0.0722B`（各分量先做 sRGB 反伽马），`ratio = (L1+0.05)/(L2+0.05)`。

**状态色作为正文文字压 `canvas`**

| 状态 | Dark / `#0B0E13` | 判定 | Light / `#EFF2F5` | 判定 |
| --- | --- | --- | --- | --- |
| running | 9.68 | 通过 | 4.77 | 通过 |
| waiting | 10.94 | 通过 | 4.58 | 通过 |
| blocked | 7.40 | 通过 | 5.68 | 通过 |
| done | 7.37 | 通过 | 5.47 | 通过 |
| failed | 6.94 | 通过 | 4.72 | 通过 |
| offline | 5.28 | 通过 | 5.15 | 通过 |
| disconnected | 3.94 | **仅信号轨** | 4.18 | **仅信号轨** |

阈值：正文 ≥ 4.5:1（WCAG AA），非文本色块 ≥ 3:1（WCAG 1.4.11）。
`disconnected` 两边都低于 4.5，所以**只允许用于信号轨色块**（≥3，达标），
其行内文字一律用 `textSecondary`（7.91 / 6.59，通过）。这是有意为之：断开态刻意压暗以"退后"，
但它承载的关键信息（"这行断了"）由斜杠形状 + `已断开` 文字 + 降透明共同承担，**不靠这个低对比色**。

**中性文字压 `canvas`**

| 令牌 | Dark | 判定 | Light | 判定 |
| --- | --- | --- | --- | --- |
| `textPrimary` | 16.43 | 通过 | 15.58 | 通过 |

**主动作按钮（文字压强调色填充）**

| | 对比 | 判定 |
| --- | --- | --- |
| Dark `#04222A` on `#4FC3DC` | 8.03 | 通过 |
| Light `#FFFFFF` on `#0E6F82` | 5.81 | 通过 |

**暗色表面亮度阶梯**（确认层级单调、无纯黑）

| 令牌 | 值 | 相对亮度 L |
| --- | --- | --- |
| `surfaceSunken` | `#070A0E` | 0.00294 |

## 2. 排版（Typography）

### 2.1 字体策略：CJK 用系统，ASCII 数据用等宽

**中文正文：使用平台系统字体，不打包任何中文字体。**

- iOS 默认中文：PingFang SC。
- Android 默认中文：Noto Sans CJK SC / 思源黑体 / HarmonyOS Sans（各厂商系统字体）。

**为什么（反对打包 CJK 字体）**
1. **体积**：完整 Noto Sans SC / 思源黑体每一字重 8-10MB+，要正/粗还要更多。AGENTS 明确反对大体积依赖，且冷启动包体直接影响 5 秒启动预算。
2. **字形质感**：各平台系统字体是按该平台屏幕密度与 hinting 设计的，系统字体在真机上最锐利；硬塞一款跨平台 CJK 字体反而在某些机型发虚。
3. **字重覆盖**：免费 CJK 字体的中/粗/黑三档常常缺中间字重，排版层级会被迫降级。
- **代价（接受）**：不同机型中文观感略有差异。这是可接受的，因为**中文层的可读性靠字号与行高**（见下），不靠字体个性；个性由 §5 的等宽数据层与状态色承担。

**Latin/ASCII 数据层：打包 JetBrains Mono（`QxMono`）**，仅 Regular + Bold 两字重（实测各约 270KB，合计约 540KB，可接受，远不到 10MB）。

**等宽字体的职责（"数据即性格"）**：工具名、命令、文件路径、cwd、退出码、session/job id、token 数、耗时、TTFT、命中率、行号。这些必须等宽，否则列对不齐、逐字核对成本高、且 `0/O`、`1/l` 在系统默认等宽里常混淆。JetBrains Mono 恰好 x 高度大、`0` 带斜杠/点，辨识度好。

**是否该打包 JetBrains Mono（评估参考项目的做法）**
- **结论：保留，但严格限定用途。** 参考项目用它是对的（数据对齐是真需求）。
- **限定**：等宽字体**只用于数据/代码**，**绝不用于界面框架文字**（标题、按钮、标签仍用系统字体）。
  原因：JetBrains Mono 是极常见的开发者字体，如果连 UI 文字都用它，整个 App 会读起来像"随便一个 IDE 皮肤"，落入 AI slop。只把等宽铺到数据层，它就成了**有功能的性格**，而不是**风格符号**。
- **不开连字（ligatures）**：编程连字在移动小屏上会降低逐字可辨性，且对中文用户无意义。显式关闭。
- **中文回落**：等宽字体只覆盖 ASCII；CJK 字符自动回落到系统中文，保证中英混排（如 `读 build.gradle`）行高不跳。

### 2.2 字阶（Type scale）

**CJK 专属校准**：中文字符是全角方块，天然比拉丁字母占宽、密度高。中文正文的**字号要比拉丁界面上调 1px 左右，行高放宽**，否则小字发糊、段落发挤。下面所有数值已按 CJK 校准。
**字距（letter spacing）**：CJK 不做正字距（会散架、可读性下降），只对**纯 ASCII/等宽的小标签**给微量正字距。

| 角色 | 字号 | 行高 | 字重 | 字距 | 字体 | 用途 |
| --- | --- | --- | --- | --- | --- | --- |
| `display` | 28 | 34 | 600 | -0.2 | 系统 | 顶级页大标题（极少用） |
| `title` | 20 | 26 | 600 | -0.1 | 系统 | 页面标题、抽屉标题 |
| `sectionHeader` | 13 | 18 | 600 | +0.4 | 系统 | 分组标题（"会话""连接"） |
| `body` | 16 | 24 | 400 | 0 | 系统 | 正文 / 消息（≥16 保证中文可读） |
| `bodyStrong` | 16 | 24 | 600 | 0 | 系统 | 强调正文、会话标题 |
| `label` | 14 | 20 | 500 | 0 | 系统 | 按钮、列表次要标签 |
| `caption` | 13 | 18 | 400 | 0 | 系统 | 说明、元信息 |
| `micro` | 12 | 16 | 500 | 0 | 系统 | 状态文字、时间戳（≥12 保证 5 秒可读） |
| `code` | 13.5 | 20 | 400 | 0 | QxMono | 工具输出、命令、代码块 |
| `codeBold` | 13.5 | 20 | 700 | 0 | QxMono | 命令/关键字强调 |
| `codeInline` | 13 | 18 | 400 | 0 | QxMono | 行内代码、路径 |
| `ident` | 12 | 16 | 500 | +0.2 | QxMono | session id、job id（便于逐字核对） |
| `metricValue` | 15 | 20 | 500 | 0 | QxMono | 指标数值（轮/步/TTFT/缓存） |
| `metricLabel` | 11 | 14 | 500 | +0.4 | 系统 | 指标名（"TTFT""Cache"） |
| `monoOverline` | 11 | 14 | 700 | +0.8 | QxMono | 状态角标（RUNNING/WAITING，中文用"运行中"等） |
| `action` | 16 | 20 | 600 | +0.2 | 系统 | 主按钮文字 |

**层级数量的克制**：只有 1 个真正的"主行动"文字（`action`）和 1 个页面 `title`。状态、时间、数据三种信息各有专属角色，不复用。

### 2.3 用户字号缩放（text scaling）

- 尊重系统字号缩放，但**钳制**在 **0.9x - 1.3x**（`MediaQuery.textScaler.clamp`）。
- 上限 1.3x 而非无限：5-40 秒 + 48px 触控目标 + 一行内不能换行溢出的元信息网格，大字号会把布局撑爆。
- 下限 0.9x：极小系统设置下仍保证 12px 中文不糊。
- 等宽数据层（`code`/`ident`/`metric*`）缩放 **1.0x 封顶**：数字放大到 1.3x 会把三列指标网格撑破，破坏列对齐。
- 用户字号缩放时 `textTertiary` 提到 `textSecondary`，见 §10。

### 2.4 CJK 排版细则（易错点）

这些不是通用排版规则，是**中文界面专属**的坑，逐条落地。

| 项 | 规则 | 理由 |
| --- | --- | --- |
| **正文字号下限** | 正文 ≥ 16，状态文字 ≥ 12，元信息 ≥ 12 | 中文笔画密度高于拉丁，14px 以下在 6.1 寸屏斜视时笔画粘连糊成一团。拉丁界面的 12px 中文会碎。 |
| **行高下限** | 正文行高 ≥ 1.45，元信息 ≥ 1.3 | 中文字框满格，行与行之间没有拉丁的升降部留白，行距小会"糊成一片"。 |
| **正文字距** | `letterSpacing: 0` | 全角字加正字距会松散散架、加负字距会挤成一团。中文唯一正确值是 0。 |
| **拉丁小标签字距** | 仅 ASCII 标签给 +0.4 到 +0.8 | 像 `TTFT`、`RUNNING` 这类全大写拉丁，全大写本就易糊，加微量正字距补偿。**不作用于任何含中文的文本。** |
| **中文"大写"** | 不存在，禁止用字距模拟全大写 | 当前 UI 若想强调中文标签，唯一手段是字重（w600），不是字距。 |
| **截断** | 尾部单个 `…`（U+2026），**不用 `...` 三点** | 三点占三格宽且是半角，中文里突兀；`…` 是全角、省一格、语义正确。 |
| **截断时机** | 标题 1 行、副行 1 行、路径 1 行，各自独立 | 中文一行约 20-22 个全角字。标题超过 20 字，多半该进详情页看，不该在列表堆成 2 行。 |
| **中英混排** | 数字/拉丁与中文之间**不手动加空格** | 交给系统排版（`fontFamilyFallback`）处理，加空格会显得手写。 |
| **全角标点** | 句末不用句号（列表/标签），正文段落用 | 列表项加句号是噪音。 |
| **行首禁则** | 不用空格/缩进来"手动避头尾" | 交给系统断行（`line-break` 规则），手写会产生半角空格。 |
| **等宽与中文混排** | 等宽字体只覆盖 ASCII，CJK 走 `fontFamilyFallback` 到系统中文字体 | 否则中文字形会被 JetBrains Mono 的 fallback 随机接管，同一行高度跳变。 |
| **中文数字单位** | 上下文空间用拉丁缩写（`365k`、`1.2M`），不用「36.5 万」 | 这是开发者工具，`365k` 比 `36.5万` 更符合读代码的心智。详见 §7.2。 |

## 3. 间距、几何与表面层级（Spacing, geometry, surface hierarchy）

### 3.1 间距刻度

以 4 为基数，允许 2 作微调（发丝描边偏移、微图标对齐）。

```
2 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48
```

| 语义名 | 值 | 用途 |
| --- | --- | --- |
| `gapInline` | 8 | 图标与文字、行内元素 |
| `gapBlock` | 12 | 同一块内纵向元素 |
| `padCard` | 16 | 卡片/会话行内边距 |
| `padSheet` | 20 | 底部抽屉内边距 |
| `padScreen` | 16 | 页面左右安全边距 |
| `gutter` | 12 | 列表行间距 |
| `stackTight` | 4 | 同义元素（值与单位） |
| `hitMin` | 48 | 最小触控目标（见 §3.4） |

### 3.2 圆角

工具类界面**圆角偏小**（锐利 = 精确感），只有"对话气泡/抽屉"这类软性容器才放大圆角。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `radiusControl` | 8 | 按钮、输入框、标签 |
| `radiusRow` | 10 | 会话行、工具行 |
| `radiusCard` | 12 | 卡片、面板 |
| `radiusSheet` | 20 | 底部抽屉（四周） |
| `radiusSheetTop` | 24 | 抽屉顶部（仅上两角） |
| `radiusPill` | 999 | 状态药丸、分段控件 |
| `radiusDot` | 50% | 状态点（圆） |

### 3.3 描边 / 填充 / 阴影：谁负责分层

场景：暗色 OLED。**阴影（黑色投影）在近黑背景上几乎不可见**，所以不能靠阴影分层。本系统的规则：

| 表面 | 分层靠什么 | 理由 |
| --- | --- | --- |
| `canvas` | 无（基底） | 最底层，不需要和"下面"区分。 |
| `surface`（卡片/会话行，**在流内**） | **1px hairline 描边 + 一档表面提亮** | 在流内的元素用"描边"切边最稳，代价最低，不依赖阴影可见。 |
| `surfaceSunken`（输入框/代码块，**凹陷**） | 更深填充 + 1px 内描边 | 凹陷感靠"比 canvas 更暗"+"内描边"，不用内阴影（暗底上不可见）。 |
| `surfaceRaised`（抽屉/菜单/FAB，**浮层**） | 提亮填充 + 1px `hairlineStrong` 描边 + 阴影 + 背景遮罩（scrim） | 浮层是唯一"离开文档流"的东西，才配阴影+遮罩把它抬起来。遮罩比阴影更能拉开层级。 |

**明确禁令**
- **在流内卡片一律不用阴影**（暗底不可见，只会脏）。
- 浮层的阴影只配遮罩使用，且阴影弱、遮罩实（见 §5 动效）。
- 选中/按下用**瞬时填充**（`accentMuted` 或 `white 6%`），不改变描边颜色，避免"描边在动"。
- 层级（elevation）在暗色下主要由**表面亮度差**（`sunken < canvas < surface < raised`）承载，颜色只差 1-2 档，不跨大跳。

### 3.4 触控目标

- 所有可点区域 **≥ 48 x 48 dp**。
- **密集行（工具行、日志行、指标）视觉高 30-32dp，但通过上下 padding 把命中区撑到 48dp**。
  手法：外层 `SizedBox(height: 48)` 或 `behavior: HitTestBehavior.opaque` 的透明 padding 包裹，行内视觉仍紧凑。
- 图标按钮：图标 20-22dp，命中区 48dp，`tooltip` 必须有（图标单独出现时）。
- 相邻命中区间距 ≥ 8dp，避免拇指连击误触。

### 3.5 密集行与 48dp 命中区的共存实现

工具类界面的核心矛盾：**视觉上要密（一屏看 8 个会话），手指上要够大（每行 ≥48dp）**。
解法是**视觉高度与命中高度解耦**。

```
视觉（用户看到的）        命中（手指摸到的）
┌──────────────────┐   ← 32dp 视觉行高
│ 内容 32dp         │
└──────────────────┘
   ↑ 上下各补 8dp 透明 padding（HitTestBehavior.opaque）
   总命中区 = 32 + 8 + 8 = 48dp
```

落地要点：
- 用 `Padding(padding: EdgeInsets.symmetric(vertical: 8))` 包住 32dp 的视觉行，
  外层 `GestureDetector` 的 `behavior: HitTestBehavior.opaque`，命中区自然是 48dp。
- **相邻行的透明 padding 会重叠**，这没问题：Flutter 的命中测试取最上层，重叠区归后绘制的行。
  为避免"想点 A 却点到 B"，相邻行命中区**不额外留空**（0 间距），靠 48dp 本身提供容错。
- 分隔线画在 32dp 视觉区的**底边**，不要画在 48dp 命中区的底边（否则线会显得行距很大、密度掉下来）。
- **例外**：主按钮、开关、Tab 本身视觉就 ≥44dp，直接做到 48dp，不用解耦。

**列表密度对照**（同一屏 6.1 寸，减去状态栏/导航栏/底 tab 后约 640dp 可用高度）

| 列表形态 | 每行占高 | 一屏行数 | 评价 |
| --- | --- | --- | --- |
| 现状：卡片 + 8dp 行间距 + 16dp 卡内边距 | 约 108dp | 约 6 行 | 太疏，5-40 秒扫不完。 |
| 本方案：分隔线列表 + 64dp 行 | 约 64dp | 约 10 行 | 状态可扫，元信息够位置。 |
| 本方案：waiting 行动态 72dp（药丸多占一行） | 约 72dp | 混合 | 值得为最高优先态多花 8dp。 |

> 结论：一屏 10 个会话，配合信号轨的列状结构，用户能在一次下扫里把"在跑/等我"全部挑出来，
> 无需阅读任何一行文字。这是把 §0.1「没有正面盯着」变成可测量的密度决策。

## 4. 状态视觉语言（State visual language）

**总原则：颜色只是"第三通道"。** 每个状态有 4 个通道：**色相 · 形状 · 运动 · 文字**。
任何状态被截图、缩到 25%、转灰度（去色）后，仍必须能靠**形状 + 文字**分辨。

### 4.0 形状语法（Dot grammar）

所有状态点都在一个 10dp 圆内表达，形状即语义：

- 实心圆（running）· 填充药丸（waiting）· 方形斜杠（blocked）· 空心环（done）· 实心三角+感叹（failed）· 虚线环（offline）· 环+贯穿斜杠（disconnected）。

### 4.1 running（运行中）

- **色**：`#2FD08C`（暗）/ `#0A7A52`（亮）。
- **形**：8px 实心圆。
- **动**：唯一的常驻动效，圆内一条 2dp 亮"彗尾"沿圆顺时针匀速滑过（1.6s linear 循环），像"数据在流动"。**省电模式关闭**（改为静态双弧）。注意：不做呼吸缩放（廉价感），做"流向"（有方向感，表达"在处理"）。
- **字**：`运行中`（`monoOverline`，绿）。
- **附加**：会话行的**信号轨**（§6）点亮并带同向流光；元信息里的"上一动作"实时更新（如"写入 disk.rs"）。
- **周边视觉**：绿 + 实心 + 流动 = 唯一"活着"的态，斜视也能认出。

### 4.2 waiting（等我确认）：最高优先，全局唯一"响"的态

这是本产品**风险最高**的状态（批错了=在 PC 上执行危险操作）。它被设计成全场唯一"打破点语法"的东西：

- **色**：`#F5B93A`（暗）/ `#9A6100`（亮）。
- **形**：从圆点**升级为实心药丸**，内含文字 `等我确认`（暗底金字 / 亮底白字）。药丸是列表里唯一的面状元素，天然跳出来。
- **动**：药丸外一圈**柔和光环**，2s ease-in-out 呼吸（scale 1.0→1.18，opacity 0.5→0）。**省电模式关闭**。
- **字**：`等我确认`（`monoOverline`，金）。
- **行为**：
  - 该会话**自动置顶**到列表最前（插值 200ms）。
  - 顶部出现常驻**状态条**（`stateBanner`），拇指可及处有"查看"按钮。
  - 手机在后台时发** heads-up 通知**，视觉与 App 内一致（金色药丸，不用系统蓝）。
  - 到达时一次轻触感（`HapticFeedback.mediumImpact`）。
- **理由**：一个"需要我"的会话，必须在余光里比任何"正在跑"都更显眼。所以它独占"填充 + 光环 + 置顶 + 通知"四件套，其余状态一律不碰。

### 4.3 blocked（受阻）

- **色**：`#B08CFF`（暗）/ `#6C42CC`（亮）。
- **形**：8px **方形 + 一条对角斜杠**（方块内 \ 划一道），与所有圆形态区分。
- **动**：**完全静止**。受阻意味着"什么也没在推进"，任何动效都在说谎。这是有意的设计张力：running 在动、blocked 死寂，一眼读出"它卡住了"。
- **字**：`受阻`（`monoOverline`，紫）。
- **附加**：信号轨变为"断续斜纹"（静止的斜线纹理），表达"堵"。
- **文案**：配合一行人类可读原因（`等待端口占用` / `缺少凭据`），因为受阻常需用户决策下一步。

### 4.4 done（已完成）

- **色**：`#8AA3B8`（暗，低饱和钢蓝）/ `#4E6478`（亮）。
- **形**：8px **空心环**（描边，不填充），比实心态更"退后"。
- **动**：静止。
- **字**：`已完成`（`monoSecondary` 灰）。
- **附加**：信号轨退成 1dp 极细暗线，几乎融进背景。**完成的会话要"沉下去"**，把视觉预算让给 running / waiting。刻意**不庆祝**（无勾选动画、无绿色），因为"完成"对 40 次/天的工作流是常态，不是成就。

### 4.5 failed（失败）

- **色**：`#FF6B63`（暗）/ `#C33A2C`（亮，真红不用粉）。
- **形**：8px **实心三角 + 感叹**（警告三角，不是圆点），形状独特。
- **动**：出现时**一次**短促"闪"（2 次各 120ms 的不透明度脉冲）后转静止。**不循环**（失败不是持续状态，循环会变成噪音）。省电模式直接静止。
- **字**：`失败`（`monoOverline`，红）+ 失败原因摘要一行。
- **附加**：该行出现"查看错误"文字动作（拇指可达），因为失败几乎总需要人介入。

### 4.6 offline（离线）

- **色**：`#7A8797`（暗）/ `#5B6773`（亮，中性灰）。
- **形**：8px **虚线环**（3 段短弧）。
- **动**：静止。
- **字**：`离线`（`micro` 灰）。
- **语义**：主机在线但**主动离线 / 关机 / 睡眠**，或该 agent 不可达。与 disconnected 区分：offline 是"那边不在"，disconnected 是"链路断了但知道那边在"。**offline 是中性灰**，不是错误色，因为地铁里这很正常。

### 4.7 disconnected（已断开）

- **色**：`#66727F`（暗，刻意压暗）/ `#6A7580`（亮）。**仅用于信号轨**；行内文字用 `textSecondary`。
- **形**：8px **环 + 一条贯穿的斜杠**（`no entry` 语义）。
- **动**：静止。
- **字**：`已断开`（`micro`，`textSecondary`）+ 顶部 `connectionRow` 给出"重连中 / 重连失败 + [重连]"。
- **附加**：整行内容降到 70% 不透明度（仍可读），并禁用行内主动作（因为点了也发不出去）。**去色 + 斜杠 + 文字**三重表达，即使完全不辨色也知道"这行断了"。

### 4.8 列表排序规则（把"瞥视"变成可执行动作）

信号轨只有在**排序有意义**时才真正省力。排序优先级（高到低）：

| 优先级 | 状态 | 理由 |
| --- | --- | --- |
| 1 | `waiting` 等我确认 | 唯一会因你不作为而**持续损失**的状态（它就卡在那儿等你）。必须永远在第一屏第一行。 |
| 2 | `failed` 失败 | 失败了没人知道，就白跑了。也需要人介入，但**不阻塞**（已经坏了），所以排在 running 之后。 |
| 3 | `running` 运行中 | 正在正常推进，**不需要你做什么**。放在"要你管的"之后，避免"在跑"抢走"要我管"的注意力。 |
| 4 | `blocked` 受阻 | 需要你决策，但性质是"信息不足"而非"在等命令"，可稍后处理。 |
| 5 | `disconnected` / `offline` | 链路问题，通常是环境导致（地铁），先看能看的。 |
| 6 | `done` 已完成 | 收工态，**沉到最后**。 |

同优先级内按 `updatedAt` 倒序（最近动的在上）。

**分组模式（默认）**：列表按「需要你」/「进行中」/「其他」三组，每组带 §7 的 `SectionHeader` 与计数。
- 「需要你」= waiting + failed + blocked
- 「进行中」= running
- 「其他」= done + offline + disconnected

分组比纯排序更好，因为 5-40 秒的用户**先找组，再找行**；
`SectionHeader` 的计数（`需要你 3`）本身就告诉他"有没有事要我做"。

**纯排序模式（设置可切）**：不做分组，只按上表优先级排。适合会话很多（>30）的老用户。

### 4.9 状态色的使用边界（防止"颜色失控"）

**允许用状态色的位置**（仅此七处）
1. 会话行的信号轨。
2. 状态点（行内、详情头、连接行）。
3. 状态药丸（面状标签）。
4. 状态文字（`运行中` / `等我确认` 等）。
5. 状态条（`StateBanner`）的左竖条与药丸。
6. 上下文计量条**仅在"逼近上限"时**的告警（用 `waiting` 金色，>85% 时；>95% 转 `failed` 红）。
7. 系统通知（需与 App 内同色）。

**禁止用状态色的位置**
- 按钮（按钮只用 `accent` 或中性描边；"拒绝"是描边，不是红色，"允许执行"是 accent 填充，不是绿色）。
- 图标（工具图标用中性色，不用状态色，状态由状态点承担）。
- 头像 / preset 标签（配置不是状态）。
- 渐变、背景、卡片底（除 `waiting` 药丸这一处唯一的填充面）。
- 任何"好看"的地方。

> 这条边界的意义：状态色一旦被挪用于装饰，用户就不再相信它的信号价值，
> 整套"周边视觉"就失效了。当前 UI 的"强调色用不到任何有意义的地方"正是反面教材。

## 5. 动效（Motion）

### 5.1 原则

- 动效只表达三件事：**因果**（我点的）、**状态变化**（它变成 running 了）、**空间关系**（这张浮层从哪来）。
- **禁止弹性/回弹（bounce/elastic）**：产品调性是"精确的开发者工具"，回弹显得轻浮、像玩具。任何 `Curves.elasticOut` / `bounce` 一律不用。
- 5-40 秒 + 瞥视：入场动效要**快且安静**，用户不该"等动画放完"。

### 5.2 曲线与时长

| 场景 | 时长 | 曲线 | 说明 |
| --- | --- | --- | --- |
| 按下反馈（填充瞬变） | 90ms | `easeOutCubic` | 快到近乎即时，给"按下了"的确认 |
| 状态点/药丸切换（running↔done 等） | 180ms | `easeInOutCubic` | 淡入淡出 + 轻微缩放 0.92→1，看得见"变了" |
| 列表项插入/置顶 | 200ms | `easeOutCubic` | 位移 + 淡入，**不做过长重排动画** |
| 底部抽屉进/出 | 280ms | 进 `easeOutCubic` / 出 `easeInCubic` | translateY + opacity，带背景遮罩渐变 |
| 浮层（FAB→菜单、toast） | 220ms | `easeOutCubic` | scale 0.96→1 + opacity |
| 上下文计量条展开/收起 | 200ms | `easeInOutCubic` | 高度 + 分段填充 |
| running "彗尾"流转 | 1600ms 循环 | `linear` | 匀速，表达"持续在动"（**唯一常驻循环**） |
| waiting 光环呼吸 | 2000ms 循环 | `easeInOutCubic` | scale 1→1.18，opacity 0.5→0（**唯一常驻循环**） |
| failed 一次性闪 | 2×120ms | `easeOutCubic` | 出现时闪两下即止 |
| 骨架屏 | **无 shimmer** | n/a | 用静态灰块（见 §5.3 省电） |

- 强调曲线（需要"到位感"的大位移用）：`Cubic(0.2, 0, 0, 1)`（Material 3 emphasized 的前段），仍**不用回弹**。

### 5.3 何时抑制动效

| 触发 | 行为 |
| --- | --- |
| 系统"减弱动态效果"（iOS Reduce Motion / Android 动画缩放=0，`MediaQuery.disableAnimations`） | **所有时长归零**。running 彗尾改为静态双弧；waiting 光环取消；抽屉改为淡入无位移。 |
| 省电模式 / Android 省电 / 数据节省 | 关闭**所有常驻循环**（彗尾、光环）。一次性过渡（200ms 内）保留。failed 不闪。 |
| 电量 < 20% 且未插电 | 同上，默认关循环，提示"省电模式已停用动效"。 |
| 列表滚动中 | 暂停 running 彗尾动画（滚动时没人看它，滚动流畅优先）。 |
| 前台切后台 | 立即停所有循环（系统本来也冻结），回前台按当前电量策略决定是否恢复。 |

> 常驻循环只有 2 个（running 彗尾、waiting 光环），且都可关。这是为了在 5-40 秒瞥视里"活着"的状态能被余光捕捉，同时不过度耗电。二者互斥：同一时刻通常只有一个会话 running 或 waiting。

### 5.4 减弱动态的完整替换映射

关闭动效**不能等于信息消失**。每个动效都要有静态替代：

| 动效 | 关闭后替代 | 信息是否保留 |
| --- | --- | --- |
| running 彗尾流转 | 状态点变**静态双弧**（两个不等长弧，表示"仍在动但静止表达"）+ 状态文字 `运行中` | 完整保留（颜色 + 形状 + 文字） |
| waiting 光环呼吸 | 药丸保留填充 + 文字 + 置顶 + 顶部状态条；仅取消脉冲动效 | 完整保留（填充面 + 文字 + 位置） |
| failed 一次性闪 | 直接显示三角 + 文字 `失败` | 完整保留 |
| 状态切换 180ms 交叉淡入 | 瞬时切换 | 完整保留（切换本身不承载信息） |
| 列表插入/置顶 200ms 位移 | 瞬时重排 | 完整保留（位置即信息） |
| 抽屉 280ms translateY | 改为**纯淡入 120ms**，无位移 | 完整保留 |
| 浮层 220ms scale | 纯淡入 100ms | 完整保留 |
| 计量条 200ms 展开 | 瞬时展开 | 完整保留 |
| 按下反馈 90ms 填充 | **保留**（不取消） | 这是触感反馈，与装饰性动效不同源，减弱动态模式下仍应保留（iOS 规范亦如此） |
| 骨架屏 | 静态灰块（本就无 shimmer） | n/a |

**实现判据**：`MediaQuery.disableAnimations == true` 时，所有时长走 `Duration.zero`（按下反馈除外）；
省电模式时，只把 `isLooping == true` 的动画换成静态形态（见上表），一次性过渡保留。

## 6. 签名元素（The signature element）

### 6.1 提案：**信号轨（Signal Spine）**

**一句话**：在**每一条**会话行、每一个会话详情头、每一个审批入口的最左缘，贯穿一条 3-4dp 宽的竖直"轨"，这条轨的**粗细、明暗、纹理、运动**编码该会话的状态，是全 App 唯一"大面积使用饱和色"的地方。

**形态**
- 位置：行最左缘，贴屏幕左边（`padScreen` 之外，通高），不是内缩的装饰条，而是**出血到屏幕边**的一条 3-4dp 竖条。
- running：4dp 实心绿 + 内部一条 2dp 亮彗尾从上往下流动（1.6s 循环）。
- waiting：4dp 实心金 + 外侧柔和光晕呼吸；该行同时置顶。
- blocked：4dp 紫色**断续斜纹**（静态）。
- done：退成 1dp 极细暗线，几乎不可见。
- failed：4dp 红实心 + 一个 6dp 三角缺口。
- offline/disconnected：2dp 中性灰虚线段。

**为什么它能从"一堆截图"里被认出来（去掉标签仍可辨）**
- 它是**列状的**：一屏 8 个会话，扫一眼是一排"长短、明暗、动静不同的竖条"，形成一个**可排序的视觉序列**（用户可以纯靠余光把"在跑/等我"的挑出来，不读任何字）。
- 它**出血到屏幕边**，形成一个连续的"状态脊柱"，视觉上像终端/监控面板，这是开发者审美熟悉的语言，不是消费 App 的圆角卡片。

### 6.2 防御（对比明显候选）

| 候选 | 为什么不是它 |
| --- | --- |
| **状态小圆点**（当前做法） | 已被用户否决（"太简陋"）。8px 圆点面积太小、色相面积小，斜视/瞥视几乎读不出；且所有态形状一样，只能靠色相区分，违反"不靠颜色"。 |
| **分段上下文计量条**（参考项目） | 是好设备但**属于数据不属于状态**，且它只出现在详情页、列表页用不上。借鉴它（§7 context meter）但不做签名。 |
| **底部"需要我"坞 / Dock** | 好的**导航**模式，但 Slack/Linear/邮件都有，不独特；且与输入框争抢拇指区。保留为功能元素，不作签名。 |
| **大圆角渐变/玻璃 Hero 卡** | AI slop，且暗底 OLED 上渐变糊、费电、误导状态。 |
| **每个 preset 一个色的头像/标签** | category-reflex，AI 味重；preset 是配置不是状态，不该吃颜色预算。 |
| **信号轨** ✅ | 单一构件、通高出血、靠**长度/明暗/纹理/运动**四维编码状态，去色可辨，功能动机强（周边视觉排序），40 次/天不累。 |

### 6.3 两个备选（runners-up，若信号轨在实机验证中不够显眼）

1. **固定三列指标微栅（Monospace metric grid）**：详情页底部/行内的 `15 轮 · 283 步 · TTFT 4.3s · Cache 99%` 固定成**标签上、数值下的两行等宽小栅格**（而非一行 `·` 串）。好处：数据对齐、可扫。缺点：这是参考项目已有的设备，辨识度不属于"千寻独有"。
2. **状态字标（State wordmark）**：状态用等宽大写短词（`RUNNING` / `WAITING`）做文字通道。好处：非颜色通道极强。缺点：太微妙，作为签名不够"有形"。

### 6.4 信号轨的具体规格（可直接实现）

| 项 | 规格 |
| --- | --- |
| 宽度 | 3dp（done 态 1dp；offline/disconnected 2dp） |
| 位置 | 贴屏幕左缘，**出血**到 0dp（不是内缩到 `padScreen` 内）。行内容的 `padScreen` 相应从 16dp 减到 12dp，保证行宽不缩水。 |
| 高度 | 贯穿整行视觉高度（32dp 或 72dp），**不**超出（不留悬空） |
| 圆角 | 上圆角 3dp、下圆角 3dp（与行的圆角 10dp 略小，避免"贴不紧"） |
| 分组间隙 | 组内行之间**不画分隔线**（信号轨连续成串，本身就是分隔）；只在**组与组之间**画 1px hairline 通栏 |
| 与命中区关系 | 轨道属于行的视觉内容，命中区仍是整行 48dp |
| 亮色变体 | 轨宽保持 3dp，但 waiting 的"光晕"改为同色 12% 淡填充外扩 4dp（暗色用外发光） |
| 出现范围 | 会话列表、连接列表、会话详情头、审批单顶部左侧、待处理交互条左侧 |
| **不出现** | 消息气泡内、工具输出行内、日志行内（那些地方状态由父级承担，加轨会变成"轨林"） |
| 减数原则 | 同一屏最多 10 条轨（超出靠滚动）；若会话 > 30，waiting 之外的轨降到 1dp |

**为什么是 3dp 出血轨而不是 4dp 内缩条**
- 出血让轨在屏幕左缘形成**连续垂直线**，视觉上像"状态脊柱"，这是签名识别度的来源。
- 3dp 是"看得见但不妨碍中文首字辨识"的下限（中文全角字 16px，3dp 轨不会让首字看起来缺一块）。
- 内缩条会变成"每个卡片左边一个小色块"，退化成另一种圆点，签名就丢了。

### 7.1 SessionRow 深挖（当前 UI 的主要返工点）

**现状（要改掉的）**
```
┌──────────────────────────────────────┐  ← 圆角卡
│ ● 我的项目重构                        │     16dp 卡内边距
│   帮我把这个模块拆一下…                │     2 行预览
│   空闲 · iot_tool_cloud · 7 轮 ·      │     Wrap 换行成 2-3 行
│   365k ctx · ↑152k · 2 小时前         │
└──────────────────────────────────────┘
```
问题：① 等大等重卡，状态不分级；② 2 行预览占掉最贵的空间；③ 元信息 `·` 串换行成噪音；
④ 状态只是"小圆点 + 第一个词"，去色后什么都不剩；⑤ 强调色无处可用；⑥ 视觉 108dp/行，一屏 6 行。

**方案**
```
│▌ 运行中  我的项目重构                        2 分钟前   │  ← 32/72dp
│▌        上一动作：写入 lib/app/theme/qx_tokens.dart      │
│▌        轮次 7   上下文 365k/1M   输出 ↑152k            │  ← 微栅 3 列，等宽
```
（`▌` = 信号轨。waiting 行动态多一行：药丸 `等我确认` + `[查看]`。）

逐项对照：
| 维度 | 现状 | 方案 | 依据 |
| --- | --- | --- | --- |
| 卡片 vs 列表 | 每行一卡 + 8dp 间距 | 分隔线列表（组间通栏线） | 密度：64dp/行，一屏 10 行（§3.5） |
| 状态通道 | 小圆点（仅颜色） | 3dp 出血信号轨（色+粗细+运动）+ 状态点（形状）+ 状态文字 | 不靠颜色（§4.0） |
| 预览 | 2 行 prompt | 1 行"上一动作"（running/waiting 才显示） | 5-40 秒只读得下一行；"上一动作"比 prompt 更有信息量 |
| 元信息 | `·` 串 + 换行 | 3 列定宽微栅，标签上数值下，等宽，永不换行 | 消除 Wrap（§8.12） |
| 时间 | 混在元信息末尾 | 右上角独立 `micro` | 位置即优先级 |
| 强调色 | 无处可用 | 仅按下/选中 | 强调色必须有唯一职责（§1.3） |
| 命中区 | 随卡片（约 108dp） | 48dp 独立，视觉 32dp | 拇指容错 |

**Anatomy 精确尺寸**
- 轨道 3dp 出血；行内容左内边距 12dp（让开轨道）。
- 状态点 8dp，位于标题行左侧，与标题基线对齐（不是垂直居中于整行）。
- 标题 `bodyStrong` 16/24，1 行，`…` 截断，右侧留给相对时间（`micro`，宽 48dp 固定，避免抖动）。
- 副行 `micro` 12/16，1 行，缩进对齐标题左缘。
- 微栅 3 列，每列 `metricLabel` 11/14 + `metricValue` 15/20（等宽），列间距 16dp，列宽固定不均分。
- 整行高：普通 64dp（内容 32 + 上下 16）；waiting 态 72dp（多一行药丸）。

### 7.2 数据格式化规范（中文界面）

统一的格式化，避免各页面各写一套：

| 数据 | 格式 | 例 | 注意 |
| --- | --- | --- | --- |
| 上下文 token | 千/百万缩写，**不超过 3 字符** | `365k` / `1.2M` | 不用「36.5万」；`0` 不显示（无数据就不显示该项） |
| 上下文占比 | `已用/窗口` 或仅 `%` | `365k/1M` 或 `36%` | 窗口未知时只显示已用绝对值（§10.3 风险 3） |
| 输出 token | `↑` 前缀 | `↑152k` | 箭头是 ASCII `↑`(U+2191)，不是 emoji |
| 轮次 / 步数 | `N 轮` / `N 步` | `7 轮` `283 步` | 中英文之间**不手动加空格**，系统排版会处理 |
| 相对时间 | 见下 | | 列表右上角 |
| TTFT | 一位小数 + `s` | `4.3s` | 无数据不显示 |
| 缓存命中率 | 整数 + `%` | `99%` | 无数据不显示 |
| 退出码 | `exit N` | `exit 1` | 非 0 时用 `failed` 色 + 文字 |
| 路径 | 尾部保留，段间 `/` | `…/lib/app/theme` | 从左截断（`path` 中间省略），保留文件名 |

**相对时间阶梯**（列表右上，1 个 token 宽）
```
刚刚        < 60s
N 秒前      < 60m      （只在 waiting/running 行显示，更细）
N 分钟前    < 24h
N 小时前    < 7d
昨天 HH:MM  < 48h
M-D         < 7d
M 月 D 日   更久
```
超过 7 天直接给日期，不给相对时间（"23 天前"没有信息量）。等宽字体，右对齐。

## 8. 反模式（Anti-patterns）

以下每条都直接对应**当前截图**的具体失败，重构时逐条对照。

1. **禁止一叠等大等重圆角卡**（当前失败：所有会话一模一样的圆角卡）。同态会话用**分隔线列表**（`hairline`），不同态用**信号轨**分轻重；不再"一张卡一格"。
2. **禁止 `·` 串起来的一坨换行元信息**（当前失败：`空闲 · iot_tool_cloud · 7 轮 · 365k ctx · ↑152k · 2 小时前` 全挤在一行还会换行）。改为**固定 3 列微栅**（标签上/数值下，等宽），永不换行，超出用省略号；`·` 只在"标签::值"设备里出现，不用作分隔符。
3. **禁止每行都放 2 行 prompt 预览**（浪费最稀缺的两行，且 90% 的预览用户不会读）。改为**1 行**，且**只对 running/waiting 行显示**（用一行"上一动作"替代完整预览），done/offline 行不留预览。
4. **禁止强调色用在无意义处**（当前失败：accent 什么都没标）。accent 只在"可交互/已选中/焦点"出现，状态点/装饰一律不用。
5. **禁止只靠颜色表达状态**。每个状态必须有形状（§4.0）+ 文字。去色截图仍可辨。
6. **禁止纯黑 `#000` / 纯白 `#FFF`**。用 `#0B0E13` / `#FEFFFF` 等带色偏的近黑近白。
7. **禁止渐变、玻璃拟态、霓虹、发光文字**。暗底 OLED 上糊、费电、且是 AI slop 的主要来源。
8. **禁止给 CJK 加字距/全大写**。中文无大小写；`sectionHeader` 之外的正文一律 `letterSpacing: 0`；正字距只给纯 ASCII/等宽小标签。
9. **禁止 emoji 当图标**。用统一的线性图标集，图标单独出现时必须有 `tooltip`。
10. **禁止把状态标签和 ctx/token 数字用同一字重**。状态 = 强（`monoOverline` w700 + 色），数字 = 弱（`metricValue` 等宽中性），一眼分得开主次。
11. **禁止 < 48dp 的可点区域**，禁止密集行只有 32dp 就结束（用 padding 把命中区撑到 48dp）。
12. **禁止在列表用 `Wrap` 让元信息换行**（当前 `_MetaLine` 用了 `Wrap`，正是"一坨换行"的元凶）。元信息用定宽微栅，不换行。
13. **禁止回弹/弹性动效**。
14. **禁止在文案里用长破折号（em dash）**。改用逗号、冒号、句号、括号。（本规范正文亦遵守，无一例外。）

## 9. 无障碍（Accessibility）

无障碍不是附加项：**斜视、低对比、老花、屏幕阅读器**和 §0.1 场景里的"瞥视"是同一类问题（信息获取成本）。

### 9.1 语义标签（Semantics）

每个复合组件必须给屏幕阅读器一个**完整句子**，而不是"按钮"：

| 组件 | Semantics label 示例 |
| --- | --- |
| SessionRow | `我的项目重构，运行中，7 轮，上下文 365k，2 分钟前` |
| SessionRow（waiting） | `我的项目重构，等我确认，双击查看审批` |
| ToolCallRow | `Bash，读取 gradlew.bat，成功` |
| ContextMeter | `上下文使用 36%，系统 12%，工具 9%，消息 15%` |
| StateBanner | `有 1 个会话等你确认`（并设为 `liveRegion`，状态变化时播报） |
| 状态点 | **不单独暴露**（状态已包含在行 label 里，避免重复播报） |

- 状态变化用 `liveRegion`（Android `announceForAccessibility`），但**只播报 waiting/failed**（需要人介入的），不播报 running（会刷屏）。
- 状态点、装饰性图标标 `excludeSemantics`，不进朗读顺序。

### 9.2 焦点与操作

- 焦点顺序 = 视觉顺序（轨 → 状态 → 标题 → 微栅 → 动作）。
- 所有可点元素可聚焦（支持外接键盘/开关控制），焦点环 2dp（高对比 3dp），用 `accent`。
- 图标按钮有 `tooltip` 且 tooltip 文本会进 Semantics。
- 命中区 ≥48dp（§3.5），相邻动作间距 ≥8dp。

### 9.3 视觉无障碍

- 正文对比 ≥4.5:1，大字/色块 ≥3:1（§1.6 全部实算通过）。
- 不靠颜色单独传信息（§4.0 形状语法）。
- 高对比模式：文字提级、描边加粗、焦点环加粗（§10）。
- 字号缩放钳制 0.9-1.3（§2.3），且尊重系统"粗体文本"开关。
- 减弱动态有静态替代（§5.4）。

### 9.4 色觉

7 状态在**红绿色觉障碍**下是最危险的一组（红/绿会混）。解法不靠改色，靠：
1. **形状语法**（圆/药丸/方斜杠/空心环/三角/虚线环/斜杠环）完全独立于色相。
2. **文字**每个状态都带。
3. 把"红/绿"这对（failed / running）在**位置**上分开（failed 独立成组，或 running 用形状+动效主导）。
4. 可选设置：`增强状态区分` 打开后给每个状态点加唯一图案（已默认启用，形状即图案）。

## 10. 深浅色对等（Dark / light parity）

**结论：两种都做，且暗色是默认与"母版"（dark-first）。**

- **为什么两种都要**：场景写的是"地铁/会议室"（暗），但用户也会在亮环境（办公室、阳光）看，工程师不会接受一个只支持暗色的工具。且系统级浅色模式是用户的系统偏好，应尊重。**先在暗色把层级、对比、状态色关系定死，亮色是对等重做，不是反色。**
- **默认哪个**：跟随系统；首次安装若系统为亮，也**默认启动在暗色**（产品调性 + 场景更常见），可在设置里改。这是"dark is default"的具体含义。

**亮色模式必须额外做对的事（不能简单反色）**
1. **状态色加深**：暗色用的粉彩状态色在亮底上会"发白、洗掉"。亮色用 §1.4 表的**加深版**（如 running `#0A7A52`、waiting `#9A6100`），保证小字 ≥4.5:1。几何形状、字重、字号**完全不变**，只换色值。
2. **描边加粗**：亮色底上，靠"表面提亮 1 档"分层很弱，**必须靠描边**。因此亮色 hairline 权重提高（可用 1.2-1.5dp 或更深一档的色），`surface` 与 `canvas` 的亮度差要拉开。
3. **信号轨的"光晕"要改写**：暗色用外发光，亮色没有"发光"概念，改为**实心轨 + 一圈同色 12% 淡填充光晕**（或加粗轨宽），保持 running/waiting 的跳脱感。
4. **阴影更重、遮罩更淡**：亮色上浮层靠阴影抬起，阴影不透明度提高（暗色 0.5 → 亮色约 0.12-0.18），但遮罩反而要更淡（亮色遮罩 0.28），避免整体压灰。
5. **强调色加深**：亮色 accent 用 `#0E6F82`（深青），按钮上的文字用白色，保证主动作不"发飘"。
6. **文本全部下调**：`textPrimary` 用 `#141A21`（非纯黑），`textTertiary` 仍保 ≥4.5:1（用 `#62707D`）。

**高对比模式（High contrast）**
- 所有 `textTertiary` 提升到 `textSecondary`（等效 5.5:1 以上）。
- hairline 加粗到 2dp 并改用更高不透明度。
- **状态点/轨加"冗余纹理"**：实心/空心/虚线/斜纹/三角本就是纹理；高对比下再给 waiting 药丸、failed 三角加深色描边。
- 焦点环加粗到 3dp。

## 11. 开放问题与风险（Open questions / risks）

| # | 问题 / 风险 | 影响 | 建议处理 |
| --- | --- | --- | --- |
| 1 | **"等我确认"在前台之外怎么送达**：App 在后台时，屏幕内的药丸/光环看不见。是否已有（或能否加）VPN 可达的系统推送通道？ | 最高优先状态可能收不到，是产品级缺口。 | 推送的视觉需与 App 内一致（金色药丸），且需服务端支持穿 VPN。若无推送，App 内置轮询 + 打开即置顶。 |
| 2 | **"blocked（受阻）"当前数据里是否可判定**。现有字段是 `running` / `agentAvailable`，没有显式 blocked。 | 形状语法第 3 格可能无源。 | 先用可判定的 6 态（running/waiting/done/failed/offline/disconnected）落地；`blocked` 作为**派生提示**（如 step 计数停滞 > N 秒）标注为"疑似"，或等产品字段补齐。**不要伪造状态。** |
| 3 | **上下文窗口分母从哪来**（不同模型窗口不同）。 | 计量条百分比算不准。 | 用预设窗口表按 preset 映射；取不到分母时只显示已用 token 绝对值，不显示百分比（诚实降级）。 |
| 4 | **TTFT / 缓存命中率 / 轮步数并非每个 agent 都有**。 | 3 列微栅会出现空槽。 | 微栅**按存在项降级**（有 2 列就 2 列，不留空框）。不显示 0，不占位。 |
| 5 | **CJK 系统字体差异**导致真机上字距观感不一。 | 视觉一致性略打折。 | 可接受（换来的是不打包 10MB 字体 + 原生锐利）。用固定行高与字重压住差异。 |
| 6 | **高对比模式在 Flutter 上主要是 iOS 概念**，Android 需手动开关。 | Android 难以自动启用。 | 设置里提供显式"高对比"开关，映射到 §9 的加深/加粗 token。 |
| 7 | **running 彗尾的 1.6s 循环在低电量下的观感**。 | 可能被用户关掉；若被关，running 会不会读不出来？ | 实心绿 + 流动是双通道；关掉循环后仍剩"实心绿圆点 + 文字运行中"，可读性不丢。彗尾是增强不是唯一通道。 |
| 8 | **信号轨出血到屏幕边**与全面屏/刘海/挖孔/手势条的适配。 | 极窄屏或横屏时轨道视觉不均。 | 轨宽 3-4dp 固定，永不压缩；顶部避开状态栏区。 |
| 9 | **"标题1行 + 预览1行"是否够**。用户可能想在列表里看更多上下文。 | 潜在信息不足。 | 保持 1 行（5-40 秒预算）。更多上下文放进详情页，不挤列表。 |
| 10 | 与桌面端千寻的**品牌一致性**（桌面端也有状态色）。 | 两端状态色可能漂移。 | 强调色沿用现有青系；状态色建议抽一份**跨端共享**的色板文档，桌面端参考本文 §1.4。 |
