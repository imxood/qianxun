## 0. 这一版真正修掉的三件事

| # | 问题 | 症状 | 根因 | 修法 |
|---|------|------|------|------|
| 1 | 侧栏展开挤压主区 | 标题竖排成「Into the Unkno wn」 | 侧栏是 grid item，硬占 280px | 展开态改 `position:fixed` 全屏浮层 |

## 1. 布局：`[data-slot]` 才是能用的锚点

### 1.1 第 2 版的 §A 全是死代码

第 2 版写了 12 组窄屏适配，用的类名是 `.dshm-shell` / `.dshm-drawer` /
`.dshm-details` / `.dshm-scrim` / `.dshm-main` —— **我自己编的**。

真机实测这 5 个选择器各命中 **0** 个元素：

```json
{"dshmShell":0,"dshmDrawer":0,"dshmMain":0,"qxFullBtn":0}
```

也就是说「custom.css 窄屏适配（12 组规则）已部署」这句话是错的：
部署了，但一条都没生效。

> **律**：CSS 规则不查命中数，等于没写。

### 1.2 DSH 暴露的是 `data-slot`（Base UI 的部件标记）

实测枚举（`docs/probe/dom-anchors.json`），共 45 个 `data-slot` 值：

```
root  sidebar  main  rightbar  shell.overlay
conversation.composer / .input.dock / .input.overlay / .header / .session …
sidebar.workspaces / .panellist / .footer.action / .settings …
```

它们是 `display: contents` 的**语义标记**（自身没有盒子），
真正的面板是它们的子元素。与之相对，class 是构建期哈希
（`hHd-Xa_root` / `bhn1Oq_root` / `pI_x6G_frame`），每次构建都变。

### 1.3 挤压的确切机制

```
[data-slot=root] > *          display: grid
  折叠态  grid-template-columns: 56px 356px 0px    ← 56px 图标 rail，正常
  展开态  grid-template-columns: 280px 132px 0px   ← 主区只剩 132px！
```

412px 的视口里，侧栏 280px 是静态 grid item，主区被挤到 132px。

展开/折叠的状态锚点是 frame 上的 `data-sidebar-collapsed`，
且**展开时该属性是「不存在」而不是 `"false"`**（实测确认）：

```json
{"collapsed": null, "inlineStyle": "grid-template-columns: 280px minmax(0px, 1fr) minmax(0px, 0px);"}
```

所以展开态的选择器是 `:not([data-sidebar-collapsed])`。

### 1.4 修法与实测

```css
@media (max-width: 760px) {
  [data-slot='root'] > :not([data-sidebar-collapsed]) {
    grid-template-columns: minmax(0, 1fr) 0px 0px !important;  /* 内联 style，要 !important */
  }
  [data-slot='root'] > :not([data-sidebar-collapsed]) [data-slot='sidebar'] > * {
    position: fixed !important; inset: 0 !important; width: 100% !important;
    z-index: 60;                    /* 低于 DSH 自己的弹窗层 */
    overflow-y: auto; overscroll-behavior: contain;
  }
}
```

注入实测（`.tmp/probe_overlay.py`）：

```json
{"collapsed":false,"cols":"412.19px 0px 0px","sidebar":{"pos":"fixed","w":412,"h":810,"z":"60"},"overflowX":false}
```

**真机部署后复测**（`probe:false`，即不是注入态）同样成立。

### 1.5 还差一步：选完不会自动收起

浮层化之后暴露出第二个问题。实测：点会话**确实会跳转**
（页面标题变成新会话名），但侧栏**不收起**：

```json
{"before": false, "clicked": "最新代码部署测试环境\n3h"}   // 点之前是展开态
{"collapsed": false, "cols": "412.19px 0px 0px", ...}     // 点之后仍是展开态
```

桌面是三栏并排，「选完收起」没有意义，DSH 当然不做 —— 得我们做。

做法：捕获阶段监听 click，命中**会话行**才收起（点工作区行是展开/折叠，
不该收起），延迟一帧后点 DSH 自己的「Collapse sidebar」，
**不自己改 DOM 状态**（会和它的内部状态机打架）。

真机复测：

```json
{"collapsed": true, "cols": "56px 356.19px 0px", "sidebar": {"pos": "static", "w": 56}}
```

## 2. `data-row-key`：DOM 行 → sessionId 的映射

第 3 版最大的将就就是「拿不到 sessionId 与 DOM 的映射」，
于是退回按标题匹配，并自认「这是本轮唯一不优雅的地方」。

**这个结论是错的。** 映射一直都在：

```json
[
  {"txt":"服务部署",            "rowKey":"workspace:48231145-4874-434e-b47c-06070bff3668"},
  {"txt":"最新代码部署测试环境",   "rowKey":"session:session-776fc1e4-480b-4e49-82b7-f8ff63602092"},
  {"txt":"分析egui提交及工具影响", "rowKey":"session:session-bff240ba-656b-49e4-809f-242f8754d7cf"}
]
```

一次解决三个缺陷：

1. 标题被服务端截断到 40 字（实测 max=40），DOM 里还可能带 markdown 标记
   → 文本匹配根本对不齐
2. 实测 **4 条标题完全相同**（「我一般不看新闻 论坛 社交媒…」）
   → 第 3 版取「最近更新的那条」，那是**猜**，标题全同时必然张冠李戴
3. 12 字前缀在中英文混排下会误匹配

> **律**：判定「拿不到」之前，先确认找过**全部**可见锚点。
> 当时的候选只有 `role` / `aria-*` / class 三类，而 `data-row-key` 都不属于。
> 可见锚点清单要**定期重扫** —— 旧清单不代表没有新锚点。

## 3. Preview Notice：命中 0 个的抑制

### 3.1 真机 DOM

```
DIV._root_o6lrb_6            ← **通用** Dialog 宿主
  ├── DIV._mask_o6lrb_18     position:absolute，空文案，吞点击
  └── DIV._dialog_o6lrb_33  position:relative, z=1, [role=dialog]
       └── DIV
            └── P            ← 真正的文案在这里
```

三个类名共用模块哈希 `o6lrb`。

### 3.2 第 3 版为什么一条都没命中

它在 `div, section, aside, dialog` 里找**最小**的含文案容器，
遇到「子节点也含同样文案」就跳过、交给子节点处理。

但含文案的叶子是 `<p>` —— **不在那个标签列表里**。
于是 root / dialog / inner 三层 div 每一层都有「子节点也含文案」，
全部被跳过，一个都没隐藏。真机症状：

```json
{"dialogVisible":1,"hidden":0}     // hidden = 0
```

它是模态框，吞掉所有点击 —— 侧栏点不动、截图永远停在它上面，
看起来像「我们的代码没生效」，其实是别人的弹窗在挡。

### 3.3 不能隐藏它的父容器

`_root_o6lrb_6` 是**通用** Dialog 宿主，审批/提问卡片也走这里。
隐藏它等于顺手把手机端最关键的审批弹窗也废了。

所以只隐藏「文案匹配的那一个 `[role=dialog]`」+「它的遮罩兄弟」。

### 3.4 实测

```json
{"found":1,"dialogsLeft":0,"rootChildren":["_mask_o6lrb_18|none","_dialog_o6lrb_33 jLrgrW_dialog|none"]}
```

真机部署后（页面重载，不再需要手点 Continue）：

```json
{"dialogVisible":0,"maskHidden":1,"noticeHidden":1}
```

## 4. 未决：「未分组」区 —— 前提被实测推翻了

### 4.1 第 3 版的裁决

> 未分组 251 条：默认收起，且用 DSH 原生措辞（`group.ungrouped = 未分组`）。

依据是 `probe_workspace_ownership.py`：

| 项 | 条数 | 占比 |
|---|------|------|
| `session/list` 总数 | 394 | 100% |
| 注册表登记 | 143 | 36.3% |
| **未登记** | **251** | **63.7%** |

### 4.2 但 DSH 侧栏里根本没有这个组

全页扫含 `未分组|Ungrouped` 的叶子节点：

```json
{"ungroupedLeaf": 0, "items": ["服务部署","egui_hikvision_app","qianxun","iot_tool_cloud", ...]}
```

**即这 251 条在桌面端也只能靠搜索到达。**

### 4.3 于是这是个产品决策，不是实现问题

用户的目标是「在手机上能完成与 DSH Web 端相同的常规 Coding 开发」。
两个方向都站得住：

- **补上「未分组」组（默认收起）**：手机屏幕小，搜索比桌面难；
  多一个折叠区只增不减，251 条不至于够不着。
- **不补，严格对齐桌面**：桌面没有的东西手机也不该有；
  免得用户以为是两套数据。

> **律**：否定断言律 —— 「桌面没有」只能由一次成功的**全量**扫描证明。
> 上面那次扫描是全页 `querySelectorAll('*')` 的叶子节点匹配，成立。

## 5. 本轮新增的门禁

### 5.1 行为闸新增 4 项（`scripts/check_custom_js_runs.py`）

| 断言 | 钉住的缺陷 |
|------|-----------|
| Preview Notice 面板被隐藏 | 「叶子查找」命中 0 个 |
| 遮罩也被隐藏 | 面板没了但底下照样点不动 |
| 审批弹窗**没**被误伤 | 抑制范围失控 |
| 同名两条各自拿到自己的摘要 | 标题匹配张冠李戴 |
| 点会话收起 / 点工作区不收起 | 浮层挡住对话 |

### 5.2 变异测试（`scripts/mutate_custom_js.py`）

一道**从没红过**的闸门不能证明它有用。所以把修复前的写法塞回去，
看闸门报不报：

```
[变异1 · 退回标题匹配] 🔴 闸门抓到了
[变异2 · 退回叶子查找] 🔴 闸门抓到了
```

第一版变异只替换了 `querySelectorAll` 那一行，函数体还是新的，
闸门全过 —— 差点误判成「闸门没用」。**变异必须整段换**，
否则你验的不是缺陷。

## 6. 本轮验证手段

| 工具 | 作用 |
|------|------|
| `scripts/cdp_webview.py eval --file <路径>` | 表达式走文件，绕开 PowerShell 吞引号 |
| `.tmp/probe_overlay.py` | 把 custom.css 注入页面反复量布局，不走部署 |
| `scripts/mutate_custom_js.py` | 验闸门抓不抓得住 |
| `scripts/check_custom_js_runs.py` | 部署前行为闸（10 项） |

> CDP 注入只能验「这一版长什么样」，**验收必须回到真机部署后**。
> 本文所有结论都标了是注入态还是部署态。
