# 手机端要移植的到底是什么（基于实测页面的分析）

> 依据：用户给的 `http://127.0.0.1:49277/?token=…` 实测页面（逐屏点过），
> 以及 `mobile/src/` 现有 RN 骨架的源码。
> 本文只做分析，不含视觉稿。

---

## 0. 先纠正一个方向性错误

我之前做的是「**agent 状态遥控器**」：砍掉搜索、砍掉工作区、砍掉插件、
砍掉自动化任务、砍掉设置，理由是「低频」「不是主线」。

**那是把「在不兼容手机端的布局里挑出值得做的部分」，当成了「做这个产品」。**

实际要做的是：**把 DSH web 端整个产品在手机上重建**，
只把「桌面三栏」这种布局约束换成手机形态，**功能不减**。

判据也随之变了：

| | 遥控器（错的） | Coding 客户端（对的） |
|---|---|---|
| 用户是谁 | 旁观 agent | **自己写代码的人** |
| 核心问题 | 它在干嘛 | **我现在能不能把活干完** |
| 失败代价 | 少看一眼 | **干不成活** |
| 转录的地位 | 摘要 | **全部内容都要能读** |
| 工具输出 | 默认折叠就够 | **要能读全文、要能展开** |
| 文件编辑 | 不做 | **要能看、要能改** |

## 2. 现有 RN 骨架（要保留的部分）

`mobile/src/` 的结构证明你已经在 web 端之外另起了一层壳：

| 文件 | 作用 | 我的判断 |
|---|---|---|
| `HomeScreen.tsx` | **设备列表**（连接卡 + 状态点 + 长按 sheet） | ✅ **保留**，这是入口层 |
| `WorkspaceScreen.tsx` | 顶栏（返回「连接」+ 连接名）+ **底部 Surface 切换 tab** | ✅ **保留骨架** |
| `surfaces.tsx` | Surface 注册表：**「工作台」（WebView 加载配对 URL）+ 「远程桌面」（占位未实现）** | ⚠️ **这是要换掉的核心** |
| `AddSheet.tsx` / `ScannerScreen.tsx` | 配对引导 | ✅ 保留 |
| `probe.ts` | 进前台逐个探活（120ms 间隔，20s 轮询） | ✅ 保留 |

**关键结论**：RN 版的「工作台」是**一个 WebView 加载 DSH 网页**——
它没做任何移动适配，就是把桌面页面塞进手机。用户要的是
**用 Flutter 原生重做这一层**。

所以 Flutter 版的结构应是：

```
设备列表（沿用 RN 的 HomeScreen 逻辑）
  └→ 选中设备 → DSH 独立页（Flutter 原生，全部重写）
        底部 Surface 切换：对话 ←→ 远程桌面
```

## 3. 手机端的骨架怎么改（我的方案）

### 3.1 桌面三栏 → 手机两层

| 桌面 | 手机 |
|---|---|
| 左栏 280px 常驻 | **不存在常驻侧栏**。变成「抽屉」但**只在需要时** |
| 中栏 对话 | **主屏**（默认占满 100%） |
| 右栏 详情 | **底部 sheet / 全屏页**（点 ⓘ 滑上来） |

**关键判断：手机 390dp 减去侧栏 280dp 只剩 110dp，对话区没法用。**
所以侧栏在手机上**必须是覆盖层，不是并排栏**。

### 3.2 导航的两种形态，各管一段

DSH 侧栏有两个语义完全不同的东西，**不能合并**：

1. **全局面板**（插件、自动化任务、设置）—— 与当前会话无关
2. **工作区树**（目录 → 会话）—— 当前会话就在某个工作区里

手机上：

```
┌─────────────────────────────────────┐
│ ← qianxun        [👥2] [📁▾] [⋯]    │  ← 顶栏（会话屏）
├─────────────────────────────────────┤
│                                     │
│         对话内容（占满）              │
│                                     │
├─────────────────────────────────────┤
│  ┌───────────────────────────────┐  │
│  │ 描述你要构建的内容…            │  │
│  ├ +  🛡▾  MiniMax-M3.1…▾  🎤  ↑│  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
       ↑ 顶栏左侧的 ☰ 打开抽屉
```

**抽屉 = 侧栏**（工作区树 + 全局面板入口）。
**顶栏 = 侧栏在手机上真正需要常驻的那部分**（标题、工作区、菜单）。

### 3.3 顶栏的四个动作，逐个定手机形态

| 桌面 | 含义 | 手机做法 | 理由 |
|---|---|---|---|
| 👥 成员图标 | 子 Agent Team | **变成 chip**：`👥 3 在跑` | 图标看不出「有几个、在干嘛」 |
| 📁 工作区▾ | 切换工作区 | **进抽屉**高亮当前工作区 | 工作区切换和浏览是一件事 |
| ⋯ | 会话菜单 | **底部 sheet** | 菜单项在手机上要点得准 |
| ▥ | 右栏开关 | **去掉** | 右栏内容改成 sheet 主动拉起 |

**子 Agent Team 我建议做成可展开的 chip**，点开是一个底部 sheet，
列出每个子 agent 的 `name / role / phase`，可点进它的子会话。
依据：实测 `agentTeam.members[]` 已在 `projections.values` 里（探针验过），
`phase: active` 也实测存在，所以**数据是现成的**。

## 4. 「在手机上真正干 Coding」需要什么

这是你和之前目标的分界线。要在手机上完成一次真实开发，需要：

### 4.1 必做（缺一个就干不成）

| 能力 | 手机上的形态 | 现状 |
|---|---|---|
| 读 turn 流 | 全部内容可读，**不能只有摘要** | 已有骨架，需补全 |
| 读工具输出 | **必须能展开看全文**。Bash 输出 300 行时，桌面可以滚动，手机要能分段 + 全文 sheet | 已有折叠，需改造 |
| 读 diff / 文件改动 | **这是最关键的一块**。Web 端有 diff 视图，手机必须有 | 需新做 |
| 回答审批 | 审批卡片能在手机上完整批准/拒绝，**带命令全文** | 已有骨架 |
| 发送消息 + 附件 | 输入框支持图片、文件 | 已有基础 |
| 引导 / 排队切换 | 插到当前轮 vs 排到下一轮 | 需新做（手机无 Alt+Enter） |

### 4.2 工具行怎么变（我认为是移植的核心设计点）

Web 端一行：`> Bash :: 一句话结论`（点击展开看参数和输出）。

手机上这条**必须变**，因为：
- 一句话结论在 390dp 上只够 15-18 个汉字
- 但要看的是「这条工具调用干了什么」

**方案：两层披露**

```
┌─────────────────────────────────┐
│ Bash · 成功 · 1.2s        ›    │  ← 折叠态：工具名 + 结论 + 耗时
├─────────────────────────────────┤
│ $ rg --files lib/ | wc -l       │  ← 展开态：命令（等宽、不换行、横向滚）
│ 142                             │  ← 输出前 N 行
│ …还有 38 行            [全文]  │  ← 超过阈值才给「全文」按钮
└─────────────────────────────────┘
```

关键取舍：**不预渲染全部输出**。实测最长会话 72 轮 / 2485 步，
一次 `rg` 输出 2MB。手机上必须懒加载 + 截断 + 「全文」入口。

### 4.3 diff 视图（Web 端有，手机端必须新做）

Coding 场景下，**改了什么**比**说了什么**重要。
手机上的 diff 我建议：

- 行级视图（不是左右分栏——390dp 放不下并排 diff）
- 只显示**改动行 + 2 行上下文**，折叠未改动的连续块
- 顶部一行汇总：`+24 −8 · 3 个文件`
- 点头汇总 → 文件列表 → 点文件 → 该文件的行级 diff
- 不用语法高亮（手机上配色噪声大于收益）

## 5. 工作区树在手机上怎么排

Web 端：`role=tree`，工作区行可拖拽排序、可折叠，每区默认 5 条 + 「展开 N 条」。

手机上（393 条会话、6 个工作区）：

```
抽屉
├ 🞨 新会话
├ 搜索会话            ← 折叠成一个图标，点开变输入框
├ 工作区
│  ▾ qianxun                    ⋯
│     千寻项目定制搜索功能优化    9月8日
│     当前项目中 已经实现了 rust… 昨天
│     展开其余 12 个
│  ▸ egui_hikvision_app          （折叠，不渲染子项）
│  ▸ iot_tool_cloud
├ ────────────────
├ 插件
├ 自动化任务
└ 设置
```

**手机上砍掉拖拽排序**（精确拖拽在触屏上极难做对，
且要真机验证）。保留折叠和「展开 N 条」。

⚠️ 但要诚实说明：`session/search` 在**本部署**是 `openAt "never"`。
所以手机端的搜索**只能做本地过滤**（标题 + 工作区名）。
这一点必须对用户明说，不能做一个必然搜不到内容的搜索框。

—— 这不是砍功能，是把 tab 变成同一份内容上的两个粒度。

## 7. 我认为最容易做错的三处

1. **把桌面三栏压扁**。DSH 自己的 `dsh-mobile` 就是这么做的
   （56px rail + 详情右滑 + 唯一断点 900px），但那是「让桌面页面在窄屏
   不崩」，不是「为手机重新设计」。手机上侧栏必须是覆盖层。

2. **工具输出全量渲染**。最长会话 2485 步、一次 grep 2MB。
   手机上不做懒加载 + 截断 + 全文入口，会直接卡死。

3. **只做「读」不做「改」**。你要的是「不在电脑边也能 Coding」。
   如果手机上只能看不能改、不能批准、不能插话，那就是个花哨的只读终端。
