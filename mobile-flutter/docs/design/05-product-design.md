## 0. 先修这个，它比任何视觉工作都紧急

### 0.1 P0 缺陷：待答审批会凭空消失

`lib/features/workspace/application/interaction_controller.dart:207`

```dart
final interactionControllerProvider =
    StateNotifierProvider.autoDispose<InteractionController, InteractionState>(...);
```

它是 `autoDispose`，而全仓只有 `pending_interaction_bar.dart:21` 一个 watcher。
用户停在根页（`/connections`）或 `/logs` 时控制器被回收，`_bind()` 的订阅被取消
（`interaction_controller.dart:62-92`）。**此刻到达的审批根本不会被看见。**

而 `$events` **不重放**（harness 语义：通知只在连接存活期间投递）。于是：

- agent 永久挂在等待态
- 手机上没有任何解释
- 用户回来看到的还是「空闲」

**这条必须在动任何视觉之前修。** 它不是 UI 问题，它让产品最核心的承诺失效。

修法：改成 **非 autoDispose**，并且在 `AppRoot` 级别无条件 `watch` 一次。
待答状态是**连接级的、阻塞的**，它的生命周期不应该跟着任何界面走。

> 顺带：`SessionListController` 的注释声称有 `workspace/follow` 实时更新，
> 但代码里**没有任何订阅**（`session_list_controller.dart:107` 只有一次
> `session/list`）。列表要实时，是本次要**新增**的工作，不是要保留的。

### 0.2 已验证的事实（探针实测，视为既定）

我用 `scripts/probe_rpc.py` 直接打了线上网关，下列事实**已确认**：

| 事实 | 证据 | 意义 |
|---|---|---|
| `agentTeam.members[].id` **就是** `sessionId` | 三个会话逐一对上 | waterfall 的 `agentId` 可直接映射到会话行 |
| `userQuestions: {active, settled}` **逐会话下发** | `session/list` 每项都有 | **服务端直接告诉你哪条会话在等你**，不必推断 |
| `permissions.currentValue` 逐会话下发 | `"danger-full-access"` | 输入栏可显示权限档位 |
| `turnOutline: [{turn, seq, prompt, response}]` | 每轮都有 | 列表第二行的素材 |
| `agentAvailable: bool` | 子 agent 结束后变 `false` | 「已断开」状态的数据源 |
| **`session/search` 在本部署被禁用** | `openAt "never"` | **搜索框是死功能，必须砍掉** |
| RPC 参数信封 `{"args":{"request":{…}}}` | `session/list` 例外用 `_request` | 已落地，见 README §2.2.1 |

第 1、2 条关掉了 01 与 03 各自标记的**头号风险**：产品在「哪条会话在等你」这件事上
从「我们猜它卡住了」变成「**它告诉我它卡住了**」。

## 1. 核心判断

**这是一个遥控器，附带条件在场。**

用户不在电脑前。他在通勤、开会、沙发上，用一只手端着手机，瞄一眼自己一小时前
留在家里的那个 agent 还在不在跑、卡在哪、要不要他答一句话。

他不是来「阅读」的，是来**确认**和**介入**的。整个产品的一切取舍都从这一句推出来。

三个问题决定一切结构：

| 问题 | 形态 | 手段 |
|---|---|---|
| Q1 它现在在干什么 | 被扫 | 状态轨 + 活动行 |
| Q2 它刚做了什么 | 被读 | 转录 + 第二行摘要 |
| Q3 它卡住等我 | 抢占 | 待答链路（唯一允许抢焦点的） |

## 2. 状态词表：从 7 态收缩到 5 态

原先设想的 `blocked`（紫）与 `failed`（红）两态**没有数据源**。
收缩到已验证字段能区分的 5 态，恰好不多不少：

| 状态 | 判定 | 语义色 | 非颜色通道 |
|---|---|---|---|
| **运行中** | `running == true` | 绿 | 轨上流光 + 活动行 |
| **等你** | `userQuestions.active` 非空 **或** 本地有未答 waterfall | 琥珀 | 轨为虚线 + 行置顶 + 全大写中文标签 |
| **已完成** | `running == false` 且 `agentAvailable != false` | 蓝 | 轨 1dp 细线 |
| **已断开** | `agentAvailable == false`（子 agent 父会话结束） | 中性灰 | 轨为**虚线段** |
| **失败** | 最后一次 turn 以 `error` / `aborted` 结束 | 赤 | 轨为实心 + 三角缺口 |

> ⚠️ **绝不靠颜色单独表意。** 每态都配一个**可见中文标签**（运行中 / 等你 / 已完成 /
> 已断开 / 失败）出现在元信息行首。色觉障碍用户与灰度截图下都必须可读。

## 3. 签名元素：信号轨（Signal Spine）

三份文档里有**两个**独立提案指向同一形状：01 §4.4 的「4dp 状态轨」（内缩、带圆点、带
第四行活动行）与 02 §6.1 的「Signal Spine」（出血 3-4dp、靠粗细/明暗/纹理/运动编码）。
**同一想法到达了两次，这本身是最强的信号。**

**裁决：02 赢。** 理由是只有 02 解释了**为什么去掉标签后还能被认出来**：列状、可排序、
贴边成一条连续的线。01 的内缩轨会退化成「卡片左边一个小色块」，签名就丢了。

### 3.1 最终规格

- **位置**：行最左缘，**出血到屏幕边**（不是内缩），通高 54dp（不满格）
- **宽度分四档**：运行中 4dp / 等你 3dp / 已完成 1dp / 已断开 2dp / 失败 4dp
- **纹理两种**：实心（运行中、失败）/ 虚线段（等你、已断开）
- **运动只有一种**：运行中轨内有 2dp 亮彗尾自上而下流动，1.6s 循环
- **出现范围五条**：会话列表行、会话详情头、审批入口、连接行、待答驻留条
- **不出现**：正文行内、元信息行内
- **横屏**：随 SafeArea 内缩

### 3.2 被砍掉的减数

- ❌ 02 §6.4 的「超过 30 条就降到 1dp」：**砍掉**。分级宽度是本设计的核心编码，
  超过 30 条时唯一该做的是**保证**「等你」和「运行中」两档最粗，其余降到 1dp，
  而不是把等待区分不出来。
- ❌ 叠加圆点：**砍掉**。轨就是状态，再叠圆点是同一信息两个形态。

### 3.3 第二签名级元素不是颜色，是位置

01 §4.5 的置顶与 02 §4.2 的「该会话自动置顶到列表最前」是同一个决定，
且它比任何视觉装置都更能兑现「5 到 40 秒内找到要你管的那条」。

**采纳为强制规则**（不是可关的排序模式）：`等你` 的会话永远排在最前。

### 3.4 runner-up

| 候选 | 裁决 | 落点 |
|---|---|---|
| 等宽指标微栅 | 保留为组件，**不作为签名** | 会话信息抽屉（那里指标是**被查**的，列对齐才有价值）。不进列表行（那里是**被扫**的） |
| 状态字标 `RUNNING` 全大写 | **砍掉** | 状态词已必须以可见中文出现在元信息行里，再加一个是同一信息两个形态。中文界面根本没有大小写 |
| 轮次分隔线 | 保留 | 转录里让长会话可读的那个装置，不是签名但不可省 |

## 4. 会话行

### 4.1 现状错在哪

一屏 5 张**一模一样的圆角卡片**，每张：色点 + 标题 + 2 行预览 + 一串换行的元信息。
没有层级、垂直空间浪费、每行长得一样、**回答不了「谁在跑」**。

### 4.2 最终行结构

```
┌─┬──────────────────────────────────────────┐
│▌│ 最新代码部署测试环境                        │  ← 轨(出血) + 标题 15.5/w600, maxLines 2
│▌│ Bash  ./deploy.sh --env test                │  ← 第二行: agent 最近做的那件事
│▌│ 运行中 · iot_tool_cloud · 7 轮 · 365k ctx   │  ← 固定三格, 永不换行
└─┴──────────────────────────────────────────┘
  ↑ 轨 4dp 绿 + 流光 = 运行中
```

**行高 66dp 固定**（idle 与 running 同高），一屏 10 行。密度 90%。

### 4.3 第二行放什么（这是最贵的一次分歧）

三份文档在这里真冲突，**正确答案不在任何一份里**：

- 01 说放 agent 的**回复**（对）
- 02 说 running/waiting 才放「上一动作」、其余不放（密度对）
- 03 直接沿用现状的 `lastPrompt`（错）

**合并后的规则：第二行永远是「agent 最近做的那件事」。**

- 在跑 → 当前工具名 + 参数（从 `tool/call` 取）
- 刚收工 → `turnOutline.last.response` 的首行
- 查不到 → 空（不占位）

**永远不是用户自己说过的话。** 用户已经知道自己说了什么，他不知道的是 agent
**据此做了什么**。当前实现把用户输入的回声摆在最显眼的位置，是方向性错误。

### 4.4 元信息三格，永不换行

```
[状态标签] · [cwd 末段] · [N 轮] · [N k ctx] · [相对时间]
```

- 用 `Wrap` 会换行 → 用**固定三格**，`Row` + `Expanded`，溢出用 `…`
- 状态标签在**最前**且**带色 + 加粗**，是唯一带色的元信息
- 轮次 / ctx / 时间是次要信息，同色同字重
- cwd 已经被当作标题时**不重复**（这条是我上一轮 widget 测试逼出来的）

### 4.5 状态轨的三重编码

形状（轨宽/纹理）+ 颜色 + **可见中文标签**。三者任一可用，信息都不丢。

## 5. 导航

### 5.1 不用 tab，不用 drawer

| 方案 | 裁决 | 理由 |
|---|---|---|
| **底部 tab** | ❌ 砍掉 | 会为「一周打开两次的目的地」永久缴税 |
| **drawer** | ❌ 砍掉 | 参考客户端把列表塞进 drawer 是因为它的根是单个会话，我们是**反过来的** |
| **push 路由栈** | ✅ 采纳 | 已经是这样，且必须在根页 `push` 而非 `go`（`go` 替换栈，按返回会退到系统 = 杀进程，这个 bug 上一轮刚修） |

### 5.2 冷启动落点必须是会话列表

现在是 `/connections`。**错。**

用户 95% 的冷启动是想看 agent，不是想连电脑。正确行为：

- 只有 1 台已保存的电脑 → **直接进会话列表**，自动选中它
- 有多台 → 进会话列表，顶部一个紧凑的机器切换器
- 一台都没有 → 才是配对引导

连接管理降级为会话列表里的一个入口（顶栏的机器名可点）。

### 5.3 屏幕树

```
/                                  会话列表（根）
├─ /pair                           配对引导（仅首启 / 无设备时）
├─ /workspace/:sessionId           会话详情
│   ├─ → /workspace/:id/details   会话信息抽屉
│   └─ → /workspace/:id/trajectory 步骤视图（降级为抽屉内标签）
├─ /connections                    连接管理
├─ /logs                           运行日志
└─ /settings                       设置
```

**返回永远不退出 App**：根页按返回 → 退到系统（此时栈已空，退出是正确行为），
其余每一层都有可 pop 的上一页。

## 6. 「等你回答」链路

### 6.1 这是唯一允许抢焦点的功能

agent 卡住直到人回答。不抢焦点就等于这个功能不存在。

四级递进（01 §5）：

| 级 | 场景 | 手段 |
|---|---|---|
| L0 | App 在后台，socket 活着 | 本地通知，**说清是哪个会话** |
| L1 | App 在前台 | 列表行置顶 + 状态轨 + 顶部常驻条 |
| L2 | 用户在别的会话 | 全屏接管（可滑动退出，不阻塞返回） |
| L3 | 声音 / 震动 | **明确拒绝** |

**L3 被拒绝的理由**：L3 买到的是**误触**，代价是信任。一个每天用 40 次的工具，
一旦在地铁上误震过一次，用户就会开始忽略它，那时 L3 带来的每一次有效提醒
都被这一次误触抵消。不如诚实：强光环境不响。

### 6.2 审批安全策略（合并 01/02/03）

1. **归属**靠 `agentId == sessionId`（已验证）
2. **参数**靠 `callId` 反查该会话转录（`session.dart:386` + `transcript_controller.dart:313`）；未加载就先 `session/page` 拉一页
3. **查到** → 显示命令（等宽、横向滚动、**不换行**），「允许这一次」可用，accent 填充
4. **查不到** → 明说「这次调用没有带参数」，「允许这一次」**置灰**，只留拒绝与稍后
5. **永远只发 `allowed-once`**。协议只有四个结局，没有「始终允许」，**保留设计原则，实现零动作**
6. 拒绝后不可撤销，但在转录留一行 notice
7. 关闭 sheet **不发任何结局**（现状先 pop 后发是对的）
8. 提问 sheet **不可关闭**，显式「稍后」才发 `rejected` + `cancelled`

按钮文案「允许执行」**改掉**（读起来像长期授权）。状态色**不进按钮填充**。

## 7. 视觉系统

### 7.1 色彩策略：**Restrained**（克制）

95% 中性。饱和色只出现在**两处**：状态（轨、标签）与可操作（accent）。
注意力是最贵的资源，不能平均分配。

### 7.2 色板（02 §1，已做 WCAG 验算）

| 角色 | Dark | Light |
|---|---|---|
| `canvas` | `#0B0E13` | `#EFF2F5` |
| `surface` | `#12161D` | `#F7F9FB` |
| `surfaceRaised` | `#1A2029` | `#FEFFFF` |
| `surfaceSunken` | `#070A0E` | `#E4E9EF` |
| `textPrimary` | 非纯白 | `#141A21`（非纯黑） |
| accent（品牌青） | — | — |

**裁决要点**：

- 02 的色板**发**，落在 03 已要求新建的 `QxSemantic`（`ThemeExtension`）里，
  **不新建第二套令牌文件**
- 01 §0.5 有一处**事实错误**：它把品牌青当成运行色（代码里 `runningDark` 是绿）。
  02 把 **accent（青）与 running（绿）分开**是修正，采纳
- **亮色模式同一次改动一起做**。02 的值与对比度已算完，剩余只有五条规则加一行
  `themeMode`。超范围的是「不改」，不是「分两次改」
- 文字缩放从 0.9-1.3 **放宽到 0.9-2.0**，按 2.0 设计布局

### 7.3 层级靠描边，不靠阴影

OLED 上阴影几乎不可见（参考客户端 `tonalElevation = 0.dp` 是刻意关掉的）。
分层靠：**发丝描边 + 极轻表面提亮**。

### 7.4 排版

参考客户端的实测字阶是扎实的：16/24、14/22、13/20、12/18、11/14，**全部 letterSpacing = null**。
我们沿用这个骨架，补上两块它没有的：

- **mono 角色**（代码、工具名、路径、指标数字），`JetBrains Mono` 随包
- 指标数字开 **`tnum`（等宽数字）**，否则上下行数字宽度不同会抖

### 7.5 反模式（当前截图的具体失败，逐条对应）

| 反模式 | 现状证据 |
|---|---|
| 等大卡片网格 | 5 张一模一样，每屏 5 行 |
| 元信息换行 | `空闲 · iot_tool_cloud · 7 轮 · 365k ctx · ↑152k · 2 小时前` 折成两行 |
| 状态只有颜色 | 绿点/灰点，无文字区分「运行中」与「已完成」 |
| 预告回声 | 第二行是用户自己的 prompt |
| 装饰性 accent | 青色 FAB + 青色「空闲」标签，用在无意义的地方 |

## 8. Flutter 架构要点

完整版见 `03-flutter-architecture.md`，这里只列**施工时必须知道的裁决**。

### 8.1 转录列表

- **不用 `itemExtent`、不用 prototype、不用 `SliverFixedExtentList`。**
  估算错的固定高度造成的是**内容错位**，不只是滚动不精确
- `cacheExtent: 900`
- **行 key 必须编码 `callId`**，且**特判字面量 `'?'`**
  （`transcript_controller.dart:347` 给孤儿结果写 `callId: callId ?? '?'`，多个孤儿会撞 key）
- 输入栏**在滚动视图之外**；实时活动头在滚动视图**之内**
  （`SliverPersistentHeader(pinned: true)`，空闲时 `maxExtent: 0`）
- 粘底用 `jumpTo` **不是** `animateTo`：动画期间 `maxScrollExtent` 还在变，
  终点是移动靶，抖动比瞬时跳难看得多

### 8.2 流式文字

- **不是**「不逐字」vs「三层节流」的对立。01 对「不能逐字」的判断（行高抖动会让人
  点不中东西，这是可复现的物理问题），03 对「怎么做到不抖」的机制都对
- **流式行永远不用 `MarkdownBody`**：0.7.x 每次 `data` 变化都重解析整篇，
  一条 20KB / 30 个代码块的消息单次解析 p99 是十几毫秒 ⇒ **每 120ms 掉一帧**
- 流式行用 `Text.rich`，样式与 `MarkdownStyleSheet.p` 逐字段一致
- **默认值改 `sentences`**（03 默认 `always`），
  并提供设置项 `streamingText: always | sentences | off`
- 降级阈值：4000 / 12000 字符（**这两个数字是起点，不是实测值**）

### 8.3 必须先修的性能缺陷

`transcript_view.dart:323` 与 `:723`：**`ToolCallCard.build` 在每次 rebuild 时
eager 地 join 完整工具输出、并 pretty-print 参数**。一次宽 `rg` 就是一个 2MB 字符串。
`MarkdownStyleSheet` 也是每行每帧重建。

### 8.4 零 `repeat()` 动画

`test/ui_test.dart:247` 已经因为运行中的 spinner 而放弃 `pumpAndSettle`。
运行态的工具卡 spinner **删掉**，换成静态 `StateDot` + 文字角标。

### 8.5 国际化（当前是坏的）

`flutter_localizations` **缺失**，`MaterialApp.router` 没有 `localizations.delegates`
（`app.dart:61`）。Material 内建字符串在中文 App 里说英文。默认页、选择器、
权限对话框全中英混排。

**语言口径**：参考客户端中英混排（`标准模式`、`1 steps`）会破坏
`Title :: value` 那套排版装置的一致性。**定全中文**，英文只出现在代码、
路径、工具名这些**本身就是英文**的地方。

### 8.6 无障碍

- 8px 状态点对 TalkBack **零信息** → `Semantics(label: '运行中')`
- 展开的工具行：`Semantics(expanded: …)` + 按钮态
- 触摸目标 ≥ 48dp
- 文字缩放按 2.0 设计，12 组（字号 × 缩放 × 宽度）组合做门禁

## 9. 三份都漏了、但产品级设计必须有的

### 9.1 配对首启

现在只有一张 `AddConnectionSheet`，**没有首启引导**。第一次打开的用户
不知道「去电脑上开远程访问」。需要一个三步：解释 → 引导去电脑 → 扫码/粘贴 →
成功。参考客户端的做法（logo + 副标题 + Preview 按钮）**不要抄**：它占了 45% 屏高，
而且副标题只是把 App 名字重说一遍。

### 9.2 离线态的产品行为

明文 VPN 上 socket 会断。当前只在顶部显示一条横幅。离线时应该：

- **缓存**最后一次会话列表，离线时**可读**
- 输入框**禁用**并明说「需要连接」
- 时间戳**诚实**：显示「上次同步于 3 分钟前」，不要假装实时
- 审批**明确不可用**，而不是让用户点了个没反应的按钮

### 9.3 多台电脑

现在只有一个「选中连接」。用户有两台机器时，顶栏需要一个**机器切换器**。
第二签名元素（等你置顶）是**全局的**，跨机器也要成立。

### 9.4 折叠屏 / 平板

现在全是 390dp 单列。转录在宽屏上应该限制**正文宽度**（可读行长上限约
70 字符），工具输出与代码块才允许吃满宽度。

### 9.5 这次重设计「做完了」怎么判断

**现在没有任何一份文档说明验收标准。这是最要紧的缺口。**

可判定的验收项：

1. 会话列表一屏 ≥ 10 行，idle 与 running 行高相同
2. `等你` 的会话在 5 秒内能被找到（不滚动）
3. 状态在 8px 点尺寸、灰度截图、1/3 缩放下都可区分
4. 正文文字缩放 2.0 时零溢出
5. 状态点对 TalkBack 朗读出中文状态
6. 转录 2000 行滚动稳定 60fps
7. 状态色作为正文文字压在 canvas 上对比度 ≥ 4.5:1
8. 冷启动直接进会话列表
9. 返回键在任何一层都不退出 App
10. Material 内建字符串全中文

## 11. 明确不做

| 不做 | 理由 |
|---|---|
| 手机上传图片 | 手机拍一张传给家里的 PC 是绕远路，桌面端发图更直接 |
| 手机改模型 / 权限档 | 那是坐在电脑前才做的决策 |
| 真正的推送 | 明文 VPN 上没有可达的推送中继。**为了推送引入中继会毁掉 v1「装上就能用」的价值主张**。Android 走前台服务常驻 socket（iOS 做不到），**并把局限写进关于页** |
| `session/search` 搜索框 | 本部署 `openAt "never"`，是死功能 |
| 状态字标 `RUNNING` 全大写 | 与元信息行里的中文状态重复，且中文无大小写 |
| `blocked` / `failed` 两个状态色 | 无数据源，砍掉（见 §2） |
| 真·远程桌面 | 需要 xcap + 硬编 H.264 + 输入注入，是独立项目 |
| 子 agent 树 / 后台 job 面板 | 协议侧形状已备（`subagentCatalog`、`JobView`），但要等 P3 的转录稳定 |

## 附：与参考客户端的取舍

参考客户端（Kotlin/Compose）的**信息装置**值得学：单行工具披露行、
`Title :: value` 排版装置、分段式上下文计量表、密集指标底栏。

它的**色彩与排版**不学：默认 Material 浅靛蓝读起来很普通。

明确**反对**它的四处：

1. `chat.png` 的 Chat 标签是一面 19 行折叠工具行，**零结论**，那是日志，不是聊天
2. `TTFT 4.3s · 80 tok/s` 常驻聊天底栏，那是 PC 侧引擎指标，搬进信息抽屉
3. Chat / Trajectory 双顶层 tab，同一个会话两条找不着北的路，占掉一半转录空间
4. 连接页约 45% 屏高给了 logo + 副标题 + Preview 按钮 + 橙色警告，而副标题只是把
   App 名字重说一遍
