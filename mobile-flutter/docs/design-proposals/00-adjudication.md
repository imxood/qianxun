## 0. 裁决前我补跑的三组实测（都是「拍脑袋会错」的量）

### 0.1 上下文占用的真实分布 —— **推翻 C10 的阈值**

`scripts/probe_context_distribution.py`，全量 393 条：

```
带 contextPressure : 174 条 (44%)
min 1.8% · p25 12.4% · 中位 23.7% · p75 38.2% · p90 53.2% · p99 73.6% · max 75.5%

<20%  78 条 █████████████████
20-40% 59 条 █████████████
40-60% 33 条 ███████
60-70%  2 条
70-85%  2 条
85%+   0 条          ← 永不触发
```

| 阈值 | 命中 | 裁决 |
|---|---|---|
| 40% | 37 条 (21.3%) | ✓ 有意义 |
| 50% | 23 条 (13.2%) | ✓ 有意义 |
| 60% | 4 条 (2.3%) | ⚠️ 少见 |
| 70% | 2 条 (1.1%) | ❌ 几乎不触发 |
| **85%** | **0 条 (0.0%)** | ❌ **从不触发** |

**C10 写的是「<70% 不显示 / 70–85% 灰字 / >85% 琥珀 + 条」。**
按真实分布，最高档**永远不出现** —— 门槛设在一个不存在的区间上。
这不是「阈值调高一点」，是「设计了一个死状态」，与约束书 C1「状态必须
标注新鲜度」是同一类错误的镜像：**设计了一个从不触发的状态**。

**裁决**：阈值改为 **50% / 65%**（p90 / p99 附近）。
- `<50%` 不显示（约 87% 的会话，占多数，不值得占位）
- `50–65%` 灰字 `上下文 5x%`
- `>65%` 琥珀 + 条（命中 4 条，但**这 4 条恰恰是最需要看见的**）

⚠️ 仍保留降级阶梯（8格→4格→`Ctx 87%`→隐藏），MiniMax 那套照抄。

### 0.2 两个上下文口径不等 —— **不可互换**
`scripts/probe_context_calibration.py`：

```
contextBreakdown 三段求和 = 80878
contextPressure.pressureTokens = 98478     差 20.8%（12 条样本 15.7%–28.1%）
```

差值**不稳定**，所以不是「固定偏移」（例如预留位），更可能是两个不同的量。
且 `contextPressure` 里有两个数：`pressureTokens` 与 `projectedTokens`
（样本里 465240 vs 465695，差 0.1%）。

**裁决**：
- 百分比阈值**必须**用 `projectedTokens / contextWindow`（只有它给分母）
- 三段 `contextBreakdown` 只用于**定性**图例（System/Tools/Messages 占比）
- ⚠️ 我们现有代码 `SessionSummary.contextTokens` 读的正是 `projectedTokens`，
  **恰好是对的**，不用改。但要在代码里写清「这个字段是唯一权威口径」
- **未解**：两者差 20.8% 的原因未知。要裁决需在一条**长会话**上同时读，
  看哪个等于服务端自己 UI 上报的百分比。

### 0.3 宿主时钟 —— **B 的「9h55m 偏移」不成立**
B 提案据单条 item 的 `updatedAt`（比抓取时刻早 9h54m）推断时钟偏移。
我补跑 `scripts/probe_host_clock.py` 查全表最大值：

```
最新 updatedAt : 2026-10-05T12:33:32Z
距今           : 3:56:08
```

3h56m 完全符合「这段时间没在跑 DSH agent」。**时钟偏移的结论被推翻** ——
那只是一条没人动过的旧会话。

**但 B 的设计结论仍采纳**（理由换成稳健性，不是偏移）：
> 没有第二个时钟源交叉验证，所以 `updatedAt` **不做绝对时长**，
> 只用于「是否变化」与增量。

C5 的「11h35m」降级为**带锚点的时长**：`本次连接起 4 小时 20 分`。

## 2. 我不同意 B 的一处

**B §8.1 用 7 条件替代 05 §2 的 `已完成 = running == false`。**

方向对（5 个布尔量推不出一个诚实的「完成」），但 **7 个条件本身就是一次「用更多不相关的字段拼一个结论」**——
和当初被砍掉的「看回复开头是不是 `error:`」是同一类操作，只是伪装得更精致。

**裁决**：采纳「需要更多条件」，但**不采纳「7 个条件」这个具体数字**。
改为三档，且**拿不到证据就只显示最弱的那档**：

| 档 | 条件 | 文案 | 颜色 |
|---|---|---|---|
| 强 完成 | `running == false` ∧ `lastTurnCompleted == true` ∧ 无待答 ∧ inbox 空 | `已完成 · 第 4 轮` | 蓝 |
| 弱 收工 | `running == false` ∧ 其余不可知 | `已收工 · 状态待确认` | **中性灰** |
| 不知 | 快照陈旧 / 链路断 | `N 分钟前的状态` | 灰 + 降级轨 |

理由：C4 的原话是「**拿不到证据就不说完成**」。
弱档用**中性灰**而不是绿色，就是把「不确定」画成「不确定」。
