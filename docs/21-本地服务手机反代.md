# 21 — 本地服务手机反代（docs/20 命名续位）

> 状态：已实现（2026-10-31）｜ 模块：`src-tauri/src/remote/proxy.rs` ｜ 需求来源：开发者在千寻所在电脑上起了本地 web 服务（dev server），手机想直接访问。

## 0. 一句话

网关在 LAN 网卡上**另绑一个端口**（网关端口 + 2，release 23092 / debug 23093），这个端口的整个 origin 原样代理给「cookie 指定的本机目标」——手机浏览器打开 `http://<电脑IP>:<反代端口>/?_qx_to=127.0.0.1:5173`，即可像在电脑上一样访问本机 dev server（根相对子资源、fetch、SSE、WebSocket/HMR 全部工作）。

## 1. 为什么是「专用端口 + 整源代理」

- **路径前缀方案会被根相对 URL 打穿**：代理页 HTML 里的 `/src/main.ts`、`/api/...` 会绕过前缀直落 DSH 上游；运行时注入的 URL 更无法穷举改写。
- **`<base href>` 救不了**：绝对路径引用（`fetch('/api/x')`）按 origin 解析，不吃 `<base>` 的路径前缀。
- **专用端口的整个 origin 就是目标的 origin**：什么都不用改写；唯一的入口动作是「种目标 cookie」。
- 代价：手机要记住带端口的地址（收藏一次即可）；单端口同时只代理一个目标（`?_qx_to=` 换目标即切）。

## 2. 用法

1. 远程页启用「远程访问」并选网卡（已有能力）；「本地服务反代」默认开启。
2. 手机浏览器（已配对）访问 `http://<电脑IP>:<反代端口>/?_qx_to=127.0.0.1:5173`，未配对时先走 `/qx-gate` 配对（或在该 URL 后追加 `&token=`）。
3. 切换目标：访问 `/?_qx_to=<新目标>`；不带参数访问 `/` 得到引导页（内含换目标表单）。

## 3. 安全边界

| 面         | 规则                                                                                                                                                                                       | 证据                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| 鉴权       | 与网关 LAN 入口完全一致：配对 cookie / query token；回环 Host + 反代端口免 token（本机调试）                                                                                               | `proxy.rs` `ProxyState::authorized` |
| 目标白名单 | 默认仅回环字面量（`127.0.0.0/8` / `localhost` / `[::1]`）；「允许内网目标」开启后放行 RFC1918 + 链路本地 + IPv6 ULA 的 **IP 字面量**；域名一律拒绝（不做 DNS 解析，杜绝 rebinding 类绕行） | `proxy.rs` `parse_target`           |
| 凭据隔离   | 转发请求剥 `qx_token` / `qx_proxy_to` cookie——本地 dev server 无权看到网关凭据                                                                                                             | `proxy.rs` `filter_qx_cookies`      |
| 框架防护   | 回包剥 `x-frame-options` / `content-security-policy`（仅本 socket），目标可被 DSH 页 iframe 引用                                                                                           | `proxy.rs` `skip_response_header`   |
| Location   | 目标 origin 绝对地址改回根相对；外部跳转（OAuth 等）原样                                                                                                                                   | `proxy.rs` `rewrite_location`       |
| WS         | 帧级双向桥 + 600s 空闲超时（与 DSH 桥同策略）；子协议不透传（本地 dev server 的 HMR 不用，需要时是明确后续项）                                                                             | `proxy.rs` `bridge_ws`              |
| 开关       | `remote.proxyEnabled`（默认开，随「远程访问」面同生灭）；`remote.proxyAllowLan`（默认关）                                                                                                  | `remote/mod.rs` `RemoteSettings`    |

> 已知取舍：反代面 = 已配对手机可触达本机全部回环 HTTP 服务。这与「已配对 = DSH 全量权限」（分析报告 06 P1-3）同级，属同一威胁模型的既有取舍；若要收敛，后续可加端口白名单。

## 4. 实现落点（file:line 以实际代码为准）

- `src-tauri/src/remote/proxy.rs`：反代 Router、入口/引导页、HTTP 转发、WS 桥、目标校验、头处理（单测 + 两个端到端测试：HTTP 全链路、WS 回显）。

- `src-tauri/src/remote/commands.rs`：指纹新增两维（`proxy_enabled`/`proxy_allow_lan`）；`remote_status` 增 `proxyEnabled/proxyPort/proxyListening`；sync 日志含反代状态。
