# 03 · 编码规范

状态：草案 v1（待确认）。**本规范是质量门禁的一部分：M0 起强制执行，先于功能存在。**
规范的目的是控制熵增——代码量上去之后，靠的是规则与工具，不靠自觉。

## 1. 总原则

1. **简单直接优先**：先写对、再写好、最后才写"通用"。不为想象中的需求做抽象；
2. **注释解释为什么**，不复述代码在做什么；
3. **失败显式**：不允许吞错误、不允许"先这样后面再说"的静默降级；
4. **边界清晰**：跨边界的每一份数据都有明确类型；边界内随意重构，边界上谨慎变更；
5. **每个里程碑结束时必须可构建、可发布、可回滚**——不留"半成品主干"。

## 2. 模块化与依赖方向

### 2.1 目录即架构

前端按**功能域（feature-first）**组织，域内自治，域间隔离：

```
features/terminal/
  api.ts          # 该域用到的 IPC 调用（只准从 lib/ipc 封装走）
  store.svelte.ts # 该域状态（runes）
  TerminalPane.svelte  TerminalTab.svelte  …
```

**依赖方向（单向，禁止反向）**：

```
features/*  →  components/*  →  lib/*  →  （无依赖）
     ↘               ↘            ↗
       stores/*（域内 store 只被本域 import）
```

- `features/A` **禁止** import `features/B` 的任何文件；需要共享的逻辑下沉到 `lib/`，
  共享的 UI 下沉到 `components/`；
- `lib/` 不准 import `features/`、`stores/`、`components/`（保持纯与可测）；
- 每个功能域根目录放一个 `index.ts` 作为唯一出口（barrel），域外只准从 barrel 引入。

### 2.2 Rust 模块

- 一个子系统一个目录（`harness/`、`terminal/`…），目录内 `mod.rs` 只做声明与组装；
- `crates/` 下的 crate（proc-guard、node-runtime）**不依赖 Tauri**，保持可独立测试——移植时保持此性质；
- 模块对外暴露最小 API：`pub` 从严，能用 `pub(crate)` 就不 `pub`。

### 2.3 尺寸上限（超出即触发重构讨论）

| 单元                  | 上限                          |
| --------------------- | ----------------------------- |
| Svelte 组件 / ts 模块 | 300 行                        |
| Rust 文件             | 500 行                        |
| 函数                  | 80 行、圈复杂度 15            |
| features 域           | 状态文件超过 2 个即考虑拆子域 |

上限不是 目标，是**烟雾报警器**：超了先讨论拆分或豁免，不允许无意识增长。

## 3. 命名规范

| 对象            | 规则                                                           | 示例                                 |
| --------------- | -------------------------------------------------------------- | ------------------------------------ |
| 前端文件        | 组件 PascalCase，其余 kebab-case                               | `TerminalPane.svelte`、`log-tone.ts` |
| 变量/函数（TS） | camelCase，布尔用 is/has/can 前缀                              | `isSupervisorAlive`                  |
| 类型/接口（TS） | PascalCase；IPC payload 类型以 `Payload`/`Result` 结尾         | `HarnessStatusPayload`               |
| 常量（TS）      | SCREAMING_SNAKE_CASE                                           | `MAX_SCROLLBACK`                     |
| Rust            | 标准 rustfmt（snake_case / PascalCase / SCREAMING_SNAKE_CASE） | —                                    |
| IPC 命令        | `<域>_<动作>`，snake_case                                      | `harness_start`、`terminal_write`    |
| 事件            | `<域>://<种类>`                                                | `terminal://output`                  |
| 状态 store 文件 | `<域>.svelte.ts`                                               | `harness.svelte.ts`                  |
| 分支            | `feat/…`、`fix/…`、`chore/…`                                   | `feat/multi-tab-terminal`            |

禁用项：单字母命名（循环索引除外）、`data`/`info`/`temp`/`foo` 类无信息名字、拼音命名（"千寻"等项目专名除外）。

## 4. 注释规范

- **语言**：注释与文档用中文；标识符、类型名、命令名一律英文；
- **必须注释的四种位置**：
  1. **模块头**：Rust `//!` 块 / ts 文件顶部块注释，讲清这个模块"是什么、不是什么、关键决策"；
  2. **为什么**：任何反直觉、绕坑、有意取舍的地方；
  3. **公开 API**：`///`（Rust）与 JSDoc（TS）给导出函数/类型，说明语义与失败行为，而不是复述参数名；
  4. **魔法数与协议常量**：端口默认值、重试次数、就绪行格式等，注明出处；
- **禁止**：注释掉的死代码（删掉，git 会记得）、过时注释（改代码必须同步改注释）、`// TODO` 不带上下文
  （TODO 必须带里程碑编号，如 `// TODO(M4): 支持正则模式`）；
- **节奏**：注释密度服务于读者，不追求行数比例；一段难懂的逻辑没有注释视为未完成。

## 5. TypeScript / Svelte 规则

- **strict 模式**，禁 `any`（确需时 `unknown` + 收窄）；禁 `!` 非空断言（用收窄或显式分支）；
- **状态管理用 runes**：跨组件状态放 `stores/<域>.svelte.ts`，组件内局部状态用 `$state`；
  禁止引入 zustand/pinia 类库；`$derived` 优先于手写同步逻辑；
- **props 显式声明**（`$props()` 解构 + 类型），禁止传"一大包对象"再解构；
- **副作用必须可清理**：事件监听/定时器订阅一律在 `$effect` 返回清理函数或 `onDestroy` 里解除；
  任何"挂了没卸"的监听按 bug 处理；
- **组件不做业务**：组件负责展示与交互，数据获取和业务规则在 `api.ts` / `store.svelte.ts`；
- xterm、konva 等命令式库：封装成单一组件，DOM 操作不外泄到域外；
- 格式化交给 Prettier，lint 规则（eslint + eslint-plugin-svelte）零警告通过。

## 6. Rust 规则

- **禁止 `unwrap()`/`expect()`** 出现在非测试代码（常量初始化等极少数例外需注释说明不变量）；
- 错误统一走 `crate::error::Error` + `Result`，各子系统错误变体集中定义、带用户可读描述；
- 阻塞操作不进 async runtime（终端三线程就是先例）；
- 锁的持有范围最小化；跨线程共享状态优先用消息（channel）而不是共享可变状态；
- 每个模块头 `//!` 文档（同 §4）；公开项 `///` 文档；
- `cargo fmt` + `cargo clippy -- -D warnings` 零告警；`unsafe` 原则上不写（移植代码已有者注明理由）。

## 7. IPC 边界规则

- **合同唯一**：命令名与类型只在 `lib/ipc/contract.ts` 声明；前端任何其他文件禁止直接 `invoke`；
- 前端通过 `lib/ipc` 的 `call()` 封装调用：统一错误包装、超时、日志；
- Rust 命令处理函数**必须校验入参**（端口范围、路径合法性、枚举值），不信任前端输入；
- 事件 payload 必须是可 JSON 序列化的扁平数据，禁止把 Rust 句柄/复杂对象塞进事件；
- 双侧一致性由比对测试锁死（见架构文档 §5），不一致 = CI 失败。

## 8. 错误处理与日志

- **用户可见错误**三要素：发生了什么、为什么、能做什么（下一步动作）；
  禁止裸抛错误码或英文堆栈给用户；
- 前端：所有 IPC 调用失败必须被 `call()` 包装为带域前缀的 `AppError`，UI 层决定展示方式；
- Rust：错误日志带上下文（哪个子系统、什么参数），日志经脱敏（不含 token、完整路径中的用户名可保留）；
- 日志分级使用规范：`error`=需要用户行动，`warn`=异常但已兜底，`info`=生命周期事件，
  `debug`=开发期细节；禁止用 `info` 打调试信息。

## 9. 测试规则

**必须测**（这些地方回归代价最高）：

| 层               | 必测内容                                             |
| ---------------- | ---------------------------------------------------- |
| Rust：supervisor | 就绪行解析、端口校验、退避重启、健康探测判定         |
| Rust：settings   | 读写原子性、schemaVersion 迁移、非法值拒绝           |
| Rust：terminal   | 会话生命周期、退出清理（借 proc-guard 既有测试模式） |
| Rust：合同比对   | 命令清单与 contract.ts 一致                          |
| 前端：lib/utils  | 全部纯函数                                           |
| 前端：stores     | 状态迁移逻辑（vitest，不挂载组件）                   |

- **不必测**：纯展示组件、样式；不为覆盖率数字写测试；
- 每修一个 bug，先写复现测试再修（回归测试纪律）；
- 测试命名讲"行为"不讲"方法"：`端口被占用时返回明确错误` 而不是 `test_start_2`。

## 10. Git 规范

- Conventional Commits：`feat:` / `fix:` / `refactor:` / `docs:` / `chore:` / `test:`；
- 功能开发走 `feat/*` 分支，自审后合入 main（个人项目允许自合，但**禁止直接在 main 上堆提交**）；
- 一次提交只做一件事；提交信息说"为什么"（正文可空，但标题不许是 `fix bug`）；
- 文档与代码同仓：行为变更的 PR/提交必须带上 docs/ 的对应更新。

## 11. 质量门禁（M0 建立，之后不可绕过）

```sh
pnpm check        # 前端门禁：prettier --check + eslint(0 warning) + svelte-check + tsc + vitest run
cargo check       # Rust 门禁：cargo fmt --check + cargo clippy -D warnings + cargo test
pnpm release:check   # 发布前：以上全部 + 合同比对测试 + 构建产物冒烟
```

- 门禁不过不合入；豁免必须在提交信息中注明原因与期限；
- CI/本地脚本先行：M0 第一周就要让 `pnpm check` 与 `cargo check` 跑起来，规范才不是空话。

## 12. 依赖引入规则

- 引入新依赖前三问：是否已被现有依赖覆盖？维护是否活跃（近一年有发布）？体积/传递依赖是否可控？
- 前端运行时依赖白名单制（Tauri API、Svelte、Tailwind、xterm 全家桶、lucide、konva、CodeMirror；
  新增需在本规范追加记录）；
- Rust 依赖保持 proc-guard / node-runtime 零 Tauri 依赖的独立性；
- 禁止复制粘贴第三方大段代码而不注明来源与许可证。
