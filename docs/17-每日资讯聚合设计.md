# 17 - 情报页设计（每日资讯 + 模型雷达）

> 状态：草案 v3.1。需求：侧边栏一个「情报」入口，打开是主题卡片列表（至少 模型 / AI / 热点，主题可方便扩展）；每次启动当天只抓一次，之后可按主题手动刷新；数据可存、历史可查、感兴趣的内容可收藏；英文源经 LLM 后处理出中文标题/摘要（可选层，原文与来源 URL 永久保留）。UI 文案简洁。不处理代理（系统已有）。

---

## 1. 需求 → 设计

| 需求                                   | 设计落点                                                                                                       |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 侧边一个「情报」页，打开是主题卡片列表 | PageId `intel`，入口 = 主题卡片网格，点卡片进主题视图                                                          |
| 至少 模型 / AI / 热点，以后方便加主题  | **主题注册表**（§4）：Rust 侧一张 `TOPICS` 表驱动卡片渲染；视图只有两种（Feed / 模型表），新主题多数零前端改动 |
| 启动后当天只查一次，后续按主题刷新     | 调度 = 启动补抓（当日已抓则跳过）+ 每主题「刷新」按钮；**无定时器**                                            |
| 不考虑代理                             | reqwest 直连，不读 settings.web.proxy，不做代理设置                                                            |
| 数据如何保存                           | 按天按主题落盘 + 收藏独立成库（§8）                                                                            |
| 如何查看历史                           | 主题视图内「‹ 前一天 / 后一天 ›」日期导航，保留 90 天（§8.2）                                                  |
| 如何保存感兴趣的内容                   | 收藏 = **快照复制**进 favorites.json，不受历史清理影响（§8.3）                                                 |
| 英文源看不懂 / 是否 agent 参与         | **两层管线**（§7）：抓取层永远无 LLM、原始字段永远保留；LLM 只做「中文标题/摘要」增列，失败降级显示原文        |
| UI 文案简洁                            | 文案规范（§10.3）：按钮动词化，状态一行，不写长句                                                              |

## 2. 关键决策

1. **单页 + 主题卡**：不做多侧边项、不做 tab。卡片即导航，也是状态面板（今日 N 条 · 时间）。
2. **抓取放 Rust**：原生页面零 CSP 限制；reqwest 直抓公开 API/RSS；**DSH 不运行也能抓**。不用 qx-websearch 作主通道（那是 agent 单次查询工具链）。
3. **无后台定时器**：启动时比对 `state.json` 的 `lastFetchDate`，缺今天才抓（源间错峰 2~5s、并发 ≤3）。跨天不关机 → 主题视图顶部出「今日未抓 · [抓取]」横幅，用户一键补，不自动打扰。
4. **模型数据双免 key API**：HF Hub + OpenRouter（已实测 200，字段含定价/上下文/AA 指数/Arena Elo/`hugging_face_id` join 键）；LMArena 直连实测 403，不爬。
5. **每指标带 Provenance**：性能等指标逐项记录 `{source, fetchedAt, 原始页链接}`，详情抽屉显示来源徽章——「数据来源」落到字段级。
6. **LLM 后处理是可选增强层**：不配模型或调用失败 → 显示原文，功能完整可用；LLM 输出只写 `zhTitle/zhSummary` 新字段，**永不覆盖原始字段**；不用 DSH agent 会话（重、面向交互），走 **DSH llm 服务的插件桥**（首选）或 Qwen 直连（后备），见 §7.2。

## 7. LLM 后处理管线（英文 → 中文，可选层）

### 7.1 定位

- **只增列，不改写**：`zhTitle/zhSummary` 是新字段；原文标题、原始摘要、URL 原样保留。前端以中文为主行、原文灰色次行，来源徽章 + URL 常驻。
- **不阻塞**：抓取层完成后数据立即可读（英文原文形态）；enhance 是抓取后的异步第二步，完成时经 `intel://updated` 原地刷新。未配 Qwen / 调用失败 / 超时 → 跳过并记状态，UI 显示原文，无报错打扰。

### 7.2 执行方式（后端可选，默认 auto）

| 后端           | 通路                                                                                                                                                                                                                                                | 前提                               | 定位                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------- |
| `dsh`（首选）  | 小宿主插件 **qx-llm**（与 qx-websearch 同款部署：include_str! 资产落盘 + patch insert）：`export const inject = ['llm', 'webServer']`，在 webServer 挂 `POST /qx/llm/complete`，内部调 `ctx.llm.stream({provider, model, messages})` 攒成 JSON 返回 | DSH 运行中（凭证已在其设置里配好） | 复用 DSH 的模型/凭证体系（ADR-007），零新增 key |
| `qwen`（后备） | 直连现有 Qwen 通路（settings 已有 Qwen 域）                                                                                                                                                                                                         | 配了 Qwen                          | DSH 不在时的独立后备                            |

- **auto 顺序**：DSH ready → `dsh`；否则 Qwen 可用 → `qwen`；否则跳过（原文形态）。`Settings.intel.enhanceBackend: 'auto'|'dsh'|'qwen'|'off'`（M2 提供设置项，M1 写死 auto）。
- **模型选择**：`dsh-llm` 服务**没有全局主模型常量**——每次请求显式给 `{provider, model}`（enhance 层固定选 flash/turbo 级便宜模型），省略时由适配器默认；`listProviders()/listModels()` 可发现可用模型。插件内每请求 1 并发、超时 30s、失败码（`NO_ADAPTER/MISSING_CREDENTIAL/AUTH/RATE_LIMIT/QUOTA`）透传给 state.json 展示。
- **为什么不是 DSH agent 会话**：翻译/摘要是机械批处理；`ctx.llm` 正是 DSH 内部非会话消费者（会话标题生成、compaction 摘要）走的同一受支持路径，包文档明确「它是进入提供方适配器的唯一受支持路径」。
- 批处理：10 条/请求，JSON 进出；只处理 CJK 占比低的条目（中文源自动跳过）。
- 量级：AI 主题约 50–100 条/天 ≈ 每天数万 token；单主题每日只跑一次（随「当天一次」策略），手动「刷新」可重跑未完成部分。
- 预算上限：单主题单日 ≤200 条增强额度，防失控；批内失败只丢该批，重试 1 次。
- state.json 记 `enhance: {status: none|running|done|failed, backend, at}`；主题卡片可显示小标记（M2 打磨）。

### 实现期实测修订（M1 落地记录）

- **源失败重试 1 次、间隔 5s**（原定 30s——手动刷新等不起；实测 HF 偶发抖动 5s 重试即可恢复）。
- **HF / OpenRouter 解析逐条容错**：先 `text()` 再逐条 `serde_json::from_value`，单条字段反例跳过而非整体失败（HF 对个别模型返回 null 字段会让整体 serde 挂掉，已实测导致源级 ⚠ 常驻）。
- **抓取并发**：`tokio JoinSet + Semaphore(4)`，刻意不用 `futures_util` 组合子栈（`stream::iter + buffer_unordered` 触发 rustc #100013 的 `Future: Send + 'static` 推断缺陷，报 "lifetime bound not satisfied"，已实测二分定位）；叶子 async fn 一律所有权参数。
- **失败路径也要 save_state**：Models 主题整体失败时先落盘逐源错误再 return，否则 UI 常驻旧错误、本次失败被吞（已实测）。

### 7.4 Agent 编辑部流水线（M2 定稿，取代 7.1/7.2 的「增强层」定位）

产品定位升级：Agent 不是增强层，而是内容生产的核心。每天出刊的是**加工后的中文文章**，
原始条目退居「原始源」次级视图（原则不变：原文标题与来源 URL 永不丢）。

**四段流水线**（抓取完成后自动出刊，全链路进度经 `intel://digest` 事件上报）：

1. **筛选 triage**（1 次批量调用）：全部当日条目（标题+摘要+来源等级）送 Agent，
   按主题主编标准打分：重要性（影响范围×时效）、权威性（来源等级+交叉验证）、
   主题相关性。输出每条 `verdict: keep|drop` + 理由。噪音（水帖、增量微小）淘汰。
2. **取正文 bodies**（对 keep 条目，按源适配）：arXiv→abstract 页 meta；
   量子位/机器之心→HTML 正文抽取；Reddit→selftext+置顶热评（JSON API）；
   HF Papers→abstract 字段。失败退回 RSS 摘要。截断 ≤8k 字符。
3. **深加工 rewrite**（每篇 1 次调用）：主题主编提示词 → 严格 JSON
   `{title, lead, body[], tags[], importance}`——专业中文文章，术语首现保留英文，
   必须有「这意味着什么」分析段，不确定信息标「待证实」。
4. **归并 synthesis**（1 次调用）：rewrite 结果中同一事件的多篇（标题/实体相似）
   合并为一篇，`sources[]` 保留全部来源；其余保持独立。落盘
   `days/{date}/{topic}.articles.json`。

**LLM 通道（用户定稿：仅 qx-llm 桥）**：

- 配置发现：`<dsh_home>/profiles/web/cordis.patch.yml` → `llm-pi-ai.providers`
  （provider → models/apiKeyEnv/baseURL），key 从 `<dsh_home>/.credentials.yaml`
  `refs[apiKeyEnv]` 读取；协议与 baseUrl 来自千寻内置映射（提取自 DSH 的
  pi-ai catalog：zai-coding-cn=openai-completions@open.bigmodel.cn/api/coding/paas/v4、
  deepseek=openai-completions@api.deepseek.com、qwen35-local 用显式 baseURL；
  anthropic-messages 协议（kimi/minimax）M2b 接入）。
- 选型：可用 provider 中优先 flash 级（glm-5.3-flash 等），并发 2，单调用超时 120s。
- **DSH 未运行 → 明确提示**：进度状态置 `llm-unavailable`，UI 红字
  「LLM 通道不可用：DSH 未运行，请到环境页启动」，不静默降级、不白等。
- 预算：单主题单日出刊 1 次（手动重出刊覆盖当天文件）；每次出刊 token 上限护栏。

**进度可见（用户要求）**：`DigestProgress { topicId, stage, done, total, message }`，
stage = `idle|fetching|triage|bodies|rewriting|synthesis|done|failed|llm-unavailable`；
每条文章/每批完成即发事件；UI 状态弹框以时间线呈现每一步（进行中/完成/失败+原因）。

### 7.5 M2b：杂志化与流水线加固（三 Agent 联合审查定稿）

三路审查（产品 / 提示词工程 / 架构可靠性）交叉验证的结论：流水线的组织层已达标，
但**内容产出正确性有结构性 bug**（归并与筛选实际不生效），且产品形态缺「杂志骨架」。
本节取代 §7.4 中与之冲突的描述。

#### 7.5.1 流水线正确性修复（阶段 0）

1. **thinking 预算**：GLM 系是思考模型，思考 token 计入 max_tokens。payload 按
   provider 加 `"thinking": {"type": "disabled"}`（zai/bigmodel 参数）；同时检查响应
   `finish_reason`，content 为空或 `length` 截断 → 重试 1 次。**不修则出刊成功率 <50%。**
2. **triage 分批 + 短序号**：条目按 ≤50 条/批分批调用（max_tokens 8192）；提示词内用
   短序号（0-99）代替 64 字符 sha2 id（模型抄错长 id = 条目静默消失）；输出压缩为
   `{序号, score(1-5), reason(≤12字)}`；代码映射回真实 id。**覆盖率护栏**：输出条数
   < 输入条数时记日志，缺失条目显式按 drop 处理（当前实现尾部条目静默消失）。
3. **triage rubric 量化**：重要性 1-5 给行为锚点（5=头部实验室旗舰发布/顶会焦点论文；
   4=一线厂商发布、知名开源大版本；3=有数据、可复现或方法有新意；2=增量改进；
   1=汇总帖/转载/梗）；keep 总量约束「≤15，宁缺毋滥」。**importance 从 rewrite 移到
   triage 全局评分**（30 篇各自独立打分无相对性），Rust 把 score 注入 Article。
4. **synthesis 改分组决策**：不再要求模型重写全部正文（30 篇 ≈ 15-20k 输出 ≫ 8192
   → 必截断 → 归并从未生效）。只输出合并组：`[{"members":["…"],"headline":"…"}]`，
   独立文章不出现；Rust 聚合组员 `sources[]` 并集，merge id = 组内 itemId 排序后的
   确定性哈希（重出刊 id 稳定，收藏星标不失联）；合并篇正文取组内 importance 最高者。
5. **LLM 调用重试**：抓取层有重试，LLM 层没有。complete 包一层重试（1 次、5s，
   针对 429/5xx/超时/空 content）；rewrite 单篇 JSON 解析失败重试 1 次（附「只输出
   JSON」提示）。
6. **extract_json 三级解析**：整段 parse → ``` 围栏 → 平衡扫描（首个完整值），
   替换现在的首尾扫描（说明文字含示例 JSON 时误伤）。
7. **防重入竞态**：DigestRuntime 加同步 `running` 集合，spawn_digest 在同步临界区
   完成「检查 + 置位」（当前检查与首次写入之间有调度窗口，双击可双跑烧双倍 token）。
8. **杂项**：`article_from_json` 参数化 topic_id（当前硬编码 "ai"）；body 空时回退
   [lead] 再判失败；`started_at` 保留首次值；模型分层——triage/synthesis 用 flash，
   **rewrite 用 provider 里的非 flash 主模型**（文风与分析是产品核心，成本仍可忽略），
   并发 2 → 3。
9. **提示词整体替换**（骨架见审查报告，落 `prompts.rs`）：rewrite 加事实纪律
   （数字/型号/日期只出自原料）、归因降噪（宣称挂来源、营销形容词转中性事实陈述、
   社区反馈单独标注）、结构模板（标题≤28字/lead/事实段/影响段）、few-shot 文风锚；
   归并输入加每篇导语。

#### 7.5.2 杂志骨架（阶段 1）

1. **头版要览**：情报入口第一屏 = 今日要览区（头条大卡 = 全 Feed 主题中 importance
   最高一篇；要目 = 其余 top 4-6 一行一条；每主题一行速览），统计卡退居其下。
   数据 = 各 Feed 主题当日 articles 聚合。
2. **出版节律**：startup 尾部 spawn 日期哨兵（每小时比对本地日期），跨天 → 重跑
   抓取 + 出刊。**同日中断续跑**：startup 扫 Feed 主题——当天 feed 文件存在且
   articles 缺失 → 补 spawn_digest（出刊中断后重启不再停留「未出刊」）。
3. **出刊幂等（修「刷新=重出刊」）**：spawn_digest 加 force 参数——自动触发
   force=false（当天已出刊则跳过），`intel_digest_start` 显式路径 force=true（覆盖）。
4. **冷启动回退**：当天未出刊时 `intel_articles` 返回最近一期（date 字段 = 实际期日，
   恢复 `list_article_days`），文章流顶部标「{date} 刊」徽章。
5. **配额与头条层级**：MAX_REWRITE 30 → 15；文章流第一条（importance 最高）用
   头条大卡（标题大字 + 导语全显），其余紧凑卡。

### 7.6 M3：从榜单到杂志（2026-10-03 定稿）

产品定位再校准（用户定稿）：情报页的目的是**焦点新闻、一手资料、掌握天下时事**，
内容必须实实在在。由此：

1. **「模型」主题重构为「模型评测」新闻主题**：模型榜单表格（HF Hub 三排序 +
   OpenRouter 归并的 155 家族雷达）移除——榜单是「列表」不是「新闻」。主题改为
   Feed 流，源（均实测可达，RSS 2.0 走通用适配器）：
   - `hf-blog`：`huggingface.co/blog/feed.xml`（官方一手：模型发布、评测、研究）
   - `the-decoder`：`the-decoder.com/feed/`（LLM 评测/能力边界报道）
2. **新增「科技」主题**：`solidot`（奇客，中文科技）+ `hn`（hnrss ≥200 分热帖，
   高信噪比筛选）。BBC 中文/联合早报/36kr/LMSYS/VentureBeat 实测不可达，不收录
   （源准入制：先探活，死源不进注册表——jiqizhixin 先例）。
3. **榜单代码全量移除**：TopicKind/ModelsView/merge.rs/ModelEntry/ArenaSlot/
   Provenance/HfModels|OpenRouter 适配器全部删除（不留守尸代码）；`kind` 字段
   从主题模型中消失——所有主题都是杂志流。旧 days/*/models.json 与模型收藏自然
   失效（serde 容忍，收藏列表过滤空快照）。
4. **主编注册表按主题分化**（prompts.rs）：`ai` / `model-news` / `tech` 三份主编
   词 + 分主题评分锚点（模型评测：权威评测报告/榜单可信度/能力边界为高分；
   科技：安全事件/基础设施/行业格局为高分）。triage/归并指令由硬编码 AI 主编
   改为按 topic 注入。
5. **triage 全覆盖指令修正**（真实出刊实测发现：flash 只对 ~30% 条目给出评分，
   其余被护栏静默丢弃）：指令明确「对全部 N 条逐条输出评分（含低分，低分会被
   丢弃），不得跳过序号」；覆盖率护栏保留为金丝雀。
6. **RSS 源新鲜度过滤**：适配器丢弃发布超过 14 天的条目（HF blog 全量 feed 含
   长历史，旧文会污染当日原料）。

主题矩阵（M3）：AI（5 源）· 模型评测（2 源）· 科技（2 源），全部走同一编辑部
流水线（筛选→取正文→深加工→归并→文章流→要览头版）。

#### 7.6.1 篇幅与质量修订（2026-10-03 用户反馈）

实测首轮出刊（三主题 44 篇）后用户反馈：文章「太短、只是总结、不是用心写的文章」。
根因与修订：

- **篇幅约束过紧**：旧指令 500-900 字 + body 2-4 段 → 产物必然是摘要体。
  修订：**总 1200-2000 字、body 4-8 段**，明确「这不是摘要改写：先完整消化原料，
  重组为读者不需要看原文的报道」。
- **五段式结构**：背景段（来龙去脉）→ 事实段（规格/数据/时间线，可要点化）→
  分析段（意味着什么、与格局对比）→ 影响段（对读者的具体影响与行动建议）→
  反应段（官方/社区/业界，逐条归因）。缺料可合并段落，不得虚构。
- **输出预算**：rewrite max_tokens 2048 → 4096（2000 字中文 + JSON 包裹）。
- **原料加量**：BODY_LIMIT 8000 → 12000 字符（原料密度决定长文的事实密度）。
- **配额换质量**：MAX_REWRITE 15 → 12（每主题；质量优先于篇数）。

## 8. 数据保存 / 历史 / 收藏

### 8.1 保存

- 按天按主题一文件：`days/2026-10-02/ai.json`。读视图 = 读文件，零计算；模型归并在抓取后预计算写入。
- 写入一律 `atomic::write`（临时文件 + rename），进程被杀不产生半截文件。
- 每主题每日条数上限：Feed 100 / 模型家族 200。同 id 重复抓到只更新热度（first_seen_at 不变）。
- 原始层不落盘：merged/provenance 已含出处，需要排查时手动刷新看日志。

### 8.2 历史

- 主题视图顶部日期导航：`‹ 前一天 · 10-02 · 后一天 ›` + 「回到今天」。`intel_days {topicId}` 返回有数据的日期列表（空日期置灰）。
- 保留 90 天，启动时清理过期目录（文本量级 ~150KB/天，90 天 ≈ 13MB）。
- 保留期内历史是**只读快照**：当时的热度/排名/中文摘要不随刷新变化——回看「那天发生了什么」语义正确。

### 8.3 收藏

- `favorites.json`：收藏时**深拷贝条目**（FeedItem 或 ModelEntry + topicId + savedAt，含 zh 字段当时的值），不引用天文件 → 历史清理、格式演进都不影响收藏。
- 入口视图固定一张「收藏」卡（伪主题，kind: Favorites），列表按收藏日期分组，每条带原主题徽章 + 取消收藏。
- 模型收藏即「关注」：详情抽屉「收藏」，后续可做新变体/相关新闻提醒（M3）。

## 12. 风险与对策

| 风险                          | 对策                                                                                    |
| ----------------------------- | --------------------------------------------------------------------------------------- |
| LLM 输出错译/幻觉             | 只增列不改写，原文常驻可对照；提示词约束「不新增事实」；额度上限                        |
| LLM 成本/失控                 | 每主题每日 ≤200 条额度 + 批处理 + flash 级模型；无 key 直接跳过                         |
| 热榜接口易碎                  | parseVersion + 逐源健康度 + 降级出内容                                                  |
| OpenRouter 性能覆盖不全       | 「—」诚实呈现，不猜值                                                                   |
| HF trending 混入量化/微调仓库 | 血缘归并 + 噪声门槛                                                                     |
| 跨天不关机导致无当日数据      | 主题视图「今日未抓」横幅一键补抓                                                        |
| 半截文件/强杀                 | atomic::write + state.json 重入                                                         |
| 合规                          | 只存标题/摘要/链接/公开榜单元数据；正文不转存；点击跳原站；主题可整体不做（注册表删行） |

## 13. 已定决策记录

- 单侧边项「情报」，主题卡片入口；模型 / AI / 热点为首批主题。
- 启动当天一次抓取 + 按主题手动刷新；无定时器。
- 不做代理设置（系统已有代理）。
- 历史保留 90 天；收藏为快照复制，独立于历史生命周期。
- 英文源处理：LLM 只做中文增列（zhTitle/zhSummary），原文标题/摘要/URL 永久保留；后端 auto = DSH llm 服务（qx-llm 插件桥，复用其凭证与模型目录，请求级指定 provider+model）→ Qwen 直连 → 跳过；不用 DSH agent 会话。
- DSH llm 服务事实（已核实 dsh-llm 0.2.0-rc.2 README）：`ctx.llm.stream({provider, model, messages})` 流式调用；无全局主模型常量，模型按请求选择；agent loop / 会话标题 / compaction 摘要等内部消费者都走此服务；失败码 NO_ADAPTER / MISSING_CREDENTIAL / AUTH / RATE_LIMIT / QUOTA。
