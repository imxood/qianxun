## 0. 一句话产品定义

**部署在你自己云服务器上的单二进制「个人远程访问网关」**——被信任的手机经 TLS
反代进入你所有 PC 上的 DSH 工作台，全程不经过任何第三方；**控制台是这个私有
信任域的观测与治理中枢**：谁在线、谁配对、谁登录、流量如何分级、出事如何止血。

现状诊断（v0.2 控制台）：底层能力（治理/审计/轮换/会话/多用户）已就位，但出口
只有「两个只读 tab + 发码」——典型的**能力先行、暴露缺失**。三个结构性风险：

1. **安全能力无 UI 等于不存在**：用户感知不到 fail-closed 与流量分级的价值；
2. **10s 轮询 + 平铺两 tab 撑不住 5 台以上实例**；
3. **手机丢失（本产品最高频安全事件）没有一键止血入口**。

| Persona | 画像 | 核心诉求 | 付费信号 |
| --- | --- | --- | --- |

## 2. 信息架构

组织原则：**观测 → 资产 → 信任动作 → 系统** 分层；给每个埋在 CLI/回环里的
能力一个显式出口。三面边界（同一功能不三处重复实现）：

- `/console` = **服务器级唯一权威管理面**（本文档主体）
- 千寻桌面端远程页 = 本机视角（docs/19 §12.3 已定）
- `/qx-pair` `/qx-fleet` = 手机数据面轻入口（只做入口，不做治理）

```
/console
├── 仪表盘   默认落地页：在线实例/活跃设备/流量形态/被限流/最近事件
├── 实例     资产页：在线状态(last seen 相对时间)/版本/连接时长/标签
│            └── 详情：token 轮换（确认弹窗+新 token 分发指引）/治理明细
├── 设备     服务器级凭据：配对时间/最后活跃/来源 IP/吊销（≠删除）
│            └── 丢失模式：一键吊销全部设备（带二次确认）
├── 配对     发码独立流程页：二维码+文字码+有效期/兑换状态/发码历史
├── 审计     login.*/pair.*/device.*/instance.* 时间线 + 过滤 + 详情抽屉 + CSV 导出
├── 治理     interactive/page/bulk 按实例×类曲线 + 桶水位 + 降级序白话说明
├── 会话     活跃登录会话列表 + 强制下线（防公用电脑忘退出）
└── 设置     版本/healthz/配对限速参数/备份迁移指引/危险区
```

竞品对标（每个模块的形态参照）：

- **Tailscale**：last seen 相对时间 + 过期徽标（实例列表）；Keys 一等公民页（token 轮换/吊销做成显式按钮）
- **frps dashboard**：四宫格最小仪表盘（别贪多）；社区面板的教训——**只读无粘性，能操作（轮换/吊销/发码）才有**
- **Cloudflare Zero Trust**：事件流结论性标记（连续 fail≥5 高亮、同设备换 IP）；一次性凭证三属性显式展示（1 次 · 5 分钟 · 全实例）
- **NetBird**：setup key 的「已用 n/m」状态展示；基础审计留开源、合规导出收费的功能分层
- **RustDesk Server**（反面教材）：开源版几乎无控制台——证明审计/设备 UI 是刚需

## 3. 设计系统（Design Tokens）

来源：ui-ux-pro-max `--design-system`（查询 "self-hosted infrastructure admin console
dark secure"，density 8 / motion 3）→ Real-Time/Operations 模式，暗色 + 状态绿。
克制取用：Glassmorphism 只用于**顶栏与弹层**（backdrop-blur ≤12px），主体是
1px 描边的扁平面板——运维工具要的是信息密度与可扫读，不是玻璃炫技。

### 3.1 色彩（暗色唯一模式——深夜运维场景）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#0B0F17` | 页面底 |
| `--surface` | `#111826` | 卡片 |
| `--surface-2` | `#1B2336` | 表头/悬浮层 |
| `--border` | `#263043` | 1px 描边 |
| `--border-strong` | `#475569` | 强调描边（弹层/输入聚焦） |
| `--fg` | `#F8FAFC` | 主文本 |
| `--fg-muted` | `#94A3B8` | 次文本（对 `--bg` 对比 ≥4.5:1） |
| `--accent` | `#22C55E` | **状态绿即品牌色**：在线/主行动——「远程可达」是产品核心价值 |
| `--accent-fg` | `#0B0F17` | 主行动上的文字 |
| `--info` | `#3B82F6` | 链接/中性动作 |
| `--warn` | `#F59E0B` | 降级/受限/过期倒计时 |
| `--danger` | `#EF4444` | 离线/破坏性操作 |

状态点语义（全站唯一真相）：`online #22C55E`（2s 呼吸，reduced-motion 时静态）/
`degraded #F59E0B` / `offline #64748B` / `revoked #EF4444`（文字加删除线）。

### 3.2 字体与数字

- 正文 `system-ui` 栈（**自托管可离线**——不拉 Google Fonts，这是部署约束不是妥协）
- 等宽 `ui-monospace`：配对码/ID/token/IP/版本号——"码"的语义暗示 + 运维可读性
- 数字一律 `font-variant-numeric: tabular-nums`（表格列对齐是运维工具的尊严）
- 尺寸 `12/13/14/16/20/24/30`，行高 1.5，字重 `400/500/600`

### 3.3 密度、圆角、动效

- 密度 8/10（紧凑）：间距 `4/8/12/16/20/24/32`；卡片内边距 16；表格行高 40
- 圆角：控件 8 / 卡片 12 / 胶囊 999
- 阴影只给悬浮层（`0 8px 24px rgba(0,0,0,.45)`）；平面层级用 1px 描边表达
- 动效 3/10（几乎静默）：弹层 160ms `cubic-bezier(.2,.8,.3,1)`；页面切换无动画；
  `prefers-reduced-motion: reduce` 全部关停

### 3.4 数据实时性（Real-Time 模式硬规则）

> 一律「相对时间 + 自动刷新指示」；轮询失败显示 stale（黄点 + 上次成功时间），
> **绝不静默假装新鲜**。

- 顶栏 liveness 徽章：`● live · 3s`（轮询中）/ `● 更新于 42s 前`（stale）
- M1 用 3s 轮询起步；基建允许时切 SSE（数据面 SSE 已验证，`fleet.changed` 帧已定义）

### 3.5 可访问性基线

- 对比度：正文 ≥4.5:1；大字/图标 ≥3:1（`#94A3B8` on `#0B0F17` = 7.1:1 ✓）
- 焦点：`outline: 2px solid currentColor; outline-offset: 2px`（WCAG 2.2 AAA 取向）
- 所有图标按钮带 `aria-label`；SVG 图标（Lucide 风格），**禁止 emoji 当图标**
- 表格危险操作行内按钮 + 确认弹层（不用 `confirm()` 原生框）
- 触控目标 ≥44×44px（移动端管理场景成立）

## 4. 页面规格（对照 `docs/assets/console-preview.html`）

### 4.1 登录页 `/login`

- 品牌行（渐变 logo + 「千寻中继」）+ 标题 + 副题「管理你的设备、实例与访问策略」
- 错误行：内联红条 `role="alert"`，文案带**剩余尝试次数**（"用户名或密码不正确（剩余 4 次尝试）"）——让锁定策略可预期
- 底部锁定提示锁图标 + 「连续 5 次失败将锁定 15 分钟 · 密码由服务器 CLI 重置」——诚实告知找回路径
- 页脚：手机配对入口（手机没有账号，从这进配对流）
- 状态：空/输入中/提交中（按钮 loading）/错误（红条）/锁定（429 → 显示剩余时间）

### 4.2 控制台外壳

- 左侧 216px 侧栏：品牌 + 五导航（仪表盘/实例/设备/审计/治理）+ 底部版本与域名
- 导航态：hover 变色，当前项 `inset 2px 0 0 var(--accent)` 左指示条
- ≤900px：侧栏转顶栏横滚（手机上管理成为可能）
- 顶栏 liveness 徽章固定于每页 pagehead 右侧

### 4.3 仪表盘（默认页）

四宫格 KPI + 双栏（流量形态 / 最近事件）：

1. **在线实例** `2 / 3` + 副行「书房主机 · 笔记本在线；实验室离线 26 分钟」
2. **活跃设备（1h）** + 副行列出设备名
3. **中转流量（24h）** + 副行「interactive 61% · page 30% · bulk 9%」（流量形态即产品故事）
4. **被限流请求（24h）** + 副行「全部为 bulk 降级，interactive 0 次」（差异化能力的每日兑现）

流量形态：24h 每小时双色堆叠柱（绿=interactive，蓝=page/bulk）；最近事件卡
（4 条 + 「查看全部审计 →」）。

### 4.4 实例

表格列：实例（状态点 + 名称 + mono 的 `pc-xxxx · 主机名`）｜版本（千寻 + DSH）
｜连接（在线时长 + 重连次数）｜流量(1h)｜治理状态 tag（正常/bulk 受限/离线）｜详情。

- **last seen 相对时间**（Tailscale 式）：离线行整体降透明度但仍可读——"离线"是状态不是错误
- 详情抽屉：token 轮换按钮（危险确认弹层：轮换后旧 token 心跳被拒，需重新导入
  千寻；**新 token 只显示一次** + 复制 + 分发指引）、该实例治理明细
- 空状态：「预置实例后，在对应 PC 的千寻『远程 → 服务器』区块填入 ID 与凭据即可上线」

### 4.5 设备（含配对弹层）

表格列：设备（状态点 + 名称 + mono 的 `dev-xxxx · iPhone · Safari`）｜配对时间｜
最后活跃｜来源 IP｜操作。

- **吊销 ≠ 删除**：主按钮「吊销」（红描边，即时断开全部会话）；已吊销行显示
  删除线 + 「彻底移除」次级操作——语义分层对齐心理模型
- **丢失模式**（P0）：页头红色按钮「丢失模式——吊销全部设备」+ 输入
  `LOST MODE` 确认（不可逆动作要求强摩擦）
- 配对弹层（新增设备）：**真二维码**（148px，`fill #0F1115` on 白底）+ 24px 大
  letter-spacing 配对码 + 链接文字 + 有效性倒计时（`04:37` 橙色）+ 说明文案
  「5 分钟内一次性有效；兑换成功后该设备获得独立凭据，可随时在此吊销」+
  **兑换成功实时提示**（配对完成的瞬间弹层内变绿——闭环反馈）

### 4.6 审计

时间线行：`时间(mono) | 事件徽章(配色) | 描述（含 mono 的 IP/用户名/设备名）`。

- 徽章：`pair.ok` 绿 / `login.fail` 红 / `instance` 蓝 / `device.enter` 蓝
- **结论性标记**（CF 式）：连续 fail ≥3 的行尾加「（连续失败已达 3/5，触发速率告警）」
- 过滤：事件类型下拉 + 时间范围；操作：导出 CSV（合规钩子）
- 详情抽屉：detail_json 原文（mono 折叠块）——运维可深挖

### 4.7 治理

- 分类水位卡：interactive / page / bulk 并发 / 带宽每实例 / 带宽全局——横条
  meter（绿→橙渐进），数值 `n / m`（mono）
- 降级序卡（**白话文案是功能**）：`1 bulk → 503 + Retry-After（最先让路）`
  `2 page → 令牌桶排队 ≤1s，超时 503` `3 interactive → 永不主动断开（SSE/WS 会话优先）`
  + 「压力解除自动恢复，无需人工干预」
- 24h 表：实例 × {interactive 放行, page 放行, bulk 放行, 被限流(橙), 字节}

### 4.8 手机侧页面（保持轻）

- `/qx-pair`：现有暗色卡片可用，M2 换新 token 皮 + 自动大写输入 + 码分组显示
- `/qx-fleet`：实例卡 + 在线角标（`fleet.changed` 推送已预留）；**不做治理功能**
- **命名冲突修正（最便宜的修复）**：console「设备」=授权手机，而 qx-fleet 现在
  的标题是「我的设备」=主机实例——同一个词两页指两种实体。qx-fleet 改
  **「我的主机」**；console 设备页的「服务器级设备」从 13px 灰字提为页描述位

### 4.9 四态完备性（每页的硬性清单）

| 页面 | 空 | 加载 | 错误 | 成功 |
| --- | --- | --- | --- | --- |
| /login | ✓ | 按钮 loading+禁用+全字段 Enter | inline 红条 + `role=alert` + **区分凭证错/服务错/限流**（限流显示剩余时间） | 跳转 + return URL |
| 仪表盘 | — | 骨架 KPI | 横幅+数据降可信 | ✓ |
| 实例 | 空态带 CTA（「预置实例」是行话——改为引导文案+文档链接） | 骨架行 | 横幅 | ✓ |
| 设备 | **全站最佳空态**（「还没有设备——点新增设备生成配对码」可作模板） | 骨架行 | 删除失败 toast 含原因 | 删除成功 toast（含撤销） |
| 配对面板 | — | — | — | **状态机：待使用(倒计时)→已使用(显示设备名,自动收起)→已过期(一键重生成)** |

### 4.10 危险操作模式（全站规范）

- 吊销/删除：**推荐「直接执行 + 5 秒撤销 toast」**（比确认弹窗更快且可逆）；
  不可逆操作（丢失模式/彻底移除）才用主题化弹窗：对象信息（设备名/最后在线/
  **是否正在会话中**）+ 后果文案 + 红色主操作 + 焦点圈定 + Esc + 焦点返回触发元素
- 退出登录无需确认（现状正确）
- 语义预留：红 = 不可逆，中性 = 可逆
- **绝对禁用原生 `confirm()`**

### 4.11 实时性反馈纪律

- 全站「更新于 Ns 前」微标签 + 手动刷新按钮（带旋转反馈）
- 轮询失败必须可见：顶部横幅「连接中断，正在重试」+ 数据整体降可信——
  **断连（控制台自己的问题）与离线（实例的问题）是两种语义、两种视觉**
- 状态翻转 toast（「实例 A 已离线」）；读屏 `aria-live` 仅通告变化防刷屏
- Page Visibility：页面不可见暂停轮询，回前台立即刷一次；只轮询当前 tab
  （现状是两个列表不管 tab 都全量轮询）

### 4.12 交互 P0 清单（合并双评审，12 条）

1. **配对码跨设备传递**：大二维码（≥200px 含静区，编码完整 pairUrl——已带
   code 预填）+ 4-4-4 分组码 + 复制按钮 → 二维码是唯一零输入通道
2. **配对码状态闭环**：待使用→已使用→已过期的状态机（§4.9）→ 管理者对 A 流有终点
3. **轮询静默失败**：新鲜度指示 + 失败横幅 → 陈旧绿点伪装在线是**排障反向误导**
4. **离线只有灰点**：加「最后在线：x 分钟前」+ 卡片可点详情 → 排障第一问
5. **删除 confirm()**：改直接删+5 秒撤销（§4.10）
6. **操作静默成功/失败**：全站 toast（成功含撤销、失败含原因）
7. **排障零工具**：实例详情页（最后在线+事件流：上下线/配对/会话/shed/反代错误）
8. **配对输入移动端**：inputmode+自动聚焦+粘贴识别+错误分「码错/过期」
9. **【bug 级】手机 401 踢错地方**：qx-fleet 的 401/无 token 一律回 /qx-pair
   并提示「访问已过期，请重新配对」——**绝不送 /login**（错误心智模型，诱发
   手机上试管理员密码）。当前实现（本日门面修改引入）正是这个错误，列立即修复
10. **主色文字对比**：链接/强调 #2563eb（实测 3.4–3.7:1 ✗）→ #3B82F6（4.7:1+），
    按钮白字蓝底不动——改一个 token 全站修复
11. **离线态实现方式**：弃 `opacity:.45`（文字对比塌到 ≈2.2:1 ✗✗）→ 降饱和配色
    + 「离线」badge + **保留可点**（禁点连"为什么进不去"都不可探索）
12. **移动端关键时刻**：触控 ≥44px、删除收「⋯」菜单、safe-area、键盘避让 →
    「手机丢了紧急吊销」是唯一必须移动完成的管理操作

## 5. 移动端与响应式

- 断点：375 / 768 / 1024 / 1440；≤900px 侧栏转横滚顶栏（5 导航正好可转底部

## 6. 安全与可运维设计

> 总体判断（SRE 视角）：基础认证原语扎实（argon2id、常数时间比较、token 只存
> 哈希、双键限流、哑校验、JSON-only 挡 CSRF、回环 /metrics、HostAssert），自托管
> 单二进制产品中上水平。差距集中在三层：**①生命周期治理缺环**（2FA、会话
> 可视化/踢出、设备 re-auth、配对审批）；**②可观测性有数据无出口**（audit/metrics
> 都落库但无 UI 无通知）；**③信任模型未诚实呈现**（服务器是明文中间人——架构性）。

### 6.1 管理面差距（对照 Tailscale/CF）

| 级 | 项 | 要点 |
| --- | --- | --- |
| P0 | **2FA(TOTP)** | console 是唯一治理入口，单因子失陷=整个数据面失陷；单用户 TOTP 成本低，与"随机密码只打印一次"心智一致 |
| P0 | **会话设备列表+主动踢** | 现状只能改密全踢；需会话页（创建/最近活跃/IP/UA+单会话吊销）——泄露后唯一外科手术式响应 |
| P1 | 密码找回 | **做文档化 CLI 重置**（reset-password 已存在=吊销全部旧会话），登录页写明；明确**不做在线找回**（无邮件基础设施下那是新开的账号接管链） |
| P1 | 登录通知 | 通用出站 webhook（Bark/TG/邮件网关），触发点：login.ok、**pair.submit_ok（新长期凭据诞生，比登录更值得通知）**、pair.locked、instance.offline |
| P1 | IP allowlist | 双层：文档给「console 前置 CF Access/wireguard/openresty allow-deny」配方；服务端 CIDR allowlist 仅作用管理面、默认关闭 |
| P1 | 配对审批（opt-in，默认即时） | 48bit+5min+限流已让暴力不可行；剩余风险是码被肩窥——兑换进 `pair.pending` 待批态，console 展示来源 IP/UA 批准/拒绝 |
| P2 | 会话时长可配置 / WebAuthn | 滑动 7d/绝对 30d 做成配置即可 |

**源码级发现（P1 修）**：`client_ip` 无条件信任 X-Forwarded-For——当前安全仅因
默认 bind 回环；若部署者 `--bind 0.0.0.0` 即可伪造 XFF 绕过全部 IP 键限流。
修法：文档红线「只监听回环」+ 服务端仅信任回环对端的 XFF（或改 unix socket）。

### 6.2 数据面：把"PC 文件读取"从 180 天免认证里分层收回来

现状=一枚 cookie 180 天零持有者验证、无绑定可跨设备重放（Tailscale 是 180d
过期后**强制重认证**，千寻只有"过期"没有"再验证"）。分层：

- **L1（P0）** 设备 cookie 有效期 180d → **30d**（档位可配置）——零新增攻击面、暴露窗口砍 6 倍
- **L2（P0）** 设备列表+一键吊销 UI（能力已有，纯暴露）——**"手机丢了"止损必须 ≤2 次点击**
- **L3（P1）** 敏感操作 step-up re-auth：日常浏览免认证，敏感集（超阈值下载/批量打包/跳出授权根）触发重验
- **L4（P1）** 设备指纹软绑定：token 关联指纹哈希，不匹配不硬拒（防蜂窝/Wi-Fi 误报），降级只读+告警+重配对恢复；只存哈希
- **L5/L6（P2）** 空闲超时 / 每设备授权范围（只读/根目录白名单）

### 6.3 可观测性：审计=表、指标=图、日志不进 UI

- **审计页**：14 类事件零入口→时间线+筛选（时间/事件/主体/结果/IP/文本）；
  **两个聚合视图比列表更有用**：按设备时间线（嵌设备页）、按 IP 失败计数+
  一键 denylist（联动 allowlist）。红线：UI 只读不提供删改
- **仪表盘**：4 卡片（在线实例/活跃设备/活跃 console 会话（联动踢出）/今日
  shed 率按类分列）+ 趋势图（流量 bytes 三类堆叠、登录成败双线、实例
  RTT/重连/带宽桶利用率）——**shed 率与带宽利用率是治理调优唯一依据，没有
  趋势图等于盲调**。数据走内部只读 API，不把 per-instance 细节经公网暴露
- **告警（服务端定时判定，不依赖浏览器开着）**：磁盘水位 >80/90%（**P0**——
  WAL 写不进=服务假死+审计断档，小 VPS 最现实的"无声死亡"）；实例离线 >5min、
  登录/配对失败暴增、证书到期 30/14/7 天（P1，复用通知通道）；设备兑换 IP
  异地（P2，弱信号）

### 6.4 运维手册化判据

> 高频+点击响应 → 进 UI；低频+需 shell → 留文档；升级/恢复这类"UI 自己也死了"
> 的**永不进 UI**。

备份 qx.db（文档：`VACUUM INTO`+cron+停服替换恢复+"备份含 token 哈希按密文
介质保存"；UI 只做"上次备份时间"徽章 48h 变黄 P2）｜升级手册（写明断 wss、
实例 30-60s 全量自动恢复）｜证书（服务端每日握手探测告警——能发现"文件续了
但 openresty 没 reload"）｜磁盘应急手册（95% 清理顺序：归档审计→清中转缓存
→**绝不动 qx.db 主文件**）｜**部署安全检查清单文档（P0，一切运维项的根）**。

### 6.5 信任模型：中转明文性的诚实呈现

事实链：手机 —TLS→ openresty —明文(回环)→ qx-server ←wss— PC。**qx-server
进程对全部应用层流量可见明文，TLS 只保两跳不保端到端**——这是 frp/CF Tunnel
的"可信中转"模型，不是 Tailscale 的 WireGuard E2E 模型；服务器失陷=流量泄露。

- **安全模型文档页（P0）**：三节点图，服务器节点标注"可见明文"+与竞品定位
  差异——信任声明必须先于用户放入敏感流量
- **产品内披露（P1）**：console 首登横幅+配对成功页一句话「流量经服务器中转，
  服务器可解密；勿传输不愿让运营者看到的敏感内容」（自托管运营者=自己也
  要看到，防分享部署的认知惯性）
- **数据处理透明清单（P1）**：审计记了什么/日志不记 body/库与备份含哪些哈希
- **服务器即信任根加固（P0）**：明文性当前架构无法消除，唯一现实缓解=守好
  服务器（盘加密/仅密钥登录/自动安全更新/专用 VPS 隔离）
- **E2E 演进（P2，明确当前不做）**：设备↔PC 应用层端到端加密（配对时交换
  公钥、服务器只见密文）——写成"长期方向"并解释原因，避免过度承诺反噬信任

## 7. 版本路线图（12 个月）

> 版本号：M2 = v1.2（2026.11–12）｜M3 = v2.0（2027.01–04）｜M4 = v3.x（2027.05–10）。
> 三句版本观：**M2「同步与知情」**（配置跟着人走、异常找得到人）；**M3「手机
> 第一」**（从"能用浏览器"到"像个 App"）；**M4「底座变现」**（个人基础设施 →
> 小团队工具端平台）。

### 7.1 M2（v1.2）「同步与知情」

范围纪律：不碰协议角色、不碰前端构建链、不做多用户。

1. **配置同步引擎**（sync.rs：CAS+LWW+config_history 每版留档；config.* 帧；
   namespace 白名单**服务端强制拒收**）——qianxun.settings（凭证/instanceToken
   明细过滤）/qianxun.mobileui/plugins.pinned
2. 桌面端同步钩子（settings::update 防抖推送、启动拉齐、changed 实时应用——
   走同一 settings 事务路径防同进程写竞态）
3. console「同步」面板（namespace/key/版本/写入者 + history diff + 一键回滚）
4. **通知 v1**：notify_outbox + dispatcher（退避重试）+ 通用 webhook
   （HMAC-SHA256 签名防重放；企业微信/飞书/钉钉机器人本质都是 webhook——
   一个实现=N 个通道）；默认只开 3 事件：device.paired、instance.offline
   （60s 判死）、login.fail 连发 ≥5
5. console「通知」面板 +「审计」面板（§6.3 的形态）
6. 治理收口：token 轮换入口、登出全部会话；**设备撤销/改名收敛到 console
   单一执法点，桌面副本改只读+深链**
7. HTML 资产外置（零构建：rust-embed 拆文件，共享 base.css；/qx-pair 保持零依赖）
8. 升级前自动 SQLite 快照（VACUUM INTO 留 3 份）+ admin backup/restore

验收：两台千寻改一端 ≤3s 收敛；抓包验证凭证不出现在同步流；拔网线 60s 收到
webhook。**不做**：PWA/device 角色/多用户/邮件/构建链。

### 7.2 M3（v2.0）「手机第一」

1. **前端构建链**：web/（Vite + Svelte 5 plain + TS）静态产物 rust-embed 进
   二进制；cargo xtask 构建即校验嵌入哈希，CI 查 dist 新鲜度
2. **device 角色单连接**（docs/19 §4.5）：/qx-ws role=device，fleet 推送 +
   反向 yamux 子流；治理键扩展实例×设备
3. **PWA 壳**：manifest + service worker（壳与舰队离线缓存；**DSH 会话页
   network-only + 离线兜底页**——防"离线旧页假在线"）+ Web Push（VAPID）
4. 舰队增强：实例详情/重命名与标签/会话页内切换设备免回首页
5. 通知全通道：Telegram bot + **Bark**（iOS 兜底，对冲 iOS PWA 推送限制）
6. **per-instance grants**（多租户半步）：设备×实例可见性矩阵——"把一台机器
   给同事/家人用"的 90% 团队需求到此为止
7. 证书到期探测（14/3/1 天，本地握手探测——能发现"续了但没 reload"）+
   升级助手（sha256 校验→替换→重启，一键）

验收：手机装主屏后飞行模式可开舰队壳；TG/Bark 60s 内收到 device.paired；
grants 收紧后该设备只见授权实例。**不做**：组织/邮件/信箱（仅 spike）/E2E。

### 7.3 M4（v3.x）「底座变现」

上半段（无需新身份体系）：API 令牌（devices.kind=api + scope 白名单）；agent
信箱（手机留言→桌面离线暂存→上线投递→回执+Web Push——「手机给关机的 PC 留
任务、开机自动回执」是本版的叙事时刻）；私有插件通道（索引缓存+签名校验）；
流量时序面板（metrics_hourly）。

下半段（**全部需求门控，没有真实信号就不做，做了默认 flag 关**）：组织与角色
（owner/operator/viewer；门控写死：连续 2 个月 ≥2 真实活跃 console 用户才立项）；
同步 E2E 加密（namespace 级密钥配对时随 token 下发，服务端只见密文）；产物分发。

### 7.4 关键决策（已定）

1. **UI 栈两步走**：M2 零构建资产外置（拿回可评审性，文件结构即未来组件边界）
   → M3 Vite+Svelte 5（plain，不用 Kit；与桌面端同栈复用心智是单人维护者的
   决定性优势）。**/qx-pair 与配对引导永久无构建零 JS 依赖**（bootloader 纪律：
   构建链坏了不能阻断重新配对）
2. **通知通道优先级**：webhook → Telegram/Bark → Email 最后且自带 relay
   （不做内置发件——自托管 SMTP 是投递率黑洞）
3. **多租户**：grants（M3）→ org（M4 下半段，门控+flag 关）。明确不做
   billing/跨 server 联邦/SSO/公开注册——**>5 人需求 = 一人一套 server，这是
   定位不是缺陷**

### 7.5 桌面端 × 云端 × 手机分工三原则

**谁拥有数据谁编辑；执法点唯一（撤销/轮换/grants 只在 server）；只读副本必须
协议帧驱动（pair.granted/fleet.changed），不轮询。** 反模式清单：桌面不再保留
撤销按钮（M2 起收敛深链）；console 不做冲突合并 UI（只做历史回滚）；手机 fleet
不做实例重命名。

### 7.6 风险与砍序预案

- M2：settings 写放大/同进程回写竞态 → 唯一写者事务 + per-key 单飞 +
  baseVersion 重试上限 3 次降级 conflict；config_history 无界 → 每 key 50 版
  裁剪；敏感字段上推 → 白名单服务端强制 + **过滤器单测门禁 + 抓包验收**
- M3：构建链破坏单二进制纪律 → xtask 校验嵌入哈希 + CI dist 新鲜度；iOS
  PWA 限制 → Bark 兜底；**砍序预设**：信箱 spike 不达标进 M4，标签分组可降级
  为仅重命名，双通道先 TG 后 Bark
- M4：org authz 渗透热路径 → grants→影子双写比对→切换 三步走 + flag 关闭
  零差异回归门禁；新攻击面（API token/插件通道）→ scope 最小权限 + 全过审计
- 跨版本：升级路径断裂 → 升级前自动快照 + schema N-1 兼容窗口；**每版本末
  复盘本文档 §7 表格，门控项可砍，主线（同步/PWA/通知）不可滑出所在里程碑**

### 7.7 排期原则

验收先行（动工前先写集成测试或抓包验收）；30% 缓冲（M2 滑期则 M3 舰队增强
让位——PWA 是不可滑主线）；每版本一个可叙事时刻：M2=两台千寻 3 秒收敛，
M3=手机主屏图标离线可开，M4=手机给关机的 PC 留任务、开机自动回执。
