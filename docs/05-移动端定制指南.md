# 千寻移动端定制指南（方案 A · 网关定制层）

> 借鉴 [dsh-mobile](https://github.com/saya-ch/dsh-mobile) 的「文件即 UI」思路：
> 手机端界面与能力来自电脑上的普通文件，**保存即生效**，不改 DSH 源码、不改千寻壳。
> 本文档同时是人与 agent 的操作契约——想用对话定制时（`/qx 把手机端改成…`），
> 把本文件连同「当前文件状态」一起交给 agent 即可。

## 1. 目录与文件

定制目录固定为千寻管理的 DSH home 下的 `mobile-access/`：

- 路径：`<DSH_HOME>/mobile-access/`（千寻隔离模式下即
  `%APPDATA%/qianxun/dsh-home/mobile-access/`，以设置页/日志中显示的 DSH home 为准）
- `custom.css` —— 手机端样式覆盖（可选，缺失时无样式注入）
- `custom.js` —— 手机端脚本（可选，缺失时无脚本注入）
- 网关启动时自动创建目录；删除文件即恢复默认，**不要放占位空文件**

所有改动只允许发生在这个目录里，绝不修改 DSH、千寻源码或其他位置。

## 2. 生效机制

1. 网关（axum）反代 DSH 时，对 `GET 200 text/html` 的页面在 `</head>` 前注入：
   `<link rel="stylesheet" href="/qx-mobile/custom.css" />` +
   `<script src="/qx-mobile/bootstrap.js" defer>`（见 `remote/gateway.rs` 的
   `inject_mobile_layer`，不满足条件原样透传，绝不阻断页面）。
2. `bootstrap.js`（内嵌在千寻里）每 5 秒（页面隐藏时 30 秒）轮询
   `/qx-mobile/version`，比较 css/js 的 sha256 短摘要；
3. 摘要变化 → 样式换带版本参数的 URL（浏览器按 URL 长缓存）；
   脚本先挂新容器执行、成功后卸旧容器（失败保留旧版并 `console.error`）。
4. 电脑离线时静默重试，不影响 DSH 页面本体。

服务端路由（全部要求已配对）：

| 路由                      | 作用                                                                   |
| ------------------------- | ---------------------------------------------------------------------- |
| `/qx-mobile/info`         | `{app,version,hostname,dshReady}`，App 端命名连接与在线探测（带 CORS） |
| `/qx-mobile/version`      | `{v,css,js}` 内容摘要，热刷新依据                                      |
| `/qx-mobile/bootstrap.js` | 定制层引导脚本                                                         |
| `/qx-mobile/custom.css`   | 定制样式（≤512KB，ETag/304）                                           |
| `/qx-mobile/custom.js`    | 定制脚本（≤1MB，ETag/304）                                             |

## 3. 脚本契约：`window.qxMobile`

```js
window.qxMobile.register(({ root }) => {
  // root：挂在 body 上的容器。定制 UI 一律放进 root，
  // 不要直接改 DSH 的节点结构（升级易碎，且热替换无法回滚）。
  const chip = document.createElement('div');
  chip.textContent = '我的定制';
  root.appendChild(chip);

  return () => {
    // 清理函数：热替换/卸载时被调用。
    // 必须撤销自己加的定时器、监听器、observer 和 DOM。
    chip.remove();
  };
});
```

规则：

- 只 `register` 一次（重复 register 会叠挂多个实例）；热替换由网关的版本机制驱动。
- 需要等 DSH 界面渲染后再增强时，在 mount 内用 `MutationObserver` / 轮询等待目标节点。
- 脚本在 `defer` 时机执行（DOM 已解析，DSH app 可能尚未挂载完）。
- 保存前先做语法检查：`node --check custom.js`。
- 超限（css 512KB / js 1MB）会被网关以 413 拒绝。

## 4. 「恢复默认」

删除 `custom.css` 与 `custom.js` 两个文件即可（无需创建占位文件），
手机端数秒内回到内置外观。

## 5. 安全约束

- `custom.js` 在**手机页面**里运行，能访问 DSH 页面的 DOM 与网络（经网关、带配对
  cookie）——不要写入来路不明的代码；
- 电脑端能力（读文件/执行命令）**尚无**扩展机制；未来 `/qx-mobile/*` 下按能力
  逐个开通并走同一配对鉴权，切勿为了求快把任意命令执行挂上网关；
- 配对令牌等同电脑控制权：定制目录、配对链接都不要分享。

## 6. 示例

见 `mobile/examples/custom.css` 与 `mobile/examples/custom.js`（回顶部按钮 +
触屏基础规则）。复制进 `mobile-access/` 改名即可生效。

## 7. 对话定制（`/qx <需求>`）操作法

1. 读取本文件 + 当前 `mobile-access/` 目录状态（存在哪些文件、内容概要），
   一并注入 DSH 对话或作为千寻 AI 功能的上下文；
2. agent 直接改目录内文件；
3. 手机端数秒内自动生效——无需重启任何东西。
