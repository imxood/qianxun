# 需求追踪

> 每个需求一份 md，编号 R001, R002...；通过「影响范围 / 关联需求 / 决策点」字段

### 字段说明

| 字段           | 作用                                           |
| -------------- | ---------------------------------------------- |
| 状态           | 跟踪进度，与 README 索引联动                   |
| 一句话         | AI 与人快速理解需求本质                        |
| 背景与验证记录 | 假设先验证、证据先存档，防止拍脑袋设计         |
| 决策点         | D1... 逐条记录结论与确认日期，评审与回溯的锚点 |
| 影响范围       | 用户视角 + 代码结构双遍历                      |
| 规范 / 约束    | 实施前必读、实施时避坑                         |
| 验收场景       | 每条可独立验证，含门禁（all:check 等）         |

## 添加新需求

1. 复制上文模板骨架
2. 编号递增：`R002_xxx.md`...
3. 填写影响范围（角色 / 功能域 / 关联文档）；涉及行为假设先验证后动笔
4. 在本 README「按状态」对应分区加链接
5. 决策点（D1...）随确认逐条回填
