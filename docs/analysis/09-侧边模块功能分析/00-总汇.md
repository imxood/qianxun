## 1. 全局结论：五个跨模块的系统性问题

### 1.1 「测试全绿 ≠ 功能能跑」——接线层是缺陷重灾区

这是本次分析**最重要的发现**，且在三个独立模块得到互证：

| 模块          | 测试状态                | 实际缺陷位置                                                                                                                                  |
| ------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **游戏**      | 131 用例全绿            | 全部 131 条**都在纯函数层**。`machine.ts` 的 9 状态机单测完备，**却从未被 UI 调用**。6 条 P1 全在未被测试的接线层                             |
| **文件**      | 81 前端 + 167 Rust 全绿 | `scanner.svelte.ts`(202 行) **是死代码**——其逻辑在 `DiskScan.svelte:130-233` 另写了一份，模块只被自己的测试导入。「单测通过」在磁盘域完全失效 |
| **笔记/远程** | 261 前端 + 25 Rust 全绿 | **0 个前端用例覆盖 notes 或 remote**（已逐一核对文件名）。数据丢失与半开连接问题在测试盲区                                                    |

**共性根因**：测试贴着「好测的纯函数」写，而缺陷产生在「对象与函数的接线处」。建议引入接线层冒烟测试（见 §3-S1）。

### 1.2 IPC 合同门禁覆盖不完整

`contract.test.ts` 的**命令级**门禁很严（Rust ↔ TS 双向比对 + `generate_handler!` 覆盖），但**字段级**门禁只覆盖 14 个类型：

| 状态          | 类型                                                     | 所属模块                           |
| ------------- | -------------------------------------------------------- | ---------------------------------- |
| ✅ 已覆盖     | `IntelTopicStatus` `FeedItem` `Article` `DigestProgress` | 情报                               |
| ✅ 已覆盖     | `SearchOpen` `FilesPage` `GrepPage` `GrepHit` 等 10 个   | 文件                               |
| ❌ **未覆盖** | `Settings` `SettingsPatch`                               | **设置**（全应用最核心类型）       |
| ❌ **未覆盖** | `MarketInstalled` `SyncItemResult`                       | 插件                               |
| ❌ **未覆盖** | `TopicDay`                                               | 情报（`items: null` 空态语义载体） |
| ❌ **未覆盖** | 整个 **Disk 域**                                         | 文件                               |

### 1.5 侧栏外壳本身的设计取舍（值得肯定）

`SideNav.svelte` 整体质量高，几处决策有明确理由且写在注释里：

- **48px 纯图标窄栏**：比文字纵排窄 16px，位置感由左缘指示条 + 图标同色承担（`:88-91`）
- **settings 沉底**：`mt-auto` + 分隔线与工具项分组，栏内层级一眼可辨（`:121-123`）
- **keep-alive 用 `visibility` 而非 `display:none`**：注释记录了实测数据——`display:none` 的 iframe 完全隔离渲染栈，合成器一归零成本十帧；`visibility:hidden` 只合成不绘制（`App.svelte` `show()` 注释）。**这是有实测支撑的决策，不是猜测**
- **分离窗口 spawn 成功才让位**，失败保持原状（`SideNav.svelte:68-75`）

**外壳的 3 个缺陷**：

| 级别 | 问题                                                                                           | 位置                                      |
| ---- | ---------------------------------------------------------------------------------------------- | ----------------------------------------- |
| P2   | **无键盘导航**：纯 `<button>` 列表，未实现方向键/数字键跳转                                    | `SideNav.svelte:92-119`                   |
| P2   | **`nav.detached` 是布尔而非计数**：重复分离后关闭其中一个，主窗会**重新挂载一个活 DSH iframe** | `stores/nav.svelte.ts:16,34`              |
| P3   | **截屏域（shots）有 10 个 IPC 命令但侧栏零入口**——只能靠全局热键唤起，功能不可发现             | `contract.ts` shots_* vs `SideNav.svelte` |

### 2.3 低分梯队（68-70）：需要立即修 P0/P1

**游戏 70** — 3 个 P0 全在这里：

1. **切关卡永久黑屏**：`MarioLab.svelte:108` 置 `level=null` 注释写「触发 `$effect` 重建背板」，但全组件仅 2 处 `$effect`（ResizeObserver + onMount），**没有任何一处会重建它**。1-1→1-2 后画面冻结在旧帧，HUD 却显示 `WORLD 1-2`
2. **熔断器无恢复路径**：`machine.ts:127` 注释承诺「探活成功由宿主调 reset」，但探活定时器只更新 `layaOk/qwenOk`，**从不调 `breaker.ok()`**。连续失败 3 次后只能重启应用，UI 的「探活恢复自启」是错误承诺
3. **`brain.ask()` 无超时**：sidecar 半死会让 `inFlight` 永为 true，锁死整局

**文件 68** — 1 个 P1 功能失效：

1. **grep `busy` 永不复位**：点「停止」或清空输入框后，UI 永久卡「扫描中 + 停止按钮」。`finally` 的两条复位分支都不命中。**现有 `cancelGrep` 用例只断言 `++grepSeq`，没断言 busy 复位**，所以漏网
2. **「上下文 0–10」是视觉空操作**：参数真实通到后端并填进 `GrepHit.contextBefore/contextAfter`，但**全前端零处渲染**——而 `docs/01:35` 已把它标为交付能力
3. **`scanner.svelte.ts` 是死代码**（见 §1.1）
