## 1. 模块定位与设计意图

### 1.1 三签结构与「保活」设计

`SearchPage.svelte:8-17` 定义三签（`files` 找文件 / `grep` 搜内容 / `disk` 磁盘扫描），切签只切换 `invisible` class，三个子页**同时挂载、结果与扫描进度全程不丢**（`SearchPage.svelte:43-51`）。这与 `src/App.svelte` 的 keep-alive 容器（`README.md:27`）是两层独立的保活策略：本页内部又保了一层活。

设计后果（必须计入缺陷评估）：**子页永不卸载** ⇒ 组件卸载后的回调清理风险在本模块基本不成立（`DiskScan` 的 `onMount` 只清了 30s 心跳，`DiskScan.svelte:356-378`），代价是三个页面的 `$derived` 链在切签后**依然全量参与响应式计算**（`invisible` 不等于 `display:none` 之外的停止计算，Svelte 5 无可见性门控）。

## 3. 实现分析

### 3.1 架构与数据流

```
用户输入
  ├─ FilesPage → debounce 80ms → search_files(Rust 同步, 索引内存)
  │     └→ store.filesResult → FilesPage.$effect → accumulated（可续页累加）→ 排序/过滤 → 渲染
  └─ GrepPage → debounce 200ms → search_content(Rust spawn_blocking 循环)
        ├→ Channel<GrepProgress> 每片 ≤100 条 → grep-merge(按 path|line|col 去重) → 即时渲染
        └→ await GrepPage 终值 → 与通道累计取并集 → 覆盖结果 + aborted/nextFileOffset

DiskScan → disk_scan_stream(Rust spawn_blocking → fff rayon walk)
        └→ Channel<DiskScanEvent> ~100ms/帧
             ├→ progress: liveGrow 合并 topChildren 进 trail 末项（边扫边长）
             └→ done:     整组替换 trail 末项（部分结果 / 跳过数 / TOP 大文件）
```

三处「代际防竞态」是本模块最扎实的设计：

| 机制                       | 位置                                      | 覆盖                                                                                      |
| -------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| `generation`（根目录世代） | `mod.rs:32,76-78`                         | 前后端双向：`search.svelte.ts:138,233,247` 丢弃旧结果；`commands.rs:615-618` 后端主动终止 |
| `grepSeq`（内容搜索代际）  | `search.svelte.ts:68, 196, 232, 246, 293` | 分片 + 终值双通道作废                                                                     |
| `seq` ticket（磁盘扫描）   | `DiskScan.svelte:179, 241, 263, 334, 344` | 换目标 / 回退面包屑都让在途帧失效                                                         |

**唯独文件名搜索没有代际守卫**（`runFiles` 只比 `generation`，见 D-3），是三处机制里唯一的缺口。

后端 `search_content` 的锁策略值得肯定：读锁**不跨分片持有**（`commands.rs:512-595` 注释明确），换根与状态轮询不会被长搜索拖住；glob 正则入口一次编译、闭包内零分配复用（`commands.rs:479-484`，注释记录了此前最坏 2000 次 `Regex::new` 的旧问题）。

**问题**：

- `search.svelte.ts:101-105`（盘符枚举）、`:110-113`（轮询）、`:173-175`（续页）三处 `catch {}` 静默。前两处有注释说明「不阻断 UI」且属可接受降级；第三处（`searchMoreFiles`）会让续页失败与「没有更多」**在 UI 上完全无法区分**（D-6）。

### 7.4 复核方式建议

D-1 / D-2 / D-4 三条最值得动手复核，可在 `pnpm dev` 起后用最短路径确认：

- **D-1**：切「搜内容」签 → 输入任意词 → 点「停止」→ 观察「停止」按钮与 spinner 是否永久停留（换任意非空查询才恢复）。
- **D-2**：切「搜内容」签 → 搜一个多次出现的词 → 把「上下文」从 1 改成 5 → 观察命中行上下是否出现额外行（预期：无变化）。
- **D-4**：切「找文件」签 → 搜一个宽泛词（命中 > 200）→ 点「加载更多」→ 对比列表实际出现的类型与顶部 chips 的计数/是否缺失。
