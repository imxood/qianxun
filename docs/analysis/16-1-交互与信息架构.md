# 16-1 · 交互与信息架构:聊天窗主导的马里奥实验室(设计稿)

> 对象:`MarioLab.svelte`(1746 行实读)/ `FloatingPanel.svelte` / docs/15 §3.2、§5、§6.2、§9b。
> 需求原话:"每一轮失败……类似聊天的窗口,进行 qwen 的分析、优化过程、结论,同时显示运行状态与必要数据,其他页面简化或取消。"
> 文案宪法:标签 ≤6 字 / 消息 ≤30 字 / 说明 ≤2 句。

## 0. 设计立场

1. **聊天列 = 叙事流,不是仪表盘**。每局的"故事"(何时死、Qwen 怎么析、提了什么、判了什么)进聊天;高频遥测留在画布 HUD;汇总数字压成一行常驻条。
2. **事实已归档,聊天只做索引**。runs/<runId>.json 已逐局全量留存(§9b),聊天消息只承载结论与锚点(runId 角标),不重复搬运原始数据。
3. **延续既有决策**:决策拍不进日志(docs/15 §5.6)→ 同样不进聊天;硬门 = 分析没出结果不开下一局(§6.2)→ 等待期在聊天里可视化,而非只靠按钮转圈。

## 1. 聊天窗消息模型

### 1.1 消息类型清单

| # | 类型 | actor | 时机(现有代码锚点) | 内容 | 紧凑度 |
|---|------|-------|---------------------|------|--------|
| M1 | 局开始 | 系统 | start() 成功(L561) | 局号 · 模式 · 试用补丁(若有) | 单行 |
| M2 | 死亡 | 规则 | death 事件(L455) | 第 n 死 · 死因@列 · 进度% | 单行+徽标 |
| M3 | 通关 | 规则 | win 事件(L471) | 通关 +bonus · attempts | 单行+徽标 |
| M4 | 终局卡 | 规则 | genPostmortem(L573) | 结果/最远列/死亡分布/用时;折叠内嵌复盘全文 | 卡片 |
| M5 | 分析占位气泡 | 系统 | 逐任务入跑(L794) | "第 k 死 · 分析中…Ns / 排队中" | 气泡(10Hz 耗时) |
| M6 | 分析结论卡 | Qwen | analyze ok(L857) | 诊断要点 ≤2 句 + insight;元数据耗时/手册增量/经验+1;折叠收发明细锚点 | 卡片 |
| M5f | 分析失败条 | 系统 | 重试超限(L916) | 失败 · 原因短语 · 已弃析 | 单行(警示色) |
| M7 | 提案卡 | Qwen | propose(L946) | patch 字段 from→to;单步挂起带「装填 ▸」;pause 态标"暂停中" | 卡片+操作 |
| M8 | 判定卡 | 规则 | commit/rollback/restore(L618/674/702) | 转正或回滚 · 得分对比 · `↩ 来自#n 提案` 回链 | 卡片 |
| M9 | 经验沉淀 | Qwen | insight 写入(L874) | `✦ 经验+1:<一句>` | 单行 |
| M10 | 熔断/不可达 | 系统 | breaker 三连败 / qwenOk=false | 状态 + 自愈提示 | 单行警示 |
| M11 | 硬门提示 | 系统 | 用户点被禁用的开始(L518) | `分析没跑完,稍候` | 单行(仅点击才出现) |

要点:
- **actor 三分**:系统=调度与环境(开始/队列/熔断/硬门);规则=引擎与判定器(死亡/通关/终局/判定);Qwen=分析与提案(结论/提案/经验)。
- **M5 气泡原地变身**:每死恰好一个占位气泡,终态变为 M6 结论卡或 M5f 失败条——"每死一张卡",不追加不重复(呼应幂等键成功后占位,R6)。
- **判定卡挂试用局块末尾**:提案在 #n 局、判定在 #n+1 局末(M8 由 genPostmortem 试用判定路径产生),卡上回链 `↩ 来自#n 提案`,跨局因果不断线。

### 1.2 组织:连续时间线 + 局分隔符(推荐)

- **不采用"一局一个会话块"**:试用→判定差一局、冷却 5 局、回归守卫跨局,硬切会话块会割裂因果链,也无法承载迭代级叙事(漏斗、经验沉淀)。
- 采用**单条连续时间线,局为折叠单元**:每局以分隔符行开头(`#6 · 自驾 · 通关 · 78列`),点击折叠/展开该局全部消息。
- **折叠策略**:历史局默认折叠为分隔符摘要行,仅当前局展开;用户可点开任意局回看。聊天不随局数增长而失焦(现 `log` 每局清空 L531,聊天则跨局保留——这是与日志的本质差异)。
- 重启后聊天流不持久化:从 runs/index.jsonl 最近 5 局 + evolution.jsonl 审计行重建"分隔符+末局详情"骨架,不新增落盘格式。

### 1.3 硬门等待期的呈现

- 局终局卡(M4)之后,逐个出现 M5 等待气泡:排队态(`◌ 第2死 排队中`)/运行态(`◌ 第1死 分析中… 8.2s`,耗时 10Hz 刷新)。
- 常驻条队列字段同步 `队列 1/2 · 上次 8.2s`;开始/重开按钮保持禁用+转圈(现 L1108-1131 语义不变)。
- 用户点被禁按钮 → 插入 M11 一条(点才说,不刷屏);队列排空 → 气泡全部变身,自然出现下一局 M1,两局块之间的"硬门期"即时间线上的等待区,无需专门"门"消息。

## 2. 运行状态与数据的嵌入方式

### 2.1 三层分发

| 层 | 承载 | 刷新 |
|----|------|------|
| 画布 HUD(canvas+DOM 覆盖,L1231) | score/coins/time/门控徽标/IN 动作 | 10Hz 实时 |
| 聊天常驻条(聊天列顶部一行) | 局# · 模式 · 队列 k/n · 胜率 · 最远列 · 冷却 · evolve 三态 | 事件驱动 + 1s |
| 消息内数据卡(M2/M4/M6/M7/M8) | 死亡/终局/结论/提案/判定 | 事件一次性沉淀,不可变 |

### 2.2 取舍原则(防聊天仪表盘化)

1. **每秒都在变的数字不进聊天**:决策拍、qps、latency、conf 只活在 HUD 与遥测徽标;聊天无任何 10Hz 字段(等待气泡耗时是唯一例外,且是临时态)。
2. **一次性事件才可入聊天**:死亡、终局、分析、提案、判定,每件一条、事后不可变——聊天是事实记录,不是实时面板。
3. **卡片只带"读得懂故事"的字段**:死亡卡=死因/列/进度,不带载荷;全量明细走 runs/<runId>.json 角标跳转查看器,聊天只引用。
4. **常驻条 ≤7 字段**:超出即砍。判据:需要换行才能摆下的数据不属于常驻条。
5. **存在性检查**:删一条消息用户不损失任何决策依据 → 它不该存在;删一个常驻字段用户不会误判局势 → 它不属于常驻条。
6. **实时项仅两处**:常驻条队列深度/在途键(事件驱动)、M5 等待气泡耗时(10Hz);胜率/最远列为局末沉淀值,局中不中途刷新(避免"半局胜率"假数据)。

## 3. 页面简化与裁剪

### 3.1 逐项判决

| 现有 | 判决 | 去向 |
|------|------|------|
| 进化浮窗(统计4格/漏斗/队列/经验/手册/时间线) | **拆解** | 统计→常驻条;队列→M5 气泡;经验→M9;时间线→聊天即时间线;手册→`/手册` 抽屉 |
| Laya 决策浮窗+内嵌日志流("调试"窗) | **日志删,调试窗留(默认关)** | game→M2/M3;evolve→M6-M10;error→M5f/M10;决策拍本就不进日志;概率条/统计/输入 JSON 60fps 密度不适合聊天,保留 FloatingPanel 供调试 |
| 复盘浮窗(Markdown) | **并入** | M4 终局卡折叠区 = 复盘全文,等宽小字 |
| 参数设置浮窗(速度/间隔/门控) | **保留** | 入口移工具条 ⚙,即时生效语义不变 |
| 顶栏(模式/开始/暂停/重开/探活点) | **压缩** | 并入底部最小工具条;探活点保留在顶栏 |
| HUD 覆盖层 + 3px 进度条(死亡刻度) | **保留** | 实时遥测唯一出口,空间成本≈0 |
| 52px 双行遥测条(L1673) | **删除** | 决策摘要已在 HUD 徽标;统计行并入聊天常驻条 |
| 三态开关(自动/单步/暂停) | **迁移** | 聊天头部 evolve 徽标下拉;单步放行 = M7 卡上「装填 ▸」(替代原"下一步"按钮 L1581) |
| 重置策略 | **迁移** | 输入 `/重置` 二次确认;审计 actor:user 保留;低频兜底不占常驻位 |
