# docs/analysis/15-4 · 架构健全性评审(Agent 4 号)

> 评审对象:docs/13/14/15(§6 v3 草案)+ evolution.ts / driver.ts / MarioLab.svelte / e2e/mario-loop.ts 实现现状。
> 视角:自进化系统**整体架构健全性**,不评单点功能。

## 结论摘要

1. 主干健全:三层职责(确定性引擎→反射驾驶→慢思进化)与"LLM 负责创意、代码负责纪律"在代码里真实成立(evolution.ts 纯函数核心,judgeCandidate 测量裁决,Qwen 异步不阻塞)。
2. 最大架构债:**两套隐式闭环状态机已分叉**——UI(单局判定、无基线人工处置,MarioLab genPostmortem/adopt/discard)vs e2e(K 局中位、无基线直接转正,mario-loop)。v3 再加分析队列,若各写第三份,行为一致性无法靠评审保证;必须抽显式状态机/调度器纯逻辑模块,两宿主复用。
3. 快慢脑边界靠解析器白名单即可硬隔离,不靠模型自觉;v3 载荷变厚不改变边界,但需补 4 条 schema 硬化规则(防 Qwen 输出逐拍指令)。
4. 进化/运行正交性现状可接受(异步 fetch + 局内快照 + attempt 守卫);v3 新增两个缝隙:载荷组装在 rAF 主线程、队列任务若引用活对象——用"不可变快照 + 局间串行"关掉。
5. 长期治理四处欠账:insights 2400 字在"每死必析+insight 必填"下数小时滚动一轮,早期结论被冲掉;evolution.jsonl 无轮转;runId 依赖墙钟(回拨+跨进程可撞);parseAuditLines 只认 v=1,v3 升级会静默丢审计行。
6. 可移植性:纪律层(evolution.ts 几乎全部)天然领域无关,应抽 `lib/evolution-core` + DomainAdapter;马里奥专用件留 adapter 侧——这是"沉淀 Laya 跨领域经验"终极目的的落地形态。

## 快慢脑边界与输出 schema 硬化

**风险**:v3 把全轨迹+逐拍收发明细喂给 Qwen(§6.3),上下文充满逐拍细节,会诱导"慢脑抢快脑的活"——输出"tick 1231 应该 jump"式指令,或把 policy_patch 当实时控制用。

**已有防线(已核实)**:解析层 `extractJson`+`parseRefine` 只认顶层三键(playbook/policy_patch/insight),多余输出天然被丢;`sanitizePolicy` 值域硬钳制;`limitPatch`/冷却/≤3 字段在代码侧;沙箱字段全部是**局级静态标量**,无时间维度。隔离已是结构性的,不依赖 prompt。

**硬化规则(v3 落地前补进 qwen.ts,并写入设计)**:

1. **顶层键白名单 + 越权可观测**:解析到未知顶层键(如 `actions`/`per_tick`)→ 丢弃并记 issue 进审计。静默丢弃会让越权尝试不可见,失去学习信号。
2. **静态性声明**:policy_patch 新增字段必须过"字段声明表"(类型:静态标量/布尔/注册枚举;值域;钳制);任何含 tick/时间/条件分支语义的字段直接拒绝——把沙箱边界从惯例升级为 schema。
3. **death_diagnosis 单向流**:diagnosis 只允许进"分析载荷⑥+审计";代码依赖方向上 driver/brain 不得 import 它,用依赖图保证诊断永不回控制路径。
4. **提示词只做软声明**:system prompt 写明"你是局间策略优化者,不是逐拍玩家";注明边界由解析器保证,不由模型自觉。载荷③ 明细块加用途前缀"归因素材,不得产出逐拍指令"。

## 领域无关内核抽取边界(lib/evolution-core)

终极目的核对:要沉淀的是 **Laya 跨领域使用经验**,马里奥只是第一试验场(docs/14 §0)。

**领域无关、进 core**(现 evolution.ts 基本零改动可抽):diffPatch/limitPatch/applyCooldowns/startCooldowns/judgeCandidate/median/evalMedian;触发器协议(shouldInvokeQwen 泛化,deathKey→unitKey);EvoState 簿记;AuditEntry+只追加审计;appendInsight 滚动+人保段;v3 变体注册表**框架**(键→枚举+默认+sanitize,内容由领域注册);AnalysisScheduler;policy 信封版本化+迁移钩子。

**马里奥专用、留 adapter**:engine/world1-1/planner/renderer;driver 物理护栏(跳跃弧/veto/stall 是平台物理);brain.encodeState 观测件(profile16/threats);postmortem 指标语义(thrash/churn);死亡签名(死因@地标)。

```ts
// core 不 import 任何游戏模块,只认注入的 adapter
interface DomainAdapter<P, R> {
  policySchema: FieldSpec[]; // 字段/值域/钳制/静态性声明(硬化规则②)

  digestOf(r: R): string;

```

下一领域(打砖块)= 新 adapter + 复用 core 全部纪律。insights.md 建议加 `domain:` 标签:跨域结论(观测件边际收益、延迟与门控配合)可跨域检索,域内战术不混。抽取时机:不阻塞 v3,但 v3 新代码(队列/触发清单/counters)必须按 core 兼容写(纯函数、零 mario import),避免二次迁移。
