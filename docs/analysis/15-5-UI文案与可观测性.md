## 结论摘要

1. 文案最大病灶:一行塞双括号解释、内部文档号/端口/文件名泄漏到玩家层、中英混排枚举。最严重 20 处见下表。

3. "学到了什么"靠 evo 面板重排:一行状态 + 4 数字格(带 Δ)+ 补丁漏斗 + 分模式胜率 + 最近 3 条经验,ASCII 见下。
4. docs/15 §5 FloatingPanel 清单够用,补 4 点:z 序计数器与 Esc 顶层语义、<900px 单窗退化、persistKey 命名规范、键盘可达。
5. 全自动后留三级干预:自动/单步/暂停 + 一键回默认;时间线只读,actor 用 Q/⚙ 符号。
6. §2 统计字段 5 处 UI 缺口:emptyInsight、队列深度、地标 Top5、bestScore 语义、Δ 口径。

## 日志分级设计

### 先决:决策流出日志
`driver.onDecision` 的每拍日志删除,最新一拍只活在 HUD 门控徽标(docs/15 §1)与 laya 面板 probs 里;ESCALATE/stale 类异常拍进 evolve 档但同因 5s 限频。否则任何分级都挡不住 250ms 刷屏。

### 三档定义

| 档 | 色 | 收什么 | 行例(≤30 字) |
|---|---|---|---|
| game | slate | 开始/暂停/模式切换/死亡/通关/重生/复盘生成 | `✝ 第2死 掉坑@69`、`▶ 开始 · 自驾` |
| evolve | violet | Qwen 触发与跳过原因/完成/提案/装填/判定/冷却/经验+1 | `✦ 提案2项 gateExecute`、`✦ 转正 1042(+6%)` |
| error | red | laya/qwen 不可达、分析失败、存储失败、策略损坏回退 | `✕ Qwen 失败 http500` |

- 过滤 chip:`全部 / 玩法 / 进化 / 异常`,默认全部;**error 恒显**(任何档位下都不被过滤掉)。
- 行模板:`HH:MM:SS {icon} {text}`,icon 固定单字符(▶⏸✝⚑ / ✦ / ✕),沿用现有 cls 着色,新增 `level` 字段替代裸 tailwind class。
- 总量上限 40 不变;死亡级分析 v3 一局可产生 3+ 条 evolve 行,同 deathKey 合并为一条。

### reason → 短语映射(evolution.ts 返回值,UI 侧查表)
`already-analyzed`→`已析过`;`no-signal`→`无信号`;`plateau`→`平台期N局`;`death(sig)`→`死亡:sig`;`death-repeat(sig)`→`重复死亡:sig`;`win`→`通关沉淀`。映射函数放 evolution.ts 纯函数,可测。

## FloatingPanel 补充规格

docs/15 §5 props(title/testid/width/initial/persistKey/onclose)与拖拽/折叠/置顶行为**够用**,补 4 点:

1. **z 序与焦点**:模块级 `zTop`(起 100),点击已开窗或新开窗时 `z=++zTop`;`activePanel` 单值记录最顶层;Esc 只关 active 窗,再按关下一窗(现 L266 的 panel=null 语义平移)。非模态:`aria-modal=false`,不设焦点陷阱;关闭后焦点回触发按钮(记录 opener)。触发按钮带 `aria-expanded`。
2. **小视口退化**(<900px 宽或 stage <480px 高):`openPanels` 退化为最多 1 项,新开自动替换旧窗;宽 `min(96vw, width)`;初始位底部居中;拖拽保留,clamp 视口已有。
3. **persistKey 规范**:`qx.mario.panel.<id>`,id ∈ laya/settings/pm/evo/stats/queue,全小写点分层;值单 JSON `{v:1,x,y,folded}`;读写 try/catch(隐私模式静默,现 persist* 同款);布局语义变更时递 `v` 丢弃旧值;面板键禁存业务数据。
4. **无障碍**:标题栏聚焦时 ←→↑↓ 移动 ±16px 并写回 persistKey(键盘拖拽替代);Enter 折叠;拖拽用 Pointer Events + `setPointerCapture` + `touch-action:none`;正文 text-muted 对比度实施时实测 ≥4.5:1;数字 font-mono tabular 防跳动。

## 全自动化透明度

去掉三按钮后,干预收拢为**三态开关**(evo 面板头 + 顶栏色点):

| 态 | 行为 | 文案 |
|---|---|---|
| 自动(默认) | 提案→自动装填→自动判定→冷却,全程无人 | `自动` |
| 单步 | 局后分析照跑,提案生成后挂起,不装填;点「下一步 ▸」放行 | `单步` |
| 暂停 | 不装填不判定;在途试用局跑完照判;分析照跑仅计数 | `暂停·挂起n` |

- 单步的定位:围观学习模式——每轮停在"提案已生成",用户看完时间线再放行,理解系统每步学到什么。
- 兜底干预:`重置策略` 按钮(回 default,审计 actor:user / action:rollback / reason:`人工重置`)。
- 时间线只读行模板(≤30 字,actor 符号 Q=qwen、⚙=system):
  - `#12 Q 析死#2 掉坑@69 → 提案1`
  - `#12 ⚙ 试用#r17 → 转正 1042(+6%)`
  - `#11 ⚙ 回滚 gapWindow · 冷却至16局`
  - `#10 Q 维持:胜率持平`(emptyInsight 在此可见)
- 死亡级 v3 一局 3 死 = 3 行,时间线 cap 20,更早折叠进「更早」。
