# docs/analysis/15-2 · 进化质量与元学习闭环有效性分析

> 评审人:设计评审 Agent 2号。对象:docs/15 §6(死亡级分析 v3 设计稿,未实施)。
> 基线:docs/13 评估纪律、docs/14 v1 现状;证据:实读 `evolution.ts` / `qwen.ts` /
> `postmortem.ts` / `policy.ts` / `e2e/mario-loop.ts` / `MarioLab.svelte`。
> 准则:自我进化系统必须**不断进化**——不仅"每次都分析",更要可归因、可收敛、可度量、可回退。

## 结论摘要

1. v3 解决了"看得到"(全量轨迹 + Laya 收发明细),没解决"归因得了":诊断在 death 级产生、补丁在 run 级评估、判定只消费 K 局中位分一个标量。一次转正可能同时"治好"3 个死,也可能只是噪声——"哪个设计变更治好了哪个死"在 v3 中无法回答。
2. **实读发现实现级缺口**:docs/15 §6.4 称"limitPatch 原样适用",但 `limitPatch`(evolution.ts L308-323)的变更收集只认 number / boolean / Window;5 个消息设计枚举字段(string)不进 `changed` 集合 → **静默丢弃、无 issue**,随后 `diffPatch` 判为无差异。§6.6 的文件映射只改 policy.ts 枚举校验,没提 limitPatch 枚举分支——不改则 §6.4 整个消息设计沙箱是死代码。
3. 防震荡只有字段级冷却;冷却期内 Qwen 可换字段继续治同一死法。且 `death-repeat` 只对比相邻局(`lastDeathSignature` 单值,L192),A-B-A 交替死亡不标注。
4. insight 必填若无"可证伪"格式约束,只会逼出"维持(第N次)"式废话计数器;insights.md 只按字数 FIFO、无证伪出清、无命中率,经验库会膨胀为不可信先验。
5. 评估带宽:v3 候选产出频率约 ×3,吞吐不变(每迭代 1 候选 × K=3 局);且候选单槽 `pending`(mario-loop.ts L270)——一局 3 死 = 3 次提案互相覆盖,前序补丁丢失、结果依赖分析完成顺序,不可复现。
6. 进化度量缺北极星与退化报警;champion 单点分数、一次测量代表整个生命周期,没有 checkpoint 可回退。
7. 总判断:v3 方向正确,但**元学习闭环**(账本/签名升级/insight 证伪/版本回退)必须与 §6 同期落地;否则只是"更高频率的观测",不是"更快的进化"。

## 强化设计

### D1 变更-效果账本(信用分配地基)

每个候选自带假设声明;评估后按死亡签名结算效果:

```ts
type ChangeLedgerRow = {
  changeId: string;            // 'c-{iter}'
  vid: number;                 // 基于 champion 版本号(见 D6)
  fields: Record<string, { from: unknown; to: unknown }>;
  dimension: 'gate' | 'window' | 'obs-geometry' | 'message-design'; // 单维度,代码强制
  originSigs: string[];        // 触发签名的集合(来自 death_diagnosis)
  deathKeys: string[];         // 关联 deathKey(runId#attempt)
  verdict: 'commit' | 'rollback';
  scoreDelta: number | null;   // 候选中位 − champion 中位
  sigDelta?: Record<string, { repeatBefore: number; repeatAfter: number }>; // commit 后 W=5 局结算
};
```

- **单变更原则(代码强制)**:一次 patch 字段必须同属一个 dimension;**数值调参与消息设计变体不得同车**(变体需重学观测格式,混车必不可归因)。跨维度时按幅度保留一个,其余丢弃并写 issue(扩展 `limitPatch` 的维度分组逻辑)。
- **提案 cadence = run 级**:同一 run 的多次死亡分析合并为**一个**提案,账本记 originSigs 多值——消除 G2 的覆盖竞争。
- **归因规则(确定性,非 LLM)**:commit 后滚动 W=5 局,仅当 `repeatAfter < repeatBefore` 才记账"changeId 治了 sig";`death_diagnosis.responsibleTick` 交叉验证——若该 tick 附近决策行为未变,标记 diagnosis 未被本次变更触及。
- **回滚写回**(治 G10):回滚时向 playbook/insights 追加 `iter-N 假设 X 已回滚(Δ=…),勿重复提案`;提案上下文注入近 3 条被否决记录。

### D2 签名级升级阶梯(死循环治理)

```
state.sigStats[sig] = { deaths, proposals, lastImprovedIter }   // 滚动 20 局窗口
repeat 判定改为按签名计数:sigCounts[sig] ≥ 2 即 repeat(修 G4)

每个候选结算后(D1):
if sig.proposals ≥ 3 && 未改善(repeatAfter ≥ repeatBefore):
  L1 换维度:该签名禁改数值字段 2 轮,强制 message-design 变体
     (gap 死 → obsThreatFormat:'rows';停滞死 → obsStateExtra +['heldTicks'])
  L2 pure 对照:排 1 局 pure 模式跑同段(按需触发,不常开,不违 §6.7)
     pure 也死 → 问题在观测数据本身,锁定 obs* 字段;
     pure 不死 → 问题在提示层,锁定 obsHintStyle / obsInstructionVariant
  L3 冻结:标记"能力边界",提示词注入"已尝试 N 次未改善,预算让给其它签名",
     该签名进冷却直至版本变更(D6 restore 可解冻)
```

### D3 insight 可证伪协议

```ts
type Insight = {
  id: string;                   // I-{n}
  kind: 'claim' | 'maintain' | 'refuted';
  claim: string;                // ≤150 字
  field?: keyof PolicyProfile;  // 涉及的沙箱字段
  metric: 'winRate' | 'repeatRate' | 'execRate' | 'staleRate' | 'avgConf' | 'p50ms';
  direction: 'up' | 'down';
  evidenceIter: number[];       // 证据来自哪些迭代
};
```

- **入口校验**(qwen.ts 解析层):缺 `metric` 或无 `field`/数值证据 → 视同空,走 v3 §6.5 重试;重试仍不合格落 `kind:'maintain'`(带 patchKeys),**单独计数、不占正常经验额度**。
- **去重**:与近 5 条做词元 Jaccard ≥ 0.6 → 不追加,原条 `confirmCount+1`(重复确认也是信号)。
- **出清**(治"只进不出"):每次 D1 结算后回扫账本引用的 insight,方向被 sigDelta 反驳 → 改标 `refuted`(附证据迭代号)。淘汰序:refuted 最先 → maintain 次之 → 其余按字数 FIFO。
- **命中率** = insight 方向与 sigDelta 一致的占比,进 §2 统计面板;< 30% 时触发提示词复盘。

### D4 评估带宽:候选队列 + 序贯早停

```
candidateQueue: Candidate[](cap 2;溢出时同维度合并取幅度大者,异维度丢最旧并审计)
评估保持 K=3,但逐局序贯:
  跑完第 k 局(k<K)做中位夹逼:
    bestCase  < champion×(1+ε) → 提前 rollback(省 K−k 局)
    worstCase ≥ champion×(1+ε) → 提前 commit
champion 基线滚动化:不再"首次测量永久用"(mario-loop L291-294);
  改为 commit 后重测,或取最近 3 局 champion 局的中位——消除跨批噪声
队列积压审计:提案从产生到评估完成的中位等待局数 > 2 → 报警(评估瓶颈显性化)
```

### D5 北极星与退化报警

| 指标 | 定义 | 来源 | 报警线 |
|---|---|---|---|
| 通关率(北极星) | 滚动 10 局窗口胜率 | history.json | < 0.5 × 此前最优窗口 |
| 签名收敛速度 | 签名首现 → 连续 5 局消失的中位局数 | sigStats(D2) | 单签名 > 15 局未收敛 → 触发升级阶梯 |
| insight 命中率 | 方向与 sigDelta 一致占比 | 账本 × insights | < 30% → 提示词/温度复盘 |
| 漏斗健康 | propose→commit→5 局内存留率 | evolution.jsonl | commit 后 5 局内被回退 > 30% → ε 过松 |

退化自动处置:`winRate10 < 0.5 × bestWindow` 且连续 2 批中位分下行 → 自动 `restore` 最优 vid + 冻结提案 COOLDOWN_ITERS 局 + 审计 `action:'regression-restore'`。

## 开放问题
